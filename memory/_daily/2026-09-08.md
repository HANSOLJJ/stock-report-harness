## Entry: 2026-09-08 — 4-way 리뷰 서브에이전트 4개가 세션 한도(429)로 동시 중단됨
- **상황**: ai_scorecard framework 구현 중 `ai-scorecard-2026-09-baseline` 초안 리뷰를 위해 Agent 도구로 리뷰어 4개(fact-checker, general-purpose×2, report-designer)를 동시에 띄움. 브랜치 `HANSOLJJ/worker`, 커밋 전 작업 트리.
- **증상**: 네 에이전트 모두 파일을 읽기 시작한 직후 종료. 알림 원문 `Agent terminated early due to an API error: You've hit your session limit · resets 2:20pm (Asia/Seoul) (error type rate_limit, HTTP 429)`.
- **원인**: 세션 사용량 한도. 같은 세션에서 장시간 구현 뒤 대형 리뷰어 4개를 동시에 띄워 한도에 닿음(추정: 병렬 4개가 한도 소진을 앞당김).
- **해결**: 한도 리셋 후 같은 프롬프트로 4개를 다시 띄움. 리뷰어 프롬프트에 "파일이 크면 grep/sed 로 필요한 부분만 읽기"를 추가해 토큰 사용을 줄임.
- **검증**: 재시작 후 4개 모두 실행 중으로 전환됨(완료 알림은 이후 확인). 한도 근처에서는 리뷰어를 2개씩 나눠 띄우는 편이 안전함. 미검증(분할 실행은 아직 시도 안 함).

## Entry: 2026-09-08 — 2차 재검증에서 같은 429 가 재발, SendMessage 로 재개
- **상황**: 1차 리뷰 반영 후 같은 리뷰어 4개에 SendMessage 로 2차 재검증을 요청. 규칙 일관성 1개만 완료되고 나머지 3개가 다시 종료됨.
- **증상**: 알림 원문 `You've hit your session limit · resets 7:20pm (Asia/Seoul) (error type rate_limit, HTTP 429)`. 같은 시각 백그라운드 http.server 2개도 `system is running low on memory` 로 종료됨.
- **원인**: 세션 사용량 한도 재도달(추정: 리뷰어 4개 병렬 + 각 리뷰어의 대형 파일 통독). 메모리 부족은 별개 현상으로 원인 미확인.
- **해결**: 한도 리셋 시각 이후(20:43 KST) 같은 agentId 에 SendMessage 로 "이어서 진행" 을 보내 재개함. 리뷰어 프롬프트에 grep/sed 부분 읽기를 명시함.
- **검증**: 재개 요청은 성공(`Resuming agent`). 완료 여부는 알림으로 확인 예정. 같은 패턴 2회째이므로 3회째면 topics/guardrails.md 로 추출하고 리뷰어를 순차 2개씩 띄우는 규칙을 스킬(score-review)에 적을 것.

## Entry: 2026-09-08 — 문자열 이어붙이기 수정에서 f-string 접두사가 빠져 템플릿이 리터럴로 출력됨
- **상황**: scorecard HTML 렌더러(`scripts/scorecard/render_html.py`)의 카드 요약에 승계 배지를 넣으려고 f-string 한 줄을 `f'...' + (조건식) + '...'` 로 쪼갬. 리뷰 1차 지적 반영 중이었음.
- **증상**: 빌드된 `output/ai-scorecard-2026-09-baseline.html` 의 14개 기업 카드가 점수 대신 `{fmt_score(c["total"])}`, `{head} · 과점 {fmt_score(c["moat"])}` 를 그대로 표시하고 `class="t c-{total_class(c["total"])}"` 로 색 클래스까지 죽음. 승인·빌드까지 통과한 뒤 출력·가독성 2차 리뷰어가 발견함.
- **원인**: 쪼갠 마지막 조각에 `f` 접두사를 붙이지 않음. 파이썬은 오류를 내지 않고 리터럴 문자열로 처리하므로 테스트·검증기·Playwright 실측(넘침·탭 대상만 측정) 어디에도 안 걸림.
- **해결**: 마지막 조각에 `f` 복구. 재발을 텍스트 규칙이 아니라 mechanism 으로 막기 위해 `scripts/scorecard/validate.py` 의 `_validate_html` 에 `UNRENDERED_RE` 검사를 추가해 렌더되지 않은 파이썬 표현식이 HTML 에 남으면 빌드가 실패하게 함.
- **검증**: 재렌더 후 리터럴 0건, 카드 헤더가 "1위(완료 9개사 기준) · 기준선 v1.5 1위(14사) · 과점 21 / 함정 -4" 로 정상 출력. 깨진 문자열을 `UNRENDERED_RE` 에 넣으면 4건 탐지, 현재 빌드 결과는 0건. 커밋 c8793a3 이후 검증기 보강 커밋.
