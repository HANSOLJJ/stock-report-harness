# 채점 확인 안내 스킬

확인은 사람 행위다(2026-10-20 사용자 결정: 승인 페이지를 확인 페이지로 바꿨다). 에이전트는 확인하지 않고 취소하지도 않는다. 이 스킬에서 에이전트가 하는 일은 **"확인 대기" 를 보고하는 것**이고, 사람이 원하면 확인 페이지를 터미널 탭에 띄운다. 코드 쪽에서도 막혀 있다. 첫 방어선은 `scorecard.stages` 의 확인·취소 함수 본체가 에이전트 세션을 거부하는 것이고(CLI 든 import 든 같은 판정), 훅(`scripts/hooks/guard.py`)이 확인·취소 명령을 차단하는 것이 둘째 방어선이다.

## 에이전트가 하는 일

1. `output/<run_id>/review.md` 가 `status: pass` 이고 `uv run --frozen python -X utf8 scripts/validate_report_contract.py <run_id>` 가 통과하는지 확인한다.
2. `output/<run_id>/preview.md` 의 변경 요약(기존/제안 점수, 순위 영향, 변경 원인, 미결 항목)과 `uv run --frozen python -X utf8 scripts/scorecard_cli.py summary <run_id> --json` 의 요약(근거·트리거·리뷰·해시 상태)을 사용자에게 보여 준다.
3. "확인 대기" 를 보고하고 아래 사람의 절차를 안내한다. 그리고 멈춘다.

## 사람의 절차 (사람 셸에서)

1. 프로젝트 루트에서 `node server.js --approvals` 를 띄운다. 확인 페이지가 브라우저에서 저절로 열린다.
2. 다른 실행이면 `http://127.0.0.1:3000/approve/<run_id>` 를 연다. 요약(점수·근거·트리거·리뷰·해시)을 본다.
3. 근거 후보를 확정하거나 거부한다. 확인 페이지에서 한다.
4. 에이전트의 판단 변경 제안은 에이전트가 반영·거부한다(2026-10-07 사용자 지시). 5절 「판단 변경 제안」에서는 결정 기록을 보고, 필요하면 사람이 반영·거부할 수도 있다(거부는 사유 필수). 직접 고칠 판단은 9절 「전체 판단 표」에서 고친다(아래 절). 판단 수정 칸은 판정·올릴 근거·내릴 근거 세 칸이다(2026-10-07, `guide.md` 5.6).
5. 10절에서 "확인"을 누른다. 코드는 없고 이름 칸은 가장 최근 확인 기록의 이름으로 미리 채워진다. 누르면 확인 기록(approval.json)이 남고 곧바로 리포트를 빌드한다. 이미 확인된 실행은 "다시 빌드" 버튼이 나온다.
6. 확인과 빌드가 성공하면 서버는 내려간다. 페이지에는 취소 양식이 없다(취소는 사람이 CLI `revoke` 로 한다).

## 판단 수정 (사람이 확인 페이지에서)

점수가 아니라 정성 판단의 **입력**을 고친다. 점수는 고친 입력에서 규칙이 다시 계산한다.

1. 9절에서 factor 탭을 누르면 그 factor 의 모든 기업 판단이 카드로 나란히 보인다. **같은 factor 의 다른 기업 판단을 함께 보고** 잣대가 같은지 확인한다(Q03). 카드의 「이 판단 고치기」를 누르면 그 카드 안에 입력란이 열린다. `?factor=F3&company=<id>` 로 들어오면 그 카드가 열린 채로 나온다.
2. 고칠 수 있는 것은 factor 마다 다르다. F3 은 `criteria`, F5 는 `grade`(A·H), F7 은 `matrix`, F9 는 `gate_inputs`, 규칙 v2.0 이상의 F1 은 `lockin`, F2 는 `paths` 와 각 근거 문장이다. 규칙 v2.0 이하의 F4·F8 은 점수와 근거다. 규칙 v2.1 의 F4(`survival` 층별 보유표)·F8(`axes` 네 축)과 ① AI 수익화 재료는 중첩 입력이라 확인 페이지에 입력란이 없고 CLI(`judge --json`)로 고친다. 계산되는 항목은 점수 칸을 고칠 수 없고, F2·F6 은 대상이 아니다.
3. 근거 문장, 사유, 이름을 적고 제출한다(일회용 코드는 필요 없다). 이전 값은 판단 안의 `revision_history` 에 남는다. 새 판단은 확정된 근거만 인용할 수 있다.
4. 제출하면 판단 해시가 바뀌어 지금의 점수·초안·리뷰·확인이 무효가 된다. 사람이 그 사실을 알리면 에이전트가 `research → calculate → draft → review` 를 다시 수행하고 "확인 대기" 를 보고한다. 리뷰가 `pass` 가 된 뒤 사람이 페이지를 새로고침해 확인한다.

## 확정 뒤 해시가 바뀌면

근거를 확정하거나 판단을 고치면 판단·결과·초안의 해시가 바뀌어 이전 리뷰가 무효가 된다. 사람이 그 사실을 알리면 에이전트가 `research → calculate → draft → review` 를 다시 수행하고, 다시 "확인 대기" 를 보고한다. 사람이 에이전트에게 하는 말은 "고쳐" 이고, 빌드는 확인 페이지의 확인이 한다.

## 제약

- 확인 뒤 자료·규칙·판단이 바뀌면 확인은 무효다. 다시 리뷰하고 사람이 다시 확인한다. 초안만 다시 렌더링한 경우(다른 해시가 모두 같음)는 확인이 유지된다.
- 미결 규칙 결정이 남아 있어도 확인할 수 있다(미완료 기업은 순위 제외로 표시됨). 단 사용자가 그 사실을 알고 있어야 한다.
- 확인에는 코드가 없다. 에이전트는 확인 페이지에서 확인을 누르지 않는다.

## 완료 보고

"확인 대기" 상태, 리뷰 결과, 확인 페이지 주소 `http://127.0.0.1:3000/approve/<run_id>`. 확인을 누르면 빌드가 곧바로 돌므로 따로 `/score-build` 를 부를 필요가 없다.
