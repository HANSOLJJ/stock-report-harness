# 채점 승인 안내 스킬

승인은 사람 행위다. 에이전트는 승인하지 않고 취소하지도 않는다. 이 스킬에서 에이전트가 하는 일은 **"승인 대기" 를 보고하는 것**뿐이다. 코드 쪽에서도 막혀 있다. 첫 방어선은 `scorecard.stages` 의 승인·취소 함수 본체가 에이전트 세션을 거부하는 것이고(CLI 든 import 든 같은 판정), 훅(`scripts/hooks/guard.py`)이 승인·취소 명령을 차단하는 것이 둘째 방어선이다.

## 에이전트가 하는 일

1. `output/<run_id>/review.md` 가 `status: pass` 이고 `uv run --frozen python -X utf8 scripts/validate_report_contract.py <run_id>` 가 통과하는지 확인한다.
2. `output/<run_id>/preview.md` 의 변경 요약(기존/제안 점수, 순위 영향, 변경 원인, 미결 항목)과 `uv run --frozen python -X utf8 scripts/scorecard_cli.py summary <run_id> --json` 의 요약(근거·트리거·리뷰·해시 상태)을 사용자에게 보여 준다.
3. "승인 대기" 를 보고하고 아래 사람의 절차를 안내한다. 그리고 멈춘다.

## 사람의 절차 (사람 셸에서)

1. 프로젝트 루트에서 `node server.js --approvals` 를 띄운다. 터미널에 6자리 일회용 코드가 나온다. 코드는 승인·취소에만 쓴다(2026-10-01).
2. 브라우저에서 `http://127.0.0.1:3000/approve/<run_id>` 를 연다. 요약(점수·근거·트리거·리뷰·해시)을 확인한다.
3. 근거 후보를 확정하거나 거부한다. 승인 페이지에서 한다.
4. 에이전트의 판단 변경 제안은 5절 「판단 변경 제안」에서 반영하거나 거부한다(거부는 사유 필수). 직접 고칠 판단은 9절 「전체 판단 표」에서 고친다(아래 절).
5. 터미널에 나온 코드를 입력해 승인한다. 필요하면 취소도 이 페이지에서 한다.
6. 코드를 5번 틀리면 서버를 다시 띄워야 한다. 승인이 성공하면 서버는 내려간다.

## 판단 수정 (사람이 승인 페이지에서)

점수가 아니라 정성 판단의 **입력**을 고친다. 점수는 고친 입력에서 규칙이 다시 계산한다.

1. 9절에서 factor 탭을 누르면 그 factor 의 모든 기업 판단이 카드로 나란히 보인다. **같은 factor 의 다른 기업 판단을 함께 보고** 잣대가 같은지 확인한다(Q03). 카드의 「이 판단 고치기」를 누르면 그 카드 안에 입력란이 열린다. `?factor=F3&company=<id>` 로 들어오면 그 카드가 열린 채로 나온다.
2. 고칠 수 있는 것은 factor 마다 다르다. F1·F4·F8 은 점수와 근거, F3 은 `criteria`, F5 는 `grade`(A·H), F7 은 `matrix`, F9 는 `gate_inputs` 와 각 근거 문장이다. F3·F5·F7·F9 는 점수 칸을 고칠 수 없고, F2·F6 은 대상이 아니다.
3. 근거 문장, 사유, 이름을 적고 터미널의 코드를 넣어 제출한다. 이전 값은 판단 안의 `revision_history` 에 남는다. 새 판단은 확정된 근거만 인용할 수 있다.
4. 제출하면 판단 해시가 바뀌어 지금의 점수·초안·리뷰·승인이 무효가 된다. 사람이 그 사실을 알리면 에이전트가 `research → calculate → draft → review` 를 다시 수행하고 "승인 대기" 를 보고한다. 리뷰가 `pass` 가 된 뒤 사람이 페이지를 새로고침해 승인한다.

## 확정 뒤 해시가 바뀌면

근거를 확정하거나 판단을 고치면 판단·결과·초안의 해시가 바뀌어 이전 리뷰가 무효가 된다. 사람이 그 사실을 알리면 에이전트가 `research → calculate → draft → review` 를 다시 수행하고, 다시 "승인 대기" 를 보고한다. 사람이 에이전트에게 하는 말은 "고쳐" 와 "빌드해" 다.

## 제약

- 승인 뒤 자료·규칙·판단·초안이 바뀌면 승인은 무효다. 다시 리뷰하고 사람이 다시 승인한다.
- 미결 규칙 결정이 남아 있어도 승인할 수 있다(미완료 기업은 순위 제외로 표시됨). 단 사용자가 그 사실을 알고 있어야 한다.
- 승인 코드는 파일에 쓰이지 않고 터미널에만 나온다. 에이전트가 코드를 읽어 입력하지 않는다.

## 완료 보고

"승인 대기" 상태, 리뷰 결과, 승인 페이지 주소 `http://127.0.0.1:3000/approve/<run_id>`. 승인된 뒤의 다음 명령은 `/score-build <run_id>` 이다.
