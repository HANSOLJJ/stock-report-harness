## 0. 한 줄 요약

**9개 factor 중 ⑥⑨는 완전 기계화, ⑤⑦③은 "판정값 → 점수"만 기계화(판정값은 사람), ①②④⑧은 정성.** 지금 문서 구조는 같은 사실이 최대 6곳에 복제돼 있어(오늘 감사 55건의 원인) 자동화 전에 **단일 진실 → 렌더링** 구조로 바꿔야 한다.

## 3. 문서에 없는 암묵지

**3-1. 같은 사실이 최대 6곳에 산다 — 오늘 감사 55건의 원인 전부.** 점수 하나가 바뀌면: MD 순위표 → 카드 헤딩 → 한 줄 요약 → 해당 factor 불릿 → **다른 기업 카드에서 인용한 곳**(Apple ⑤가 "NVIDIA ⑤1"을 인용) → 규칙 파일 예시표(별표 C·G·H·I, ③ 사다리) → 해석 1~9 → 트리거 영향란 → 3-1b 게이트 열 → 신용표 함정 열 → HTML `D` → HTML 설명 섹션(fcard·별표 범례·판정 흐름·08 해석) → CSV → 운영이력 → CLAUDE.md 현재 상태 줄. **이 중 검사기가 기계적으로 잡는 건 절반**이고, 나머지는 문장이라 못 잡는다.

**3-2. 기업명 별칭.** `Alphabet / Google` · `Amazon / AWS` · `🍎 Apple`(HTML만 이모지) · `SpaceX + xAI`. 검사기 7번의 `alias` 맵 참조. CSV는 `Apple`(이모지 없음).

**3-3. HTML 근거 문자열 규약.** `r`·`rt` 배열의 각 문자열은 ` · `로 불릿 분리되는데, `splitPts()`가 **`<b>`·`<i>`·괄호 균형이 깨지면 다음 조각과 합친다.** 근거를 쓸 때 `<b>` 안에 ` · `를 넣으면 불릿이 안 갈린다. 맨 앞 `<i>(v1.5: …)</i>`는 `frow()`가 주석(fnote)으로 떼어낸다.

**3-4. "상장 12사" ≠ "14사".** ⑥·PEG·P/S 문맥은 비상장 2사(Anthropic·OpenAI) 제외 12사가 맞다. 그 외는 14. 오늘 이걸 섞어 쓰다 4건 틀렸다.

**3-5. 순위 계산.** `rank = 1 + (조정이 더 높은 기업 수)` — 동점은 같은 순위, 다음은 건너뜀(공동 2위 셋 → 다음이 5위). HTML `rank` 필드는 수동 입력이라 점수 바꾸면 **전 기업 rank를 재계산**해야 한다(자동화 1순위).

**3-6. 판정에서 실제로 걸렸던 오류 — 체크리스트 23개 외.**
- 규칙에 예외를 만들고 싶어질 때(NVIDIA ⑥ P/S) → 그건 결론이 마음에 안 드는 것. 예외 금지
- "미등재·없음"은 검색 없이 쓰면 틀린다(Meta AA, Oracle Stargate 지분)
- 감점 완화(방향 완화·게이트 4 커버리지)는 **실질적 가점**이라 별표 D·I의 엄격 기준 적용
- 관계사(SpaceX↔Tesla)는 동맹도 자산도 아니다 — 한쪽에서 뺐으면 반대쪽도 뺀다
- 사는 쪽에게 공급 계약은 조달이지 동맹이 아니다(OpenAI–Oracle $300B)
- 하한(-3)을 유지한 논리: 1999년 아마존 테스트 — ⑨가 낮은 것과 회사가 나쁜 것은 다르다

**3-7. 작성자 이해상충.** Claude=Anthropic. 긴장 #4(⑤5)·#11(② 독립 측정 규칙이 Anthropic ②5를 지킴)에 기록. 자동화하면 이 편향은 줄지만 **A·H 등급·경로 판정을 사람이 하는 한 남는다.** 제3자 재검토 조건이 긴장에 적혀 있다.

## 4. 구조 재설계 제안 — 단일 진실 → 렌더

지금: **점수**는 HTML `D`·MD 순위표·CSV에 3중, **원자료**는 MD 3-1a/3-1b/전수표·HTML `VAL`/`EARN`/`FIN`/`BORR`에 2중, **트리거**는 MD 표·HTML `TRIG` 2중. 검사기가 동기를 확인할 뿐 생성하지 않는다.

```
scores.json        ← 단일 진실 (기업 × ①~⑨ + 판정 입력값 + 변동유형 + 근거 문자열)
inputs.json        ← 원자료 (NTM PER · FCF · 현금 · 등급 · CDS · 부외 · RPO · AA 순위) + 출처·날짜
rules.json         ← ⑥ 구간표 · ⑨ 게이트 임계 · ③ 사다리 매핑 · ⑤ A/H 표 · ⑦ 매트릭스
      ↓ score.py   (⑥⑨ 자동 산출 · ⑤⑦③② "판정값→점수" 산출 · rank 재계산)
      ↓ render.py  (MD 순위표·카드 헤딩·3-1a/b·전수표 / HTML D·VAL·EARN·FIN·BORR·TRIG / CSV 행)
      ↓ check.py   (기존 검사기 — 렌더 결과 검증용으로 유지)
```

**근거 문장(`r`/`rt`)·한 줄 요약·해석은 사람이 쓴다.** 단 근거 안에 **다른 기업 점수를 인용하지 말 것** — 인용하면 그 기업 점수가 바뀔 때 깨진다. 필요하면 `{{score:NVIDIA:⑤}}` 같은 치환 토큰으로.

**렌더링 전환 시 확인점**: HTML은 `D`만 바꾸면 KPI·순위·산점도·카드·스파크라인이 자동이지만 **fcard 설명·별표 범례·판정 흐름·08 해석·신용표·클라우드 4사 표는 하드코딩**이라 렌더 대상에 넣거나 "기업 점수를 인용하지 않는 문장"으로 유지.

## 5. 검증 — 검사기 한계와 임시 스크립트

**`check_채점표.py` 7항목이 못 잡는 것**: 의미 모순(카드 A가 카드 B와 충돌), 낡은 최상급("유일·최저"), 규칙↔적용 불일치(관계사를 동맹으로), 인접 기업 오귀속(검사기 7번이 4~7건 오탐으로 남음). **분기마다 한 번은 서브에이전트/사람이 4개 파일을 통독**해야 한다 — 오늘 그 방식으로 34건 나왔다.

**세션 중 쓴 임시 스크립트 (저장 안 됨, 재현 시 다시 작성)**
- HTML 인라인 JS 추출 → `node --check` (CLAUDE.md에 있음)
- **산점도 좌표 겹침**: `D`에서 (과점, 함정) 좌표 중복 확인 — 겹치면 auto-layout이 처리하지만 확인은 한다
- **카드 렌더 시뮬레이션**: `D.forEach(d=>{d.moat=…;d.trap=…;d.total=…})` 먼저 실행 후 카드 템플릿을 node로 돌려 `cgrp`/`frow` 개수·태그 균형 확인
- **FIN/BORR 테이블 렌더**: 헤더 `<th>` 수(−1, `<thead>` 매칭 제외) = 행 `<td>` 수
- **한 줄 요약 숫자 검증**: 검사기 6번에 흡수됨
