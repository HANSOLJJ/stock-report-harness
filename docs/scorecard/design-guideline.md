> 구현 구조는 `structure.md`, 남은 작업은 `open-items.md` 를 함께 본다. 이 문서의 설계 원칙 D-01~D-10 은 검증 담당 보고서의 항목 번호 D-01~D-13 과 체계가 다르다. 겹치는 번호를 섞지 않는다.

- 작성일은 2026-09-08이다.
- 문서 역할은 분석 도메인 명세다. 다른 agent가 작성하는 현재 harness 구조 확장 지침과 함께 구현 기준으로 사용한다.
- 이번 산출물은 설계 문서다. 규칙 개정의 활성화, 실제 기업 재채점, 데이터 제공사 연결 또는 구현 완료를 의미하지 않는다.

## 1. 목표와 문서 경계

AI 기업의 경쟁 구조와 재무 위험을 동일한 규칙으로 반복 분석한다. 원자료, 사람의 판단, 계산 결과를 구분하고, 모든 점수를 입력과 적용 규칙까지 역추적할 수 있어야 한다.

자동화의 단위는 factor 전체가 아니라 **입력 사실 → 정성 판정 → 점수 환산**의 각 단계다. 정성 요소가 섞였다는 이유로 factor의 산술까지 수작업으로 남기지 않는다. 반대로 숫자 자료가 있다는 이유만으로 정성 판단을 임의의 수치 구간으로 바꾸지 않는다.

| 이 문서에서 정하는 것 | 다른 agent의 구조 확장 지침에서 정하는 것 |
|---|---|
| 9개 factor의 의미, 입력, 자동화 경계 | 기존 디렉터리·모듈·명령에 추가하는 위치 |
| 규칙 우선순위, 원문 충돌, 결정이 필요한 정책 | report_type 분기와 기존 코드의 수정 범위 |
| 원자료·판단·계산·검토·승인의 논리 계약 | 실제 JSON/YAML 스키마, 함수·CLI 인터페이스 |
| 점수·총점·순위·이력의 일관성 | 파서·계산기·렌더러·검증기·훅 연결 |
| 분석 보고서 내용과 수용 기준 | 구현 순서, 테스트 배치, 배포와 실행 방법 |

두 문서를 합칠 때 이 문서의 요구 ID를 구현 위치와 테스트에 연결한다. 구조 문서에서 채점 구간을 다시 정의하거나, 구현 편의를 이유로 정성 입력을 기본 점수로 대체하지 않는다. 이 문서는 구현 작업 순서를 정하는 별도 plan 파일이 아니다. 정식 구현 계획 파일을 만들 때는 프로젝트 지침에 따라 checklist.md와 context-notes.md도 함께 준비한다.

### 4.2 F1·F4·F8 정성 입력 계약

- F1은 모든 실질 채널을 평가하고 가장 강한 락인으로 판단한다. 소비자·업무·거래·부품을 구분한다. 실질 소비자·업무 채널이 없는 부품 공급형은 상한 2다. 채널 수를 합산해 가점하지 않는다.
- F4는 사업 수나 투자액만으로 자동 점수화하지 않는다. 출하·실제 배포와 계획·인수 서명·규제 대기를 분리한다.
- F8은 고객·공급자 집중도만으로 자동 구간을 만들지 않는다. 같은 집중도라도 대체 가능성, 계약 방향, 핵심 생산 중단 여부가 다르다.
- 각 판단에는 점수, 판단 대상 속성, 근거 ID, 반대 증거, 검토자, 검토일, 승계 여부를 붙인다.
- 비AI 사업의 긍정적 기여는 F1, F3의 별도 수익모델, F4에서만 인정한다. F2와 F3의 모방불가·가속도는 AI 귀속 증거를 사용한다. F6·F9의 기업 재무 계산은 별도로 정의한 연결 범위를 따른다.

### 4.3 F2 경로 환산

입력은 성능 도약·패러다임 적응·표준 선점의 세 경로 판정과 증거다. `pass`, `partial`, `fail`, `unknown`을 구분한다. 부분 통과를 완전 통과로 세거나 미확인을 실패로 간주하지 않는다.

S-HAND와 S-SCORE에는 통과 경로 0개→2점, 1개→3점, 2개→4점과 AA 종합 1위→5점이라는 설명이 있다. 그러나 S-RULE 별표 F는 이 매핑 전체를 완결된 표로 정의하지 않았으며, NVIDIA·TSMC의 기존 5점은 AA 모델 순위로 설명되지 않는다.

따라서 이 환산은 **개정 후보**다. 3개 경로 통과 시 점수, 0·1점 사용 조건, 하드웨어·플랫폼의 5점 자격, 동점 1위, 경로와 최고점 자격의 우선순위를 확정해야 한다. 모델 기업의 AA 순위 규칙을 모든 기업에 전역 적용하지 않는다. 미확정 분기는 `needs_rule_decision`으로 남기고 기존 점수는 기준선 표시로만 제공한다.

벤치마크에는 평가기관, 평가일, 모델·제품 버전, 지수 버전, 하네스·설정, 모집단, 순위, 측정값을 저장한다. 서로 다른 지수 버전의 절대값을 연결하지 않으며 순위도 모집단과 시점을 함께 제시한다. 종합 지능·코딩·에이전트 실무 축은 별도로 유지한다. 전원이 각자 제품 하네스를 쓰는 동일 평가 프로토콜과, 한 기업에만 유리한 어댑터를 쓰는 비교를 구분한다.

### 4.4 F3 사다리

확인된 정성 판정 `pass=1`, `partial=0.5`, `fail=0`의 합을 통과점으로 사용한다. 원문의 부분/보류 표시는 이관 시 의미를 확인한다. 새 입력의 단순 자료 누락은 `unknown`이며 자동으로 0.5를 주지 않는다.

| 통과점 | 기본 점수 | 추가 조건 |
|---:|---:|---|
| 0 | 1 | 없음 |
| 0.5 또는 1 | 2 | 없음 |
| 1.5 또는 2 | 3 | 없음 |
| 2.5 또는 3 | 4 | 모방 불가능성이 완전 pass여야 한다. 아니면 3 |
| 위 4점 조건 충족 | 5 | 실제 문 닫힘 증거가 검토되어야 한다 |

문 닫힘은 선두의 가격 결정력 붕괴 또는 점유율 역전 등 실제 결과의 판단이다. 자료 수집기가 임의로 판정하지 않는다. F1의 설치기반을 모방불가 근거로 재사용하거나 관계사 소유 자산을 자체 자산으로 세지 않는다.

가속도는 AI 귀속 지표의 성장률 변화다. 절대 규모, 단일 성장률, 출시 일정만으로 자동 판정하지 않는다. QoQ 성장률 두 개를 비교하려면 같은 정의의 최소 3개 분기 수준값이 필요하다. 인접 분기의 YoY 성장률 비교에는 전년 비교 분기도 필요하다. 지표 선택과 인수·회계 변경·계절성 영향은 검토 입력으로 남긴다.

### 4.5 F5 등급 합산

`F5 = 3 + A + H`를 적용한다.

| 입력 | 허용값 | 판단 기준 |
|---|---|---|
| 동맹 A | 0, 1, 2 | 독립 상업 동맹 없음 / 의미 있으나 제한적 / 복수 지분 동맹 또는 경쟁사까지 플랫폼 편입 |
| 적대 H | 0, -1, -2, -3 | 최소 / 비용형 / 구조형 / 구조형 다발 및 최대 파트너 긴장 |

허용된 조합은 모두 0~5가 된다. 잘못된 입력을 범위에 맞춰 잘라내지 말고 오류로 처리한다. 거래별로 주고받는 권리, 성공의 연동, 상대의 이탈 가능성, 나의 이탈 가능성을 기록한다. 마지막 항목은 F8 판단이며 F5 산식의 추가 감점이 아니다.

등급 자체를 파트너 수로 자동 계산하지 않는다. 단순 조달, 무료 사용자, 관계사는 독립 동맹으로 세지 않는다. 별표 H의 이탈 가능성 본문과 실제 예시 사이의 충돌은 11절 C-08에서 결정한다.

### 4.6 F7 매트릭스

| 자기 자금의 고객/JV 경유 환류 | 조달 의존 고객 비중 작음 | 조달 의존 고객 비중 큼 |
|---|---:|---:|
| 없음 | 0 | -2 |
| 있음 | -1 | -3 |

큼/작음의 수치 임계는 원문에 없다. 자동으로 10%·30% 등 임계값을 신설하지 않는다. 실제 매출 집중도와 RPO 집중도를 구분하여 사람이 판정한다. 자기 설비 투자, 받은 투자, 관계사 거래라는 사실만으로 자기 자금 환류를 인정하지 않는다. 실행된 투자와 구속력 있는 약정, 루머를 구분한다.

F7의 현행 하한은 -3이다. 일반 함정 factor의 명목 범위 -5를 그대로 허용하거나 과거 트리거의 -4를 실행하지 않는다. 동일 거래에 F7·F8·F9가 연결될 수 있으나 각각 수요의 조달 의존, 대체 불가, 현금 소진이라는 다른 속성을 설명해야 한다.

## 5. F6 가격 자동 산출 계약

### 5.1 상장사

> **이 절은 대체됐다. F6 엔진 정본은 `parameters` 다(사용자 확정 2026-09-14, F6-SPEC-18 · IMPL-46).**
> 아래 본문은 F6 를 **NTM PER 단일 지표**(`bands`)로 매기던 v1.5·v1.6 계약이다. v1.7 은 P1 PER · P2
> EV/Sales · P3 매출성장률 · P4 입력신뢰도 **네 파라미터**로
> 분해했다. 무료·허용 원천 중 12개사 전부에 향후 4개 분기 컨센서스를 같은 기준으로 주는 곳이 없어
> NTM PER 을 유지할 수 없다는 조사 결과(F6H-BATCH-10·AV-SOURCE-11)가 근거이며, 근거와 밴드는
> `scorecard/rules/v1.7.json` 의 최상위 `note` 와 `policies.f6` 에 있다.
>
> **v1.5·v1.6 실행에는 그대로 유효하므로 본문을 지우지 않는다.** `bands` 는 구버전이고 `run.json.rule_version`
> 으로 v1.5·v1.6 을 고른 실행에서만 선택된다. v1.7 이후 실행에 아래를 적용하지 말 것.
>
> 같은 날 **C-13 은 `reject_proxy` 로 확정**됐다 — 아래 본문이 말하는 `annual_weighted_proxy`(연간 EPS 가중)를
> NTM 으로 받지 않는다. 다만 정본이 parameters 라 이 결정은 `bands` 모드에서만 효력이 있다.
> 특히 이 절 끝의 `TTM PER·P/S·영업외 이익 비중·시가총액은 F6 의 추가 감점·가점 입력이 아니다` 는
> **v1.7 에서 뒤집혔다** — 네 가지가 모두 입력이다. 그 줄에 따로 표시해 두었다.

1. 분석 기준 시점과 시장별 실제 가격 시점을 고정한다. 휴장일이면 직전 거래일 종가를 사용하고 날짜를 표시한다.
2. 기준 시점에 이용 가능했던 다음 4개 미발표 회계분기의 EPS 컨센서스를 확보한다. 각 분기의 기간과 추정치 스냅샷 시점을 저장한다.
3. 주가와 EPS의 통화, 보통주/ADR, 분할 조정, GAAP/조정 기준을 맞춘다. 네 분기는 중복 없이 연속해야 한다.
4. `NTM EPS = 네 분기 EPS 합`, `NTM PER = 주가 / NTM EPS`를 계산한다.
5. 내부 정밀도의 PER로 구간을 판정한 뒤 화면만 반올림한다.

| PER 구간 | F6 |
|---|---:|
| 0 초과, 20 미만 | 0 |
| 20 이상, 29 미만 | -1 |
| 29 이상, 42 미만 | -2 |
| 42 이상, 62 미만 | -3 |
| 62 이상, 90 미만 | -4 |
| 90 이상 | -5 |

가격은 유효한 양수여야 한다. EPS 합이 0 이하이거나 4개 분기·회계 기준·주식 기준이 확보되지 않으면 점수를 보류한다. 낮은 PER이나 0점으로 대체하지 않는다. S-PLAN의 정확한 NTM 계약을 채택하는 설계이며, 기존 연간 EPS 가중 근사 방식과 달라지는 기업은 규칙 영향 검토에 포함한다.

`forwardPE`라는 공급사 필드 이름만으로 NTM임을 인정하지 않는다. 연간 EPS를 가중한 값은 `annual_weighted_proxy` 등 별도 방법으로 기록하고 참고만 제공한다. 역사적 분석에 현재 컨센서스를 끼워 넣지 않는다.

경계는 20·29·42·62·90이며 `min(abs(PER - 경계) / 경계) <= 0.03`이면 주의 표시한다. 경계값 자체도 주의 대상이다. 표시는 점수를 바꾸지 않는다. ~~TTM PER, P/S, 영업외 이익 비중, 시가총액은 F6의 추가 감점·가점 입력이 아니다.~~ **⚠️ 마지막 문장은 v1.7 에서 뒤집혔다(F6-SPEC-18).** 네 가지가 모두 F6 입력이다 — P1 이 TTM PER, P2 가 EV/Sales(P/S 계열), P1·P2 의 분자가 시가총액, P4 조건이 영업외 이익 비중이다. 경계 표시(±3%)는 v1.7 에서도 유지되며 P1·P2·P3 밴드와 P4 임계에 모두 적용한다.

### 5.2 비상장사

자동 계산할 지표는 post-money 기업가치/ARR, 기업가치/TTM 매출, ARR/누적 조달액이다. 실제 TTM 매출이 없으면 추정값과 추정 방법을 별도로 기록한다. ARR을 연간 실적이나 계약된 미래 수입으로 바꾸어 표시하지 않는다.

현재 원문에는 연속된 구간 전체, TTM 보정의 산식, 자본효율과 이익의 점수 개입 방식이 완결되어 있지 않다. 따라서 비상장 F6의 **배수는 자동 계산하되 최종 점수와 보정 판단은 정성 예외로 유지**한다. 입력 점수에는 자료·보정 근거·검토자가 필요하다. 이를 정량 자동 점수로 표시하지 않는다.

비상장 F6까지 완전 자동화하려면 별도의 완결된 구간과 보정 규칙을 개정하고 전 기업 영향표를 검토해야 한다. 상장사 PER 구간을 매출 배수에 재사용하지 않는다.

상장 상태는 기준일의 검증된 이벤트로 결정한다. 상장 후에는 상장사 계약으로 전환하며 EPS 부족을 이유로 비상장 예외를 연장하지 않는다. 과거 비상장 시점의 기록은 보존한다. 원문 예상 IPO 일정만으로 전환하지 않는다.

## 6. F9 적자 깊이 자동 산출 계약

### 6.1 원자료와 정규화

- 기업 연결 기준의 TTM 매출, 영업손익, OCF, 현금 CapEx를 기본으로 한다. 분기와 세그먼트는 별도 기록한다. 단일 분기 흑자를 TTM 영업흑자로 대체하지 않는다.
- `영업이익률 = TTM 영업손익 / TTM 매출`, `표준 FCF = TTM OCF - TTM 현금 CapEx`다. 정규화된 CapEx는 지출 크기를 양수로 저장하며 원출처 부호와 변환을 남긴다.
- YTD 누적 자료는 개별 분기로 환산한 뒤 합산한다. 연간과 9개월 누적으로 Q4를 도출할 수 있으나 범위·회계 기준·정정 공시가 같아야 한다.
- 회사가 정의한 조정 FCF는 표준 FCF와 별도 보관한다. 비현금 리스 취득액을 현금 CapEx와 섞지 않는다.
- 매출 0·음수, 기간 불일치, 영업손익 정의 불명은 산식 유효성 문제로 처리한다.

### 6.2 게이트별 동작

아래는 S-RULE의 4단계를 유지하면서 S-PLAN의 데이터 정책을 반영한 **설계안**이다. 경계·충돌 항목은 11절 결정 후 활성화한다.

| 단계 | 입력과 계산 | 점수 처리 |
|---|---|---|
| G1 본업 | TTM 영업손익·손실률, 검토된 BEP 후퇴·완충 잠식·방향 입력 | 영업적자는 기본 -3~-5. 방향 완화는 최대 +1이며 -3보다 좋아질 수 없다 |
| G2 현금 | TTM FCF와 검토된 추세 | 영업흑자·FCF 양수·추세 안정은 0, 악화는 -1. FCF 음수는 기본 -2에서 G3 진행 |
| G3 지속 기간 | 사용 가능한 현금 + 확정 미인출 여신을 연간 FCF 소진액으로 나눔 | 3년 이상 유지, 1년 이상 3년 미만 -1 추가, 1년 미만 -2 추가 |
| G4 미래 약정 | 같은 범위·기간의 계약된 수입 / 미개시 B종 약정 | 1 이상 유지, 1 미만 -1 추가. 미확인·미공시의 처리는 별도 결정 |

모든 감점의 최종 하한은 -5다. FCF 양수의 런웨이는 계산 대상 아님으로 표시하며 JSON에 무한대 숫자를 넣지 않는다. G1 실패 뒤 G3·G4를 추가 적용하는지, 진단만 하는지는 원문이 일관되지 않으므로 C-05에서 확정한다. 게이트 실행 여부와 종료 이유를 계산 경로에 남긴다.

### 6.3 정성 입력과 경계 결정

- 영업손실률의 경계 **제안**은 `-10% <= m < 0`이면 -3, `-30% <= m < -10%`이면 -4, `m < -30%`이면 -5다. 원문의 중첩·부호 모호성을 해소하기 위한 안이며 확정값으로 조용히 채택하지 않는다.
- BEP 후퇴의 -5 우선 여부, 완충 잠식의 정의, 영업손익 0, FCF 0, 단위경제로 영업적자를 대체할 수 있는 조건을 확정해야 한다.
- 방향 완화 A는 영업손실률의 4분기 연속 YoY 개선이다. 단순 4개 분기 수준값만으로는 확인할 수 없으며 전년 동분기까지 통상 8개 분기 자료 또는 검증된 네 개의 YoY 비교 쌍이 필요하다.
- 방향 완화 B는 매출 성장률이 비용 성장률보다 높은지다. 비용 범위와 비교 기간을 고정해야 하며, 일회성 조정·감원·회계 변경에 따른 개선 인정 여부는 사람의 판단이다.
- A·B의 비교 수치는 자동 계산할 수 있다. 동일 조건의 실질 개선인지, 추세 안정/악화인지, BEP 목표가 실제로 후퇴했는지는 검토 입력으로 둔다.
- 자료 부족으로 완화 요건을 입증하지 못한 경우 완화를 적용하지 않는 정책과, 기본 점수 입력 자체가 부족해 계산할 수 없는 경우를 구분한다.

### 6.4 런웨이와 약정

현금 여력에는 사용 가능한 현금 및 현금성자산과 조건이 확인된 확정 미인출 여신만 포함한다. 제한 현금, 이미 현금에 포함된 인출 여신, 예상 증자·회사채 발행, 신용등급에 따른 추정 조달 능력은 포함하지 않는다. 단기 투자자산을 포함하려면 환금성·사용 가능성 기준을 먼저 정한다.

| 약정 유형 | 저장·평가 원칙 |
|---|---|
| A 이미 개시된 리스 | FCF에 반영된 현금 지출을 다시 차감하지 않는다 |
| B 미개시 확정 약정 | 계약 기간·연도별 지출·취소 조건·대응 수입을 기록하고 G4 대상 여부를 검토한다 |
| C 우발 보증 | 현재 확정 현금 지출로 간주하지 않는다. F7 등 관련 위험의 근거와 교차검증에 연결한다 |

분류는 계약·공시 주석을 확인한 판단값이다. B종과 리스 총액·구매 약정이 겹치지 않도록 계약 식별자를 남긴다. RPO·백로그는 미래 매출 계약이지 현금·이익 보장이 아니다. 기간·대상 자산·사업 범위가 다른 총액을 바로 나누지 않는다.

ARR/연환산 약정은 G4 커버리지가 아니다. B종이 확실히 0인 경우, 수입이 확실히 0인 경우, 어느 쪽인지 미공시인 경우를 구분한다. 동일한 미공시 사유를 G2·G4에서 중복 감점하는 문제는 사유 ID와 적용 경로로 검토한다. 자료 수집 실패를 기업의 미공시 위험으로 둔갑시키지 않는다.

### 7.2 자료 상태와 계산 상태

| 구분 | 상태 예 | 처리 |
|---|---|---|
| 유효 자료 | verified | 계산 입력 가능 |
| 과거 이관 | legacy_unverified | 기준선 열람 가능. 이번 실행에서 재검증된 자료로 간주하지 않음 |
| 실제 미공시 | not_disclosed | 승인된 미공시 정책 또는 판단 필요 |
| 수집 실패 | collection_failed | 재수집·수동 입력 대상. 자동 감점 금지 |
| 출처 충돌 | source_conflict | 값 선택·정정 근거 필요 |
| 정의·기간 불일치 | incompatible_basis | 비교·합산 차단 |
| 정성 판단 부족 | needs_judgment | 필요한 질문과 근거 후보를 제시 |

`unknown`은 `not_applicable`이 아니다. 적용 제외에도 이유가 있어야 한다. 상태 이름은 구조 문서에서 바꿀 수 있으나 위 의미를 합치지 않는다. 해결 가능한 대기를 즉시 blocked로 처리하지 않으며 실제 외부 차단 또는 반복 실패는 현재 harness의 차단 정책과 조정한다.

### 7.3 출처와 수집

공시·IR을 재무 1차 근거로 사용하고, 구조화 API 값도 원문 기간·태그와 대조할 수 있어야 한다. 뉴스와 2차 자료는 공시가 없는 정보의 근거 수준을 표시한다. 원문에 출처명이 있지만 URL이 없으면 없는 상태로 가져오며 기사 URL을 만들지 않는다.

가격은 현재 프로젝트의 yfinance 원칙을 유지하는 방향으로 설계한다. S-PLAN의 FMP 가격·분기 EPS는 **후보 검토**이지 연결 확정이 아니다. 분기 컨센서스 공급사의 실제 커버리지, 회계 기준, 과거 스냅샷, 요금·공유 조건은 연결 시 공식 자료로 검증한다. yfinance에 필요한 네 분기 컨센서스가 있다고 가정하지 않는다.

같은 기준일의 이용 가능 정보를 사용하되, 회사별 결산일·발표일 차이를 숨기지 않는다. 확정 재무 자료는 신규 공시·정정 전까지 재사용할 수 있고, 가격·컨센서스·상장 상태는 실행별 시점을 고정한다. 근거 없는 일괄 유효기간을 신설하지 않는다.

벤더 벤치마크·이해관계자의 시장점유율 주장은 독립 측정과 구분한다. OpenRouter 트래픽을 전체 시장으로, 토큰 점유율을 매출 점유율로, 목록 미등재를 부재로 단정하지 않는다. 미등재·미출시 등 부재 주장은 검색 범위와 시점을 기록한다.

## 8. 점수·순위·변경 이력

### 8.1 합산과 순위

```text
과점 = F1 + F2 + F3 + F4 + F5
함정 = F6 + F7 + F8 + F9                 # 음수 또는 0
조정총점 = 과점 + 함정
rank(company) = 1 + 조정총점이 더 높은 대상 기업의 수
```

원문의 “과점 − 함정(-20)” 문장을 코드로 옮겨 음수를 다시 빼지 않는다. 감점 크기를 양수로 표시하는 UI라면 표시용 값만 `-함정`으로 변환한다. 현재 F7 하한 -3을 적용하면 함정 합계의 실제 최저는 -18이다. 개요의 -20은 네 factor를 모두 -5로 놓은 명목 설명이므로 활성 범위는 규칙에서 계산한다.

동점은 공동 순위이며 다음 순위를 건너뛴다. 동점 기업의 화면 정렬은 안정적인 ID 등으로 고정할 수 있지만 순위 차이를 만들지 않는다. 미완료 기업을 0점으로 채워 공식 순위에 포함하지 않는다. 일부 기업만 계산되면 임시 결과의 모집단과 제외 사유를 표시한다.

F1~F5의 과점 20점 기준은 원래 framework의 분류 기준이며 조정총점에 적용하지 않는다. 해당 분류는 수익률 예측이나 검증된 승리 확률이 아니다. 1~3점 차이에 의미가 없다는 원문의 문구도 통계적으로 입증된 오차 범위로 표시하지 않는다.

### 8.3 변동 기록

실적·사실 변화, 규칙 변경, 원자료·기존 적용 정정, 가격 경계 통과를 구분한다. 여러 원인이 함께 작동하면 복수 원인을 기록한다. 같은 규칙에서 가격만 움직여 경계를 넘은 경우와 EPS 변경으로 경계를 넘은 경우를 구분한다.

규칙 버전, 보고서 버전, run_id를 별도로 유지한다. 기준선 이관과 개정 규칙 재계산은 별도 결과다. 개정으로 점수가 바뀌었다면 기업 실적 개선·악화로 해석하지 않는다. 모집단이 바뀌어 발생한 순위 변화도 점수 변화와 구분한다.

원문 S-PLAN의 v2.0은 예정 버전이다. 이 문서 작성만으로 활성화하지 않는다. 동일 승인 결과의 재생성은 이력 중복을 만들지 않아야 한다.

## 9. 분석 산출물과 실행 흐름

논리 흐름은 `plan → research → calculate → draft/preview → review → awaiting_user → finalize/build`다. 이는 scorecard용 요구이며 기존 stock 실행 계약을 전역으로 변경하는 지시가 아니다.

| 산출물 | 반드시 보여줄 내용 |
|---|---|
| 실행 계획 | 분석 목적, 기준 시점, 대상 기업·연결 범위, 규칙 버전, 정량/정성 범위, 기준선 |
| 리서치 | factor별 근거·반대 증거, 원자료·출처, 검증 상태, 미공시·충돌·판단 필요 항목 |
| 계산 결과 | 자동 산출 점수, 수동 판단 출처, 산식·게이트 경로, 경계·미완료 이유 |
| 변경 미리보기 | 기존/제안 F1~F9, 합계·순위 영향, 변경 원인, 승계된 판단, 미결 사항 |
| MD·HTML | 순위표, 기업별 요약과 factor 근거 불릿, 가격·재무 원자료, 방법·규칙 연결, 해석, 트리거, References |
| CSV·운영이력 | 실행·기업·규칙·승인 식별자, 점수·합계·순위, 변경 원인과 출처 연결 |

원문의 HTML D·VAL·EARN·FIN·BORR·HIST·TRIG는 기존 화면의 데이터 영역을 설명하는 이름이다. 새 구현이 이름까지 재현할 의무는 없지만 해당 점수·원자료·이력·트리거 내용은 동일 원본에서 생성해야 한다. D를 사람이 편집하는 별도 원본으로 유지하지 않는다.

근거는 구조화된 불릿 배열로 관리한다. ` · ` 문자열 분할과 HTML 태그 균형에 핵심 데이터를 의존시키지 않는다. 다른 기업의 점수·순위와 현재 최고/유일 같은 문장은 결과에서 생성하거나 ID 참조로 치환한다. 규칙 숫자·체크리스트를 카드와 설명란에 수작업으로 반복하지 않는다.

공유 HTML은 단일 파일로 열 수 있어야 한다. API 키·비공개 원자료는 포함하지 않고, 필요한 근거 요약과 공개 출처만 노출한다. 본문에 검증용 `[S1]`·`[N1]` 표식을 그대로 보여주지 않되 내부 추적 정보와 References는 유지한다. 한국어 불릿, 통화 $M/$B/$T, 사용자 수 만/억, 실적 비교 상회/하회 표기를 따른다.

차트는 점수 분포·과점/함정·이력 등 원자료에서 생성하며, 규칙 버전이 다른 점수를 한 추세선으로 무심코 연결하지 않는다. 산점도 동점 좌표와 모바일 표 잘림을 검증한다. 순위표와 해석은 투자 지시·수익 보장을 포함하지 않으며 기존 harness의 하단 투자 유의 문구 계약을 따른다.

scorecard에는 hero 이미지와 기업별 뉴스 100건을 기본 필수로 요구하지 않는 것이 S-PLAN의 설계 방향이다. 별도 일반 종목 리포트를 요청한 경우에는 해당 stock 계약을 따른다. 구조 문서에서 두 유형의 적용 범위를 명시하고 현재 검증기를 일괄 약화하지 않는다.

가능하면 독립 세션에서 검토하고 실제 수행자·결과를 남긴다. 수행하지 않은 검토를 4-way 완료로 표시하지 않는다. 기계 검증은 형식·산술·증거 연결을 확인하며, 의미 모순이나 자료 신뢰성까지 자동 입증했다고 주장하지 않는다. 분기 재채점 시에는 원문에서 반복된 의미 모순을 찾는 통독 검토도 수행한다.

두 문서를 합친 구현 명세에는 D-01~D-10, F1~F9, Q01~Q23, T-01~T-20의 담당 모듈·검증 위치가 연결되어야 한다. C-01~C-22는 각각 문구 정정, 원자료 재확인, 규칙 승인 대기, 해결 완료 중 상태와 결정 근거를 가져야 한다.

구조 문서는 특히 다음을 구체화해야 한다.

1. 기존 stock과 scorecard의 계약 분기 및 공통 검증 진입점.
2. 원자료·판단·규칙·계산·출력의 소유권과 실제 저장 스키마.
3. 분석 기준 시점·실행 ID·해시를 단계 간 전달하는 방식.
4. 정성 입력·승계·자료 부족·규칙 결정 대기를 표현하는 사용자 흐름.
5. 기준선 보존, 미리보기, 검토·승인, 동일 입력 확정, 실패 시 원상 유지 방식.
6. 기존 기능 회귀와 이 문서 수용 기준을 실행할 테스트 방법.

이번 문서 작성의 완료와 framework 구현의 완료는 별개다. framework는 승인된 규칙에 따른 계산, 검토 가능한 정성 입력, 원본에서 일관되게 생성되는 산출물, 기존 harness 회귀 검증을 모두 만족해야 완료로 판단한다.
