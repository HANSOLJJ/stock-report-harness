## 발견 사항

점수·순위·체크리스트 판정을 바꾸는 발견은 없다. 아래 B 는 HTML 전용(렌더러 CSS·표 구성) 수정이라 draft_hash 와 results_hash 를 바꾸지 않는다. 고칠 곳은 모두 `scripts/scorecard/render_html.py` 이고 HTML 을 손으로 고치지 않는다.

- B-1. Microsoft 카드가 모바일에서 잘린다(medium, 빌드 전 수정 권장, 점수 영향 없음). HTML 기업 상세 탭, Microsoft 카드 ① 의 사업 줄.
  - 증상. 320px 에서 `card.scrollWidth` 373 > `clientWidth` 271 이고 카드가 `overflow:hidden` 이라 사업 이름과 점수가 잘린다. `LinkedIn(Talent·Marketing·Premium·Sales Solutions)` 은 `…Sal` 에서 끊기고 점수 11.28 이 안 보이며, `Search advertising(Bing·Copilot·Microsoft News·Edge·제3자 제휴)` 의 점수 11.76 도 잘린다. `Microsoft 365 Commercial(…)` 도 요약 줄이 한 줄을 넘는다. 375px 에서도 47px 넘친다. 768px 이상은 맞는다. Alibaba `국제 소매(AliExpress·Trendyol·Lazada)` 요약 줄도 2px 넘친다. 다른 12장은 맞는다.
  - 원인. `details.unit>summary` 가 flex(125행)이고 `.uname`(128행)이 `min-width:auto` 라 공백 없는 긴 이름이 줄어들지 못한다. 시범 5개사에는 공백 없는 긴 사업 이름이 없어 안 보였다.
  - 고칠 방법. 렌더러 CSS 에서 `.uname{min-width:0;overflow-wrap:anywhere}` 한 줄. 고친 뒤 14장 모두 320·375px 에서 `card.scrollWidth <= card.clientWidth` 이고 `summary.scrollWidth <= clientWidth` 인지 다시 잰다.

- B-2. 트리거 탭이 모바일에서 모든 행이 오른쪽으로 잘린다(medium, 빌드 전 수정 권장, 점수 영향 없음). HTML 트리거 탭 표 128행.
  - 증상. 320·375px 에서 표 폭이 603px 로 고정돼(래퍼 271·326px) 128개 행의 관찰 사실·조건·재검토 문단이 전부 오른쪽에서 끊기고 줄마다 가로로 밀어야 읽힌다. 이 문자열은 시범 46건에는 없었다. 768px 이상은 문제없다.
  - 원인. TRG-260(NVIDIA ⑤)의 관찰 사실에 공백 없는 74자 문자열 `Alphabet(TPU)·Amazon(Trainium)·Microsoft(Maia)·Meta(MTIA)·OpenAI(Jalapeño)` 가 있어 자동 레이아웃 표의 최소 폭을 603px 로 끌어올린다. 표 하나라서 한 행의 긴 낱말이 모든 행을 넓힌다.
  - 고칠 방법. 렌더러 CSS 에서 `.trig td{overflow-wrap:anywhere}`. 확인본에 이 한 줄을 임시로 넣으면 표가 271px 로 줄고 래퍼 안 넘침이 0이 됐다. 입력(TRG-260 문장)을 고치는 방법은 draft 해시를 바꾸므로 쓰지 않는다.

- B-3. HTML 순위표에 순위 열이 없다(medium, 빌드 전 수정 권장, 점수 영향 없음). HTML 요약 탭 「종합 순위표」.
  - 증상. 열이 기업·①~⑤·과점·⑥~⑨·함정·조정총점뿐이라 공동 순위(5위 Microsoft·Apple, 8위 Alibaba·Palantir, 11위 SpaceX + xAI·Tesla)가 표에서 보이지 않고, 열 제목을 눌러 정렬하면 순위 순서마저 사라진다. 순위는 카드 머리(`5위(완료 14개사 기준)`)에만 있다. draft 순위표에는 순위 열이 있다. `docs/scorecard/structure.md` 6절은 「첫 두 열 고정」(순위·기업)인데 렌더러는 기업 열 하나만 고정한다(pilot10 N8 이월). 시범 5곳은 동점이 없어 눈에 띄지 않았다.

## 빌드 전 상태와 빌드 뒤 확인

초안은 구조적으로 빌드할 수 있다(H1 하나, 필수 절 여섯, 순위표·카드·preview 숫자 일치, 확인본에서 HTML 구조 검사 오류 0건). 점수·순위를 바꾸는 발견이 없어 이 영역의 결과는 pass 다.

빌드 전에 고칠 수 있는 것은 B-1·B-2·B-3 이고 모두 `render_html.py` 한 파일의 HTML 쪽 수정이다. draft 는 `render_md` 에서 만들어지므로 `draft_hash` 가 바뀌지 않는다. 고친 뒤 `draft` 단계를 다시 돌려 `draft_hash` 가 `2efc197d5781231e…` 그대로인지 확인하고, 달라지면 렌더러 수정을 되돌린다. N1~N19 는 draft 나 입력을 바꾸므로 다음 실행에서 한다.

빌드 뒤에는 `uv run --frozen python -X utf8 scripts/validate_report_contract.py ai-scorecard-2026-10-v30full --require-html` 로 HTML 존재와 해시 결합을 확인한다. 화면은 320·375·768·1280px 에서 카드를 연 상태의 `card.scrollWidth <= card.clientWidth`(14장 전부), 트리거 표 폭, 순위표의 순위 열, 산점도 글자 크기를 다시 잰다. 본문 `감사 기록` 링크는 빌드가 `audit.md` 를 쓴 뒤 같은 폴더에서 연다. 승인 칸(머리 칩·푸터)은 승인 뒤 채워진 값으로 한 번 더 본다.
