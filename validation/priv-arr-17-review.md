## 원본이 이미 알고 있던 것

`arr` 의 한계를 원본 작성자가 정확히 인지하고 보정까지 해뒀다.

> post-money **$965B ÷ ARR $65B(7월) = 14.8배** — 그러나 **ARR은 런레이트라 TTM 매출보다 과대**하다. 분모를 TTM 으로 맞추면 **약 30~39배**(Q2 매출 $10.9B 역산) = Palantir 의 절반 수준

자본효율도 v1.5 규칙에 **공식 정의**돼 있다.

```
🔑 자본효율 — 비상장 ⑥의 보조 지표
   자본효율 = ARR ÷ 누적 조달액
     Anthropic  $65B ÷ $125B = 0.52
     OpenAI     $40B ÷ $180~190B = 0.22
```

**따라서 P2·P4 는 정의와 근거가 원본에 다 있다.** 설계진행이 "분모가 불확실하다" 고 한 것은 과했다.

**진짜 문제는 옮기는 과정이다.** 원본에는 `(7월)`·`런레이트`·`TTM 대비 과대` 라는 맥락이 다 있는데, `observations.json` 으로 옮기면서 `period` 가 `null` 이 되고 성격 표시가 떨어져 나갔다. worker 지적대로 `kind` 는 `run_rate` 라고 말하고 있으므로 **은폐가 아니라 이름과 종류의 불일치**다.

## P3 중복 판단 철회

설계진행이 "비상장 P3 는 ③ LastMover 가속도와 중복이니 빼야 한다" 고 했다. **철회한다.** 원본이 명시적으로 갈라놨다.

| 개념 | 지표 | 어느 칸 |
|---|---|---|
| 위치 | 현재 규모 (ARR·시트 수·점유율) | **①** |
| **속도** | **성장률 (YoY·QoQ %)** | **참고** ← 어느 factor 도 안 셈 |
| 가속도 | 성장률의 **변화** | **③** |

**③ 은 2계(가속도)를 재고 P3 는 1계(성장률 자체)를 잰다.** 원본이 "속도" 를 참고로만 두고 어느 factor 에도 배정하지 않았으므로 **P3 는 비어 있던 자리를 채우는 것**이다.

Anthropic 이 그 사례다. 월 증가율이 `+58% → +57% → +14%` 로 꺾여 **③ 에서 감속으로 이미 감점**받았으나, `$47B → $65B` 는 P3 관점에서 여전히 고성장이라 감점 대상이 아니다. **두 판정이 공존하는 것이 맞다.**

다만 원본이 ③ 에 건 제약을 P3 에도 볼지는 구분이 필요하다.

> ⚠️ 플랫폼 전체 성장률이 아니라 **AI 에 귀속되는 부분만** 본다.

**P3 는 전사 기준으로 간다.** F6 는 ⑥ 가격이고 분자가 전체 시총이므로 분모도 전체 매출이 맞다. ③ 은 AI 귀속분, P3 는 전사 기준 — 재는 대상이 다르다. **스펙에 명시한다.**

## 비상장 트랙 확정

사용자가 **기간 기준이 달라지는 것을 감수**하기로 했다.

```
P1  불가 (주가 없음)
P2  post_money ÷ ARR          v1.5 정의 있음
P3  ARR 증가율 — 직전 대비     원본에 +58% → +57% → +14% 있음
P4  ARR ÷ 누적조달            v1.5 공식 정의 (자본효율)
     상한 -5
```

**기간 기준 차이는 P4 보정이 자동으로 잡는다.** `기간 단위가 TTM 아님` 조건에 걸려 한 칸 내려간다. 규칙이 스스로 정합한다.

## worker 의 구조적 발견 — F6 스펙 전에 정리 필요

같은 값이 `contracted_revenue` 에도 들어가 있고 거기서는 **배제**돼 있다.

```
anthropic  contracted_revenue = 65,000,000,000   status=incompatible_basis
           raw="ARR $65B — 계약 수입 아님(C-07)"
openai     contracted_revenue = 40,000,000,000   status=incompatible_basis
```

**F9 가 C-07 근거로 못 쓴다고 판정한 값을 F6 가 P2·P4 분모로 받아쓰게 된다.** 요구하지 않았는데 스스로 찾았다.

다만 `incompatible_basis` 는 **"계약 수입이 아니다"** 라는 뜻이지 **"값 자체가 못 쓸 것"** 이라는 뜻이 아니다. F9 g4 는 계약 수입을 요구하는데 런레이트는 계약 수입이 아니라서 배제된 것이고, F6 P2 는 매출 규모를 요구하므로 런레이트가 부적합하지 않다. **같은 값이 한 factor 에서 배제되고 다른 factor 에서 쓰이는 것이 모순은 아니다.**

그래도 **스펙에 이 구분을 명시한다.** 적어 두지 않으면 다음 사람이 "F9 에서 버린 값을 F6 가 쓴다" 로 읽는다.

## worker 질문 넷

1. **Anthropic 약관의 증권·금융 조언 목적 사용 금지 조항** — **사용자 판단 사항이 맞다.** 사실이면 수집 방법이 아니라 용도의 문제이고 손으로 옮겨 적어도 걸린다. 다만 **v1.5 원본이 프로젝트에 있으므로 이번 건은 이 조항을 건드리지 않고 해결된다.** 판단을 보류하고 넘어간다.
2. **약관을 프로그램으로 받아 읽는 행위** — **허용한다.** 조건을 알아야 준수 여부를 판단할 수 있고, 약관 페이지 자체를 읽지 못하면 정책이 성립하지 않는다. **표준으로 정한다 — `robots.txt` 와 약관·정책 문서는 확인 목적으로 조회할 수 있고, 그 외 내용 페이지는 약관 확인 후에만 조회한다.** 긴장을 보고서에 적은 처리가 옳다.
3. **`contracted_revenue` 충돌** — 위에서 다뤘다. 모순은 아니나 스펙에 명시한다.
4. **v1.5 원본 확보** — **정확했고 실제로 있었다.** 이번 라운드에서 가장 값진 제안이다.
