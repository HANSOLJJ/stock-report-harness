## C-05 = `apply`

**G1 실패 뒤 G3·G4 를 실제 감점에 적용한다.** 진단 기록으로만 남기지 않는다.

### 왜

`diagnose_only` 면 **적자 기업은 G1 손실률 밴드 하나로 점수가 끝난다.** 적자 경로는 G2 를 이미 건너뛰므로, 여기서 G3·G4 까지 빼면 **적자 기업의 현금을 아무도 보지 않는다.**

실측으로 확인한 결과다.

| 가정 (손실률 같음, 현금만 다름) | `diagnose_only` | `apply` |
|---|---|---|
| 적자 −5% · **런웨이 0.15년** | **−2** | **−4** |
| 적자 −5% · 런웨이 3.1년 | **−2** | −2 |

**"현금 두 달치" 와 "현금 3년치" 가 같은 점수가 된다.** F9 가 재려는 것이 정확히 그 차이다.

역전도 생긴다.

```
적자 -5%, 런웨이 0.15년   →  diagnose_only 에서  -2
oracle 흑자, 런웨이 1.35년 →                     -3
```

**더 위험한 쪽이 더 좋은 점수를 받는다.** 흑자 기업은 G2·G3·G4 를 다 통과해야 하는데 적자 기업은 G1 밴드로 끝나기 때문이다. **현금 검증이 가장 필요한 자리에서 현금을 안 보는 구조**라 거꾸로다.

### 설계진행이 처음에 `diagnose_only` 를 권했다가 뒤집었다

근거가 "차등이 생기기 전에 하한이 먹는다" 였는데 **그것은 v1.5 하한 −5 · 밴드 −3/−4/−5 일 때만 성립한다.** 시작점이 −4 면 아래로 한 칸뿐이다. 재척도로 시작점이 −2 가 되면 두 칸이 남아 차등이 실제로 생긴다. **사용자가 "G1에서 점수 까먹은 애들은 그냥 더이상 감점 주지 말자는거냐" 고 되물어 드러났다.**

### 대가

`apply` 는 G4 에 도달하므로 **`coverage_comparable` 검토 입력과 `offbalance_B` 숫자를 요구한다.** spacex-xai 가 당장은 안 풀리고 `OFFB-24` 조사 결과를 기다린다. **규칙의 옳음을 사는 값으로 받아들인다.**

## C-06 = `proposed_v15_boundaries` 채택 + **−4 하한에 맞춰 재척도**

확정된 함정 재배분이 **F6 −7 · F7 −2 · F8 −5 · F9 −4 = −18** 인데, `v1.7.json` 의 `policies.f9` 는 아직 −5 하한 그대로라 **선언한 range 밖 점수가 나온다.**

### 확정 값

```
g1_bands_proposed
  -10% ≤ m < 0     →  -2      (v1.5: -3)
  -30% ≤ m < -10%  →  -3      (v1.5: -4)
          m < -30% →  -4      (v1.5: -5)

floor                          -4   (v1.5: -5)
g1_bep_retreat_score           -4   (v1.5: -5)
g1_buffer_erosion_min_score    -3   (v1.5: -4)
g1_direction_relief_cap        -2   (v1.5: -3)
```

**불변으로 두는 것.**

```
g2_fcf_negative             -2
g2_private_not_disclosed    -2
g2_fcf_positive_stable       0
g2_fcf_positive_deteriorating -1
g3_runway_keep_years / one_step_years   3 / 1
g3 step                     0 / -1 / -2
g4_coverage_keep            1.0
g4 step                     0 / -1
g1_direction_relief_step    +1
```

### 원칙 — 레벨은 올리고 스텝은 그대로

**하한이 한 칸 올라갔으므로 "점수 자리" 를 지정하는 값은 전부 한 칸 올리고, "몇 칸 움직인다" 를 지정하는 값은 건드리지 않는다.**

| 성격 | 값 | 처리 |
|---|---|---|
| **레벨** — 어느 점수에 앉히는가 | `floor` · 밴드 3종 · `bep_retreat` · `buffer_erosion_min` · `relief_cap` | **한 칸 올린다** |
| **스텝** — 몇 칸 내리는가 | G2·G3·G4 감점폭 · `relief_step` | 그대로 |

`buffer_erosion_min` 과 `relief_cap` 도 같이 올리는 이유는 **둘이 밴드 위에 정의된 경계이기 때문**이다. `buffer_erosion_min` 은 "완충이 잠식 중이면 아래에서 둘째 칸보다 좋아질 수 없다" 이고 `relief_cap` 은 "방향 완화를 받아도 가장 나은 적자 칸을 넘지 못한다" 다. **밴드가 움직이면 두 경계도 같이 움직여야 같은 뜻을 유지한다.** 절대값을 고정하면 재척도 후 뜻이 바뀐다.

### 대안 기각 — "하한만 −4 로"

밴드를 −3/−4/−5 로 두고 하한만 −4 로 내리면 **−4 칸과 −5 칸이 한 칸으로 합쳐져 적자 깊이가 3단계에서 2단계로 줄어든다.** F9 가 재려는 것이 그 깊이인데 변별을 잃는다. 기각한다.

## 점수 영향

`OFFB-24` 이전 시점에서, 두 결정으로 값이 바뀌는 기업은 **둘뿐이다.**

| 기업 | 현행 v1.5 | 확정안 | 사유 |
|---|---|---|---|
| **openai** | −5 | **−4** | 하한이 −4 로 바뀜 (BEP 후퇴 → 하한 직행) |
| **spacex-xai** | `needs_rule_decision` | **G4 대기** | C-06 으로 밴드는 풀리나 `apply` 라 G4 필요 |
| 나머지 12개사 | | **불변** | G1 계열 상수를 안 타는 경로 |

**G1 이 실패하는 기업이 둘뿐이라 재척도의 영향도 그 둘에 한정된다.** 흑자 경로(12개사)는 G2 에서 0 으로 시작해 스텝만 쌓으므로 레벨 상수를 읽지 않는다.

**`spacex-xai` 는 `OFFB-24`(SPCX 미개시 B종 약정 SEC 조사) 결과로 결정된다.** 숫자가 나오면 커버리지로 계산되고, 확인했는데 없으면 그때 C-16 이 묻는 상황이 된다.
