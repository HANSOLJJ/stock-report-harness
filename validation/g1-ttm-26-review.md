# G1-TTM-26 / 26B 2자 재검토 — alibaba 영업손익

- 검토일. 2026-09-11.
- 대상. C-13 `dd67258` · NTM `fa4abee`.
- 판정. **둘 다 `pass`.** 수치가 3자 일치한다. **그리고 앞 라운드에서 통과시킨 숫자 하나가 틀렸다는 것이 여기서 드러났다.**

## 독립 재현

`companyfacts` 를 직접 열었다.

```
us-gaap:Revenues             2025-04-01~2026-03-31   1,023,670,000,000 CNY   20-F  0001193125-26-231755
us-gaap:OperatingIncomeLoss  2025-04-01~2026-03-31      50,150,000,000 CNY   같은 제출
us-gaap:CostOfRevenue        2025-04-01~2026-03-31     616,136,000,000 CNY
us-gaap:GrossProfit          개념 없음
taxonomy                     us-gaap 358 · ifrs-full 0
```

**두 보고서와 한 자리도 다르지 않다.** 영업이익률 `50,150 / 1,023,670 = 4.8990%` 도 맞다. 20-F 연결손익계산서 원문에서 `Income from operations ... 50,150 7,270` 과 `Revenue ... 1,023,670 148,401` 을 확인했다.

**G1 답은 `profit` 이다.** 영업손익이 양수이므로 G1 을 통과하고 C-06 손실률 밴드의 대상이 아니다.

## 앞 라운드에서 내가 통과시킨 숫자가 틀렸다

`F9-DECIDE-20` 보고서 각주가 지금도 이렇게 적혀 있다.

> `*` … **SEC 20-F 공시상 연간 영업이익 1,134억 위안 흑자** 기반 `operating_result_reviewed = profit` …

**FY2026 이 아니다.** 20-F 연결손익계산서 원문이다.

```
Income from operations     FY2024  113,350     FY2025  140,905     FY2026   50,150
```

**`113,350` 은 2024년 3월 결산이다. 두 회계연도 전 값이고 실제 FY2026 의 2.26배다.** 세 해가 나란한 표에서 맨 왼쪽 칸을 읽었다.

**그 보고서를 `pass` 로 판정한 것은 나다.** 결론(흑자)이 맞아서 넘어갔고 **숫자 자체는 확인하지 않았다.** 이 프로젝트가 반복해 배운 "파생값을 원자료로 대조한다" 를 근거 숫자에는 적용하지 않았다. C-13 은 이번 보고서에서 옳은 값을 냈으나 **자기 앞 보고서의 오기를 정정하지 않았다.**

**결론이 안 바뀌었다는 것이 면죄부가 아니다.** 둘 다 양수라 `profit` 판정은 같지만, **그 숫자가 근거로 인용된 이상 틀린 채로 남으면 다음 사람이 그것을 재사용한다.**

## 더 중요한 것 — FY2026 에 영업이익이 3분의 1로 줄었다

```
              FY2024      FY2025      FY2026
영업이익     113,350     140,905      50,150     RMB 백만
매출         941,168     996,347   1,023,670
영업이익률    12.04%      14.14%       4.90%
```

**매출은 늘었는데 영업이익이 `140,905 → 50,150` 으로 64.4% 줄었다.** 마케팅비가 `144,021 → 245,023` 으로 70% 늘어난 것이 주된 자리다(20-F 손익계산서).

**F9 의 G1 은 이것을 못 본다.** 부호만 보기 때문에 `+4.90%` 도 `+14.14%` 도 똑같이 "통과" 다. **적자 깊이 factor 라 흑자 구간의 악화를 잴 수단이 없다** — F6 가 함정 factor 라 상단 변별을 못 하는 것과 같은 구조다. 지금 규칙으로는 정상이고 놓친 것이 아니다. **다만 alibaba 가 `-2` 를 받는 이유가 FCF 이지 수익성 급락이 아니라는 점은 기록해 둔다.**

## C-13 — pass

**20-F 원문 매핑이 정확하다.** `us-gaap:OperatingIncomeLoss` ↔ 손익계산서 `Income from operations` 1:1, `us-gaap:Revenues` ↔ `Revenue` 1:1 을 확인했다. 편의환산 `6.8980` 근거를 Note 2(a) 원문으로 인용한 것, TSM 이 `ifrs-full` 334개인 것과 대비해 BABA 가 `us-gaap` 358개임을 보인 것도 맞다.

### "영구적·구조적으로 불가능" 은 한 칸 과하다

> TTM 조립은 … 공시 체계상 **영구적**·구조적으로 불가능하다.

**FPI 지위는 매년 판정되고 바뀔 수 있다.** 사업 실질이 미국 쪽으로 기울면 국내 발행인이 되어 10-Q 의무가 생긴다. **"현재 FPI 이므로 분기 보고 의무가 없다" 까지가 확인된 사실이고 "영구" 는 그 너머다.**

**OFFB-24 의 BABA 미개시 리스와 같은 형태다.** 그때도 `not yet commenced` 0건이라는 사실에서 "회사가 공시하지 않았다" 로 한 칸 더 갔고 `공시 없음(중요성 미달 가능)` 으로 물렀다. **증거가 받쳐 주는 데까지만 적는 습관을 한 번 더 붙이시라.**

## NTM — pass

**세 가지가 C-13 보다 정확하다.**

1. **영구 단정을 피했다.** "지위가 바뀌면 달라지므로 영구적이라고 단정하지 않았다" 가 정확한 선이다.
2. **부재의 근거를 규정 지식이 아니라 20-F 원문에서 가져왔다.** 회사가 스스로 FPI 라 분기 보고 의무가 없다고 서술한 문장을 인용했다. **우리가 아는 규정이 아니라 발행사가 적은 사실**이라 근거가 한 단계 단단하다.
3. **"연간만 있다" 를 스스로 정정했다.** 반기 관측이 **219건** 있다. 다만 매출·영업손익 기준으로는 2019·2020 두 시점뿐이고 전부 `2021-02-02` 제출 6-K 하나에서 왔으므로 **최신 TTM 복원에는 못 쓴다.** 기간 길이 히스토그램(0~29일 8건 · 180~209일 219건 · 360~389일 5,333건, **80~100일 구간이 빔**)으로 보인 것이 특히 좋다. **"분기가 없다" 를 세는 방식으로 증명했다.**

**환율 약분 실증도 값을 한다.** 두 통화 영업이익률 차이 `0.0000015` 가 환산 문제가 아니라 **공시 USD 의 백만 단위 반올림** 때문임을 밝히고, 반올림 전 값으로 계산하면 소수 12자리까지 일치함을 보였다. **차이를 발견하고 원인까지 분리했다.**

## 물으신 셋에 답한다

### 1. 관측 등록과 `period_basis: annual` 표현

**등록한다. 다만 metric 이름은 바꾸지 않는다.**

`operating_margin_ttm` 이라는 이름에 연간값이 들어가는 것이 걸리는 것은 맞다. 그러나 **이름을 바꾸면 F9 코드·스키마·기존 12개사 관측이 전부 딸려 온다.** 그 대가로 얻는 것이 이름의 정확성뿐이다.

**대신 `period` 와 `basis` 필드로 기간을 명시한다.** 스키마에 둘 다 선택 필드로 있다.

```
period : "2025-04-01..2026-03-31"
basis  : "annual (FPI — 20-F only, 10-Q 0건)"
```

**F6 가 이미 같은 문제를 이 방식으로 풀었다.** `period_basis` 선언으로 트랙을 가르고 tsmc·alibaba 를 연간 트랙에 뒀다. **F9 도 같은 선언을 읽게 하면 된다.**

**한 가지는 분명히 해 둔다 — F9 에서 연간 기준에 추가 감점을 걸지 않는다.** F6 의 `P4` 가 "기간 단위가 TTM 아님" 으로 이미 한 칸 내린다. **같은 한계를 두 factor 에서 두 번 세면 FPI 라는 사실 하나로 두 번 깎인다.** 기록은 하되 벌하지 않는다.

### 2. alibaba 가 G1 을 통과한 뒤 필요한 것

**엔진으로 직접 돌려 확인했다.** `profit` 과 `coverage_comparable=yes` 를 넣으면 경로가 이렇게 간다.

```
G1  pass (profit)
G2  FCF -11.4B 음수        → -2
G3  런웨이 4.98년           → step 0   (현금 56.8B ÷ 소진 11.4B)
G4  contracted_revenue 결측 → C-16 이 가른다
```

**남은 것은 딱 하나, C-16 결정이다.** `hold` 면 `-2`, `downgrade` 면 `-3` 이다. `OBS-REG-25` 가 BABA `offbalance_B` 값과 `contracted_revenue` 의 `not_disclosed_confirmed` 를 등록하면 **C-16 이 물을 수 있는 상태가 된다.** 지금 돌리면 `결측유형 미분류` 라 `pending_data` 로 떨어지는데, **그것이 worker 가 넣은 안전장치가 제대로 작동하는 모습이다.**

**다만 G2·G3 가 얹혀 있는 값이 흔들린다.** `fcf_ttm -11.4B` 와 `cash 56.8B` 가 둘 다 `legacy_unverified` 이고 **기간 정의가 없다.** 이번에 영업손익을 연간으로 선언하면 **이 둘도 같은 연간 기준으로 다시 뽑아야 한다.** 런웨이 4.98년이 G3 무감점을 만드는데 근거가 `legacy` 다. **후속 과제로 남긴다.**

### 3. `GrossProfit` 유도 — 하지 않는다

**계산하지 않은 판단이 옳다.** `Revenues - CostOfRevenue = 407,534` 로 산술은 간단하지만 **지금 그 값을 읽는 곳이 없다.** F9 도 F6 도 매출총이익을 쓰지 않는다.

**규칙으로 굳힌다.** `F6-FIX-21` 에서 "소비자가 없는 선언은 `pending` 표식과 소비 과제 명시로 허용한다" 를 정했다. **유도값은 그보다 엄하게 간다 — 소비자가 생길 때 만든다.** 미리 만들어 두면 **원자료 없이 완제품만 남는 상태**가 되고, 그것이 `ttm_per`·`ps_ratio`·`nonop_share` 가 `legacy_unverified` 로 검증 불가가 된 경로다.

필요해지면 그때 **`Revenues`·`CostOfRevenue` 원자료를 함께 보존하고** 만든다.
