# P4 `nonop_share` — 경계 2.4% 에서 1위 기업을 한 칸 깎는다

- 검토일. 2026-09-11.
- 발견 경위. **worker `a1fcd6a` 재고 보고의 "C-13 이 지금 경로에 안 닿는다" 를 검산하다 나왔다.**
- 성격. **지금 점수를 바꾸지 않는다. 지금 기록해 둘 것이다.**

## 경위

worker 의 재고 보고는 네 항목 전부 맞았다. 그중 "blocking 둘(C-03·C-13)이 지금 경로에 안 닿는다" 를 확인하려고 tsmc·alibaba 의 F6 계산을 열었다. **C-13 은 정말 안 닿았다** — F6 는 `P1 = market_cap / net_income_ttm` 이라 NTM 을 안 쓴다. **그 사실을 확인하는 과정에서 P4 가 보였다.**

**검산이 원래 묻던 것 말고 다른 것을 보여 줬다.**

## 1. 경계 표시가 P4 에만 없다

```
P4 조건   |nonop_share| >= 0.30   →  F6 소계 한 칸 강등

기업        |값|       임계 대비     조건 적중   소계 → 점수
alphabet   0.3955     +31.8%       hit        -2 → -3
amazon     0.3073     **+2.4%**    hit        -1 → -2     ← 유일 조건
meta       0.2765      -7.8%        —         -1 → -1
alibaba    0.5159     +72.0%       hit        -3 → -4
spacex-xai 0.5459     +82.0%       hit         0 → -1
```

**`amazon` 은 `nonop_share` 가 유일하게 걸린 조건이고 총점 15 로 공동 1위다.** 한 칸이 1위 구성을 바꾼다.

```
boundary_tolerance  0.03
boundary_note       "±3% 는 표시 전용이다. 파라미터마다 각자의 경계에 대해 계산한다"

P1·P2·P3   boundary 키 있음 — nearest_boundary · distance_ratio · flag
P4 임계    boundary 키 없음
```

**규칙이 "파라미터마다 각자의 경계에 대해 계산한다" 고 말하는데 P4 만 빠져 있다.** amazon 의 +2.4% 는 다른 자리였으면 플래그가 떴을 거리다. 표시가 없으면 다음 사람이 이 자리가 아슬아슬한 줄 모른다.

## 2. 저장값과 재계산값이 11/12 에서 다르다

```
기업        저장     재계산     부호
alphabet    0.51    0.3955
amazon      0.46    0.3073            ← 33% 차이
meta        0.01   -0.2765    뒤집힘
microsoft   0.06   -0.1607    뒤집힘
tsmc        0.07   -0.1422    뒤집힘
apple       0.01   -0.2011    뒤집힘
nvidia      0.14   -0.0244    뒤집힘
tesla       0.18   -0.1493    뒤집힘
palantir    0.14    0.1266
alibaba     0.54    0.5159
oracle     -0.15   -0.2059
```

**12개사 중 11개가 다르다. 하나씩 틀린 것이 아니라 정의가 갈린 것이다.** 오늘 `cash` 가 세 뜻이었고 `net_cash` 는 정의가 아예 없던 것과 같은 종류다. 엔진은 경고를 남기고 재계산값을 쓴다 — **경고는 맞다. 어느 쪽이 옳은지를 아무도 안 봤다는 것이 문제다.**

**오늘 확인한 것만으로는 점수가 안 바뀐다.** hit/no-hit 가 뒤집히는 기업이 없다 — amazon 은 0.46 도 0.3073 도 임계 위, meta 는 0.01 도 0.2765 도 임계 아래다. **그래서 급한 것이 아니라 지금 적어 둘 것이다.**

## 3. AGENTS.md 조항과 구현이 다르다

```
AGENTS.md 72행
  "새 실행에서 상장사 ⑥은 NTM PER(4개 연속 미발표 분기 ...)만 채점하고 근사치는 대기한다"

실제
  F6 listed   P1 = market_cap / net_income_ttm      ← TTM PER
  ntm_per     관측 12건 존재 · 전부 legacy_unverified · 아무도 안 읽는다
```

**오늘 내가 이 조항을 worker 브랜치에서 main 으로 승격했다(`4056de2`).** 승격할 때 **문면만 보고 구현과 대조하지 않았다.** worker 가 "브랜치에만 있는 절이 사라진다" 고 한 지적이 맞았고, 그래서 옮기는 데 집중하느라 **옮기는 내용이 참인지를 안 봤다.**

조항이 v1.7 다파라미터 설계로 대체됐는데 문면이 안 따라온 것이거나, 구현이 계약을 벗어난 것이다. 그 설계를 한 worker 에게 답만 물었다.
