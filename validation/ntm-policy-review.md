# C-13 원자료 조사 재검토 및 정책 권고

- 검토일은 2026-09-08이다.
- 검토 대상은 scarpper의 QWEN-NTM-DATA-03 최초 완료본과 C-13의 C13-DATA-01 v2 보완본이다.
- worker 검토 기준은 `c13a293`이다. 계산 코드·기준선·실행 결정·승인·HTML은 수정하지 않았다.
- 상태는 **조사 결과 일부 채택, 판정 오류 보완 요청, 정책 권고 작성**이다. 두 보고서의 최종 검토 통과를 의미하지 않는다.

## 1. 판단

**5.1절을 유지하고, 미검증 브라우저 조회 경로를 먼저 확인하는 방향을 권고한다.** 이번 정적 수집 결과만으로 유료 공급사 계약이나 연간 근사치 채점 허용을 결정하지 않는다.

신규 검증 실행에서는 다음 네 미발표 회계분기 EPS 또는 동일한 기간·단위·기준을 입증한 공급사 지표만 채점에 사용한다. 미확보 값은 자료 대기로 둔다. 기존 점수는 과거 이관 기록으로 보존한다. 기존 기준선의 재계산 성공과 현재 데이터 적격 검증을 구분한다.

현재 C-13 선택지에서는 `reject_proxy`가 이 권고와 맞는다. 다만 이 문서는 선택을 실행에 기록한 승인 문서가 아니다. `accept_proxy_with_flag`는 근사치로 순위를 산출하는 별도 정책이며, 데이터 검증을 통과했다는 뜻이 아니다.

## 2. 독립 확인한 사실

### 2.1 기준선의 방법 이름은 검증 결과가 아니다

worker `baseline_import.py`의 `vendor_forward_pe_verified_ntm`는 원본 HTML 값을 이관하면서 회사 집합에 따라 넣은 문자열이다. 현재 기준선 JSON을 직접 집계한 결과는 다음과 같다.

| 항목 | 건수 |
|---|---:|
| 전체 관측 | 227 |
| `ntm_eps` | 0 |
| `ntm_per` | 12 |
| PER 관측 중 `legacy_unverified` | 12 |
| `vendor_forward_pe_verified_ntm` | 10 |
| `annual_weighted_proxy` | 2 |

이 결과는 12개 값이 모두 틀렸다는 증명이 아니다. 네 분기 원자료나 공급사 기간 검증 근거가 새로 확보되었다고 주장할 수 없다는 뜻이다.

### 2.2 방법 이름 정정은 표시만의 변경이 아니다

worker `calc_f6.py`는 `basis.method`로 허용 경로를 선택한다. 메모리 안에서 같은 PER 25.4와 `legacy_unverified` 입력을 두고 방법만 바꿔 직접 실행했다.

| 입력 방법 | 실제 결과 상태 | 실제 점수 |
|---|---|---:|
| `vendor_forward_pe_verified_ntm` | `ok` | -1 |
| `vendor_forward_pe_period_unverified` | `pending_data` | null |

따라서 Qwen의 방법 이름 변경 제안은 현재 코드에서 점수에 영향을 준다. 기존 기준선을 그대로 고쳐 쓰는 방식으로 적용하면 안 된다. 신규 검증 실행의 입력 계약과 과거 기록 보존을 함께 검토해야 한다.

### 2.3 Microsoft·Oracle 비NTM 단정은 성립하지 않는다

설계 5.1절의 기준은 **기준 시점에 이용 가능했던 다음 네 미발표 회계분기**다. 오늘부터 연도 말까지 남은 일수를 재는 기준이 아니다.

| 기업 | 공식 발표 근거 | 2026-09-04 및 09-08 기준 다음 미발표 분기의 종료월 |
|---|---|---|
| Microsoft | 2026-07-29에 2026-06-30 종료 FY26 Q4 실적 발표 | 2026-09, 2026-12, 2027-03, 2027-06 |
| Oracle | FY27 Q1 실적을 2026-09-10 장 마감 후 발표할 예정이라고 공지 | 2026-08, 2026-11, 2027-02, 2027-05 |

공식 발표와 회계기간을 대조하면 두 기업에서 이 네 분기의 기간은 FY27과 일치한다. Oracle처럼 분기가 종료됐어도 실적이 미발표이면 이 계약의 대상이 될 수 있다. 이로부터 “회계연도 말까지 9.82개월·8.84개월밖에 안 남았으므로 비NTM”이라는 논거가 잘못됐음을 확인했다. [Microsoft 공식 발표](https://www.microsoft.com/en-us/Investor/earnings/FY-2026-Q4/press-release-webcast), [Oracle 공식 발표 일정](https://investor.oracle.com/investor-news/news-details/2026/Oracle-Sets-the-Date-for-its-First-Quarter-Fiscal-Year-2027-Earnings-Announcement/default.aspx).

그러나 기간이 같다는 사실만으로 연간 EPS를 네 분기 EPS 합으로 승인하지 않는다. 집계 표본, 주식수 및 조정 기준의 일치도 확인해야 한다. 가격/PER 역산과 연간 EPS의 수치 일치 역시 공급사 방법 정의의 독립 증명이 아니다. 두 기업의 적격 상태도 **미검증**으로 둔다.

### 2.4 SpaceX 티커 누락은 별도 확인 대상이다

Nasdaq 공식 발표와 SpaceX IR은 SPCX의 2026-06-12 거래 개시를 확인한다. 따라서 Qwen의 상장 티커 발견은 Wikipedia에만 의존하지 않고 1차 자료로 보강할 수 있다. `companies.json`의 상장 상태와 티커 누락 정정은 이 근거를 붙여 별도 반영할 수 있으나, NTM EPS 확보나 F6 통과까지 의미하지 않는다. [Nasdaq 거래 개시 발표](https://www.nasdaq.com/newsroom/spacex-ipo-rocket-company-launches-historic-ipo), [SpaceX IPO 완료 발표](https://ir.spacex.com/updates/releases-details/2026/Space-Exploration-Technologies-Corp--Announces-Closing-of-Initial-Public-Offering-Including-Full-Exercise-of-Underwriters-Option-to-Purchase-Additional-Shares-2026-RgoR-Y1Vwh/default.aspx).

## 4. 무료 브라우저 경로 확인 범위

설계진행에서 Orca 브라우저로 StockAnalysis MSFT forecast를 열고 Quarterly 버튼을 실제 클릭했다. 클릭 응답은 성공이었으나 재확인한 화면은 Annual 활성 상태와 연간 표를 유지했다. 네 분기 데이터나 Quarterly 전용 유료벽 메시지는 확인하지 못했다. 처음 snapshot은 연결 종료 오류였고 재시도는 성공했다.

이 관측은 브라우저 경로가 반드시 성공한다거나 유료여서 실패했다는 증거가 아니다. 다음 확보 작업은 이 UI 전환의 실제 응답과 Nasdaq 렌더링을 확인해야 한다. 추후 성공하더라도 현재 조회값을 2026-09-02 과거 컨센서스로 소급하지 않는다.

## 5. 구현 담당자에게 전달할 범위

1. C-13은 근사치 사용 정책이고, 10개사의 공급사 방법 검증 누락은 별도 데이터 적격 문제다. 두 회사를 제외하면 모두 검증 완료라고 표시하지 않는다.
2. 과거 기준선과 승인된 산출물을 보존한다. 신규 검증 실행에서는 모든 상장사에 동일한 기간·통화·주식·회계 기준 검증을 적용한다.
3. 방법 이름 정정이나 적격 판정 변경은 점수 상태를 바꿀 수 있으므로 영향표와 회귀 검증이 필요하다. 이번 조사값으로 기준선을 덮어쓰지 않는다.
4. SpaceX 티커 정정은 1차 출처와 적용 기준일을 붙여 별도 변경으로 관리한다.
5. C-06 경계 제안과 C-05·G4 등의 남은 판단을 C-13 데이터 조사로 확정하지 않는다.
