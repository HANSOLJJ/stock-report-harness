## 2. 통화 — 이번 과제에서 가장 큰 함정

지표 단위가 `USD` 로 고정돼 있어 TWD·CNY 를 그대로 둘 자리가 없습니다. 그런데 **공시 USD 환산치를 두 해 그대로 쓰면 안 됩니다.**

| | 현지통화 | 공시 USD 그대로 | 같은 환율 |
|---|---|---|---|
| **alibaba** | +2.742% → **−3** | +8.085% → **−2** | +2.742% → **−3** |
| **tsmc** (FY2024 기준) | +33.888% → **0** | +25.028% → **−1** | +33.888% → **0** |

**둘 다 한 칸 뜹니다.** 원인은 두 해의 convenience translation 환율이 **서로 다른 20-F 에서 오기 때문**입니다 — alibaba 는 6.8980 대 7.2567, tsmc 는 32.79 대 30.62. 규칙이 P3 에 "현지통화로 계산한다"고 적어 둔 이유가 이것입니다(`parameters.P3.currency_note`).

**그래서 당해와 전년을 같은 환율로 환산했습니다.** 환율이 분자·분모에서 상쇄돼 성장률이 현지통화와 같아집니다.

환율은 **20-F 가 스스로 선언한 값**입니다. 외부 출처를 새로 끌어오지 않았습니다.

| | 환율 | 선언 위치 |
|---|---|---|
| alibaba | **6.8980** | FY2026 20-F 'Exchange Rate Information' (연준 H.10, 2026-03-31) |
| tsmc | **31.37** | FY2025 20-F Note 3 'U.S. DOLLAR AMOUNTS' (F-13) (연준 H.10, 2025-12-31) |

환산 결과가 발행사 자체 USD 공시와 맞는지도 확인했습니다 — TSM 세 항목 전부 상대오차 0.0001% 이내, BABA 세 항목 0.0031% 이내입니다.

### 2.1 환산하지 않으면 P2 가 두 칸 뜹니다

P3 만의 문제가 아닙니다. `P2 = (market_cap − net_cash) / revenue_ttm` 은 USD 시총을 매출로 나눕니다.

```
TSM  TWD 를 그대로 넣으면   EV/Sales =  0.716  밴드  0     ← 31배 틀린다
     32.79 로 환산하면      EV/Sales = 23.485  밴드 -2
     H.10 현물 31.37 이면   EV/Sales = 22.468  밴드 -2
```

**환율을 어느 쪽으로 골라도 밴드는 같습니다.** 환율 선택이 점수를 가르지 않는다는 것까지 확인했습니다.

## 3. SPCX — 왜 혼자 `quarterly_yoy` 인가

**현재 TTM 은 복원되는데 전년 TTM 이 복원되지 않습니다.**

```
당해 TTM  = FY2025 18,674 + H1'26 12,508 − H1'25  8,138 = 23,044   ✅
전년 TTM  = FY2024 14,015 + H1'25  8,138 − H1'24  ??            ← H1'24 가 없다
```

S-1/A 는 연간 3개년과 1분기만, 10-Q 는 2025·2026 상반기만 줍니다. `H1'24` 는 어느 문서에도 없습니다(기계로 확인). P3 는 전년이 있어야 성립하므로 `listed_ttm` 으로 두면 F6 가 미완료가 됩니다.

**분기 전년 동기는 10-Q 에 둘 다 있습니다.** `listed_newly` 트랙이 정확히 이 상황을 위해 있고(`select`: 연간 기간 사실이 없어 P1·P2 가 성립하지 않는 기업), `short_history` 로 한 칸 내립니다. **자료가 없어 무른 트랙으로 내려보낸 것이 아니라, 전년 대조가 성립하지 않는다는 구조적 사실이 트랙을 정합니다.**

다만 손익 셋은 **TTM 으로 등록**했습니다. F9 G1 이 그것을 요구하고 TTM 이 실제로 복원되기 때문입니다.

| metric | 기준 | 값 |
|---|---|---|
| `revenue_ttm` · `revenue_ttm_prior` | `quarterly_yoy` | 7,814 / 4,071 |
| `operating_income_ttm` · `net_income_ttm` | `ttm` | −3,732 / −8,218 |
| `operating_margin_ttm` | `ttm` | **−16.195%** (승계 legacy −14.9% 교체) |

**기준이 섞여 계산되는 자리는 없습니다** — `listed_newly` 는 매출과 손익을 함께 쓰는 계산(P2)을 하지 않습니다. 그 사실을 `basis.basis_mismatch_note` 에 적었습니다.

SPCX `operating_margin_ttm` 교체는 지시대로 **점수를 바꾸지 않습니다**(재척도 밴드에서 −14.9%·−16.195% 둘 다 −3). 바뀌는 것은 근거가 `legacy_unverified` 에서 실측으로 옮겨간 것입니다.

## 4. 부수 1 — `as_of` 최신성 키 분리

`as_of` 한 필드가 두 뜻을 지고 있었습니다. 승계 관측에서는 기준선 날짜, 새 관측에서는 접근일.

**`observed_at` 을 신설했습니다.** `as_of` 는 **자료 기준일**, `observed_at` 은 **관측 시점**입니다.

```python
# inputs.py
def recency_key(obs):
    return obs.get("observed_at") or obs["as_of"]
```

- **승계 관측에는 이 필드가 없습니다** → `as_of` 로 물러서므로 과거 실행의 선택 결과가 바뀌지 않습니다.
- 스키마가 `observed_at >= as_of` 를 강제합니다 — 자료 기준일보다 먼저 관측할 수는 없습니다.
- OBS-REG-25 의 임시 해법(접근일을 `as_of` 에 넣기)도 새 필드로 정리했습니다.

**테스트로 고정했습니다**(`tests/test_scorecard_obs_recency.py`).

| 테스트 | 고정하는 것 |
|---|---|
| `test_value_less_replacement_beats_carried` | **값 없는 교체 관측이 승계를 이긴다** — 파일 순서와도 무관 |
| `test_regression_if_observed_at_removed` | `observed_at` 을 지우면 다시 승계가 이긴다 — 검사가 살아 있는가 |
| `test_verified_still_beats_by_status_first` | 등급이 최신성보다 먼저다 |
| `test_schema_accepts_and_orders_dates` | 날짜 역전 거부 |
| `test_approved_run_has_no_observed_at` | 승인 실행 미변경 |

## 7. TSM FY2025 — 합쳤고, 효과는 따로 떼어 보였습니다

### 7.1 왜 합쳤나

**FY2024 를 등록하면 이미 낡은 것으로 아는 값을 승인 대상 실행에 넣게 됩니다.** 20개월 경과 상태가 승인 기록에 남았다가 다음 차수에 지워지는데, 그것은 신호가 아니라 잡음입니다. TSM FY2025 자체가 F6 입력이므로 같은 관측을 두 번 등록하는 꼴이기도 합니다.

**대조표 가독성은 열을 나눠서 해결했습니다.** `compare_scores.py` 가 FY2024 로 되돌린 변형을 메모리에서 계산해 TSM 효과만 따로 냅니다 — 합치는 비용 없이 분리해 읽습니다.

### 7.2 효과

```
tsmc  F6   FY2024 -5 -> FY2025 -3        총점 9 -> 11
      P1   60.905(-2) -> 39.788(-1)
      P2   23.485(-2) -> 17.072(-1)
      P3    0.339( 0) ->  0.316( 0)
```

**P1·P2 가 각각 한 칸 올라옵니다.** 시총 기준일은 그대로인데 분모가 한 해 새것이 되었기 때문입니다. P3 는 예상하신 대로 +31.61% 로 0점 유지입니다. F9 G1 은 영업이익률 45.68% → 50.83% 로 `profit` 유지입니다.

### 7.3 물으신 것 — "TSM 의 P1·P2 를 읽지 않기로 해 뒀던 제약"

**그 제약은 TSM FY2025 가 푼 것이 아니라 v1.7 이 이미 푼 것입니다.** 제약의 정체는 C-13(`accept_proxy_with_flag` / `reject_proxy`)이고, 그것은 **v1.5 의 NTM PER 정의 아래에서 연간 EPS 가중 근사를 NTM 으로 쓰는 문제**였습니다. v1.7 은 F6 를 P1·P2·P3 로 재정의해 NTM EPS 를 아예 쓰지 않고, `listed_annual` 트랙이 ADR/FPI 에 P1·P2·P3 를 명시적으로 허용합니다(대신 `period_basis_not_ttm` 으로 한 칸 내립니다).

실제로 대조표에서 tsmc·alibaba 의 F6 는 `rule(C-13)` → (v1.7) 로 넘어오면서 풀립니다. **TSM FY2025 가 한 일은 제약을 푼 것이 아니라 그 입력을 8개월 것으로 바꾼 것**입니다.

## 12. `stale_asof` 구현

**선언에 소비자를 붙였습니다.** `_p4()` 가 읽고, 임계는 **보고 주기에 상대적**입니다.

| `period_basis` | 임계 | 근거 |
|---|---|---|
| `ttm` · `quarterly`(`quarterly_yoy` 포함) | **6개월 초과** | 분기는 3 + 여유 |

**단일 임계는 안 됩니다.** 6 하나면 연간 신고자가 상시 걸려 `period_basis_not_ttm` 과 중복되고 FPI 라는 사실 하나로 두 번 깎게 됩니다(G1-TTM-26 이 금지한 것). 16 하나면 분기 신고자가 10개월 묵어도 안 걸립니다. 그 이유를 `why_not_single_threshold` 에 적었습니다.

## 13. P1·P2 환율 규칙 개정

v1.7 `policies.f6.fx` 를 개정했습니다.

> P1·P2 의 USD 환산은 **발행사가 20-F 에 선언한 편의환산 환율**을 우선하고, 선언 환율이 없는 발행사에만 연준 H.10 현물환율을 쓴다. 어느 쪽이든 **당해와 전년을 같은 환율로 환산**하고, 다른 환율을 썼을 때 밴드가 갈리는지 확인해 근거란에 남긴다.

`priority` 를 `["issuer_declared_convenience_rate", "h10_spot_at_price_date"]` 로 두고 H.10 계약(`price_date`·`fx_rate_date`·`fx_backfill_days`·`backfill_limit_days`)은 **`fallback_h10` 아래로 옮겼습니다** — 대체 경로가 됐을 뿐 없어지지 않았다는 것을 테스트로 고정했습니다.

### 13.1 밴드 민감도를 근거란에 남겼습니다

규칙이 요구한 "다른 환율을 썼을 때 밴드가 갈리는지 확인해 근거란에 남긴다"를 **데이터로** 만족시켰습니다. 대안 환율은 같은 발행사가 다른 연도 20-F 에서 선언한 값입니다.

| 관측 | 파라미터 | 쓴 환율 | 대안 환율 | 밴드 차이 |
|---|---|---|---|---|
| tsmc `revenue_ttm` | P2 | 31.37 → 17.072 (**−1**) | 32.79 → 17.845 (**−1**) | 없음 |
| tsmc `net_income_ttm` | P1 | 31.37 → 39.788 (**−1**) | 32.79 → 41.589 (**−1**) | 없음 |
| alibaba `revenue_ttm` | P2 | 6.8980 → 1.701 (**0**) | 7.2567 → 1.790 (**0**) | 없음 |
| alibaba `net_income_ttm` | P1 | 6.8980 → 17.979 (**0**) | 7.2567 → 18.914 (**0**) | 없음 |

**네 건 다 갈리지 않습니다.** 환율 선택이 점수를 만들지 않았다는 뜻이고 그것도 `note` 에 남겼습니다. P3 는 분자·분모가 같은 환율이라 **구조적으로 환율과 무관**합니다.
