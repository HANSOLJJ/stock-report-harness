# TSM-EDGAR-29B — TSM FY2025 연간 매출·영업손익 EDGAR 원문 확보

## 0. 결론

**조건 2 의 FY2024 두 경로 검산이 통과했고, FY2025 를 채택했다.** FY2024 매출·영업손익 모두 companyfacts 값과 EDGAR 원문 값이 **오차 0 으로 정확히 일치**했다(반올림 오차조차 없다). 이에 따라 FY2025 를 뽑았다.

|---|---:|---|---|
| 매출 | **3,809,054,300,000** | `ifrs-full:RevenueFromContractsWithCustomers` | NET REVENUE |
| 영업손익 | **1,936,091,700,000** | `ifrs-full:ProfitLossFromOperatingActivities` | INCOME FROM OPERATIONS |
| 영업이익률 | **50.83%** | (유도 아님 — 아래 §6 참고) | — |

- 회계기간 2025-01-01 ~ 2025-12-31 (12개월, 역년과 일치)
- 제출본 accession **0001628280-26-025362**, form **20-F**, 제출일 2026-04-16, reportDate 2025-12-31, inline XBRL
- 원문 위치 — 연결손익계산서(CONSOLIDATED STATEMENTS OF PROFIT OR LOSS AND OTHER COMPREHENSIVE INCOME), 렌더링 `R4.htm`, 제출 원문 `tsm-20251231.htm`
- **통화는 TWD 로 둔다.** 같은 표의 USD 열(매출 121,423.5백만 / 영업손익 61,717.9백만)은 **편의환산치라 계산에 쓰지 않는다**(§5).

기준일 2026-09-02 대비 경과 — 종전 FY2024 는 **20.1개월**, 이번 FY2025 는 **8.1개월**. 12개월 당겨졌다.

| 영업손익 | 1,322,053,000,000 | 1,322,053,000,000 | 0 | 일치 |

- **지시서가 제시한 두 기준값을 그대로 쓰지 않고** 내 companyfacts 스냅샷에서 직접 다시 뽑아 대조했다. 결과는 지시서 값과 같았다.
- **FY2023 도 두 경로가 맞는다**(2,161,735.8백만 TWD). 검토에서 설계진행이 확인해 준 사실이며, 두 해가 겹쳐 검산되므로 파싱 경로의 근거가 한 해짜리보다 두껍다.
- 두 경로가 **서로 다른 제출본**이라는 점이 이 검산의 값어치다. companyfacts 의 FY2024 는 FY2024 20-F(2025-04-17 제출)에서 왔고, EDGAR 원문 값은 FY2025 20-F(2026-04-16 제출)의 비교표시 열에서 왔다. **재작성이 있었다면 여기서 드러났을 것이고, 드러나지 않았다.**

## 2. 채택 경로와 개념 확정

개념 이름은 추정하지 않고 렌더링 파일의 `defref_` 속성에서 각 줄에 직접 결합해 읽었다.

- NET REVENUE → `ifrs-full:RevenueFromContractsWithCustomers`
- INCOME FROM OPERATIONS → `ifrs-full:ProfitLossFromOperatingActivities`

둘 다 G1-FILL-27B 의 후보 목록(`REV_CANDIDATES` / `OP_CANDIDATES`)에 이미 있는 개념이다. **새 개념을 도입하지 않았고, 규약 3(개념 Coalesce 는 기간별 fallback)의 순위를 바꿀 필요도 없다.**

`ifrs-full:Revenue` 도 이 회사의 과거 연도(2015~2024)에 존재하지만 FY2025 손익계산서의 매출 줄에 태깅된 개념은 `RevenueFromContractsWithCustomers` 다. 규약 3 은 회사별 고정이 아니라 기간별 fallback 이므로 **FY2025 기간에 상위 개념이 값을 가지면 그것을 쓴다**는 기존 규약대로 동작한다.

## 3. 열 순서를 가정하지 않았다

렌더링 표의 열 순서를 눈으로 넘겨짚지 않고 머리글 행에서 연도·통화를 파싱해 확정했다.

```
col0  year=2025 currency=TWD
col1  year=2025 currency=USD
col2  year=2024 currency=TWD
col3  year=2023 currency=TWD
```

이게 중요한 이유는 **제출 원문 본문의 열 순서가 정반대**이기 때문이다. `tsm-20251231.htm` 본문은 `2023 2024 2025 US$(Note 3)` 순으로 싣는다. 열을 잘못 잡으면 FY2023 값을 FY2025 로 보고하게 되는데, 두 경로의 열 순서가 서로 반대라 대조가 곧 그 오류의 검출기 역할을 했다.

## 4. 채택값 검증 넷

**(1) 표 내부 산술** — 네 열 모두에서 닫힌다.

| 열 | 매출−매출원가 = 매출총이익 | 총이익−영업비용+기타영업 = 영업이익 |
|---|---|---|
| 2025 TWD | OK | OK |
| 2025 USD | OK | OK |
| 2024 TWD | OK | OK |
| 2023 TWD | OK | OK |

**(2) 제출 원문 대조** — `R4.htm` 은 EDGAR 가 XBRL 로 생성한 렌더링이지 제출 문서가 아니다. 그래서 제출 원문 `20F-TSM-FY2025.txt` 본문에서 따로 확인했다.

```
NET REVENUE 6, 22, 34, 38  $ 2,161,735.8  $ 2,894,307.7  $ 3,809,054.3  $ 121,423.5
INCOME FROM OPERATIONS 38     921,465.6     1,322,053.0    1,936,091.7     61,717.9
```

네 값이 모두 렌더링과 일치한다. **렌더링·제출원문·companyfacts 세 경로가 겹치는 지점에서 모두 같다.**

**(3) companyfacts FY2025 부재 재확인** — 지시서 전제를 그대로 믿지 않고 직접 셌다. 2025-01-01~2025-12-31 기간을 가진 사실이 **전체 taxonomy 를 통틀어 0건**이다. 2026-04-16 제출본(`0001628280-26-025362`)이 companyfacts 에 기여한 사실은 **단 2건**이고 둘 다 재무 수치가 아니다.

```
('dei', 'EntityCommonStockSharesOutstanding', 'shares', None, '2025-12-31')
('srt', 'StockRepurchaseProgramNumberOfSharesAuthorizedToBeRepurchased', 'shares', None, '2024-06-05')
```

**(4) 라이브 재확인** — 보존 스냅샷이 2026-09-10 자라 그 사이 SEC 가 채웠을 가능성을 오늘 직접 호출해 배제했다. 두 개념 모두 **TWD 연간 최신값이 여전히 FY2024**(2025-04-17 제출분)이고 FY2025 관측은 0건이다. 응답 본문을 `raw/live-companyconcept-*.json` 에 보존했다.

즉 **우회는 여전히 필요하며, 이번 채택은 대체가 아니라 보충이다.**

## 5. 통화 — USD 열을 쓰지 않는 이유

F6-FX-16 에서 잡은 함정이 이 문서에도 그대로 있다. 원문이 스스로 밝힌다.

> all translations from NT dollars to U.S. dollars in this annual report were made at **NT$ 31.37 to US$1.00**, the exchange rate set forth in the H.10 statistical release of the Federal Reserve Board on **December 31, 2025**.

- 재무제표 USD 열의 환산 기준은 **기말 단일 환율 31.37** 이다(Note 3 에서 재확인). 매출·영업손익 두 줄에서 역산한 내재환율이 **둘 다 정확히 31.3700** 으로 나와 이를 뒷받침한다.
- 같은 20-F 안에 **다른 환율이 공존한다.** 설비투자 서술은 **가중평균 31.11**(2025년)을, 매출 변동 서술은 2024년 **32.13** → 2025년 **31.11** 을 쓴다. **어느 환율인지 밝히지 않은 USD 수치는 이 문서 안에서도 모호하다.**
- 결정적으로 각 연도가 **자기 연도의 기말환율**로 환산되므로 연도 간 USD 비교는 환율 변동에 오염된다. FY2025 20-F 의 USD 열은 FY2023·FY2024 를 표시하지 않는데, 표시했더라도 FY2024 20-F 의 USD 열과는 다른 환율이 걸렸을 것이다.

따라서 **G1 입력은 TWD 로 등록하고, 환산이 필요하면 소비 시점에 공통 환율을 적용한다.** 편의환산 USD 는 참고로만 기록한다.

## 6. 영업이익률을 유도값으로 저장하지 않는다

위 표의 50.83% 는 **보고용 표시이지 저장 대상이 아니다.** 매출·영업손익 두 원자료를 그대로 남겼고 비율은 소비하는 쪽에서 계산한다. G1-TTM-26B 에서 `GrossProfit` 에 적용한 기준("읽는 곳이 지금 없으면 만들지 않는다")과 같다.

참고로 FY2024 영업이익률은 45.68% 였다. **FY2025 에 5.15%p 개선**이다. 이 비교는 두 해 모두 TWD 기준이라 환율이 상쇄되어 유효하다.

**비율 자체는 통화에 불변이다.** 분자와 분모가 같은 환율로 환산되므로 환율이 약분된다. 다만 **표시 반올림까지 같지는 않다** — USD 열이 백만 단위 소수 첫째 자리로 반올림돼 있어 TWD 기준 50.82867% 와 USD 기준 50.82863% 가 4.3×10⁻⁷%p 갈린다(직접 계산해 확인). 실무상 무의미한 차이지만 **"같다" 가 아니라 "환율이 약분된다" 가 정확한 진술이다.** **통화를 TWD 로 고정하는 이유는 비율 때문이 아니라 금액 때문이다** — 연도 간 금액 비교와 타사 합산에서 연도별 기말환율 차이가 드러난다. §5 의 왜곡(현지통화 성장률 33.888% 가 공시 USD 로 25.028% 로 줄던 F6-FX-16 사례)이 그 자리다.

## 7. 기간 단위 — TTM 이 아니라 연간이다

TSM 은 foreign private issuer 라 분기 보고 의무가 없어 분기 행이 없다. 이번 값도 **연간(FY) 기준**이며 TTM 이 아니다.

G1-TTM-26B 에서 alibaba 에 확정된 처리를 그대로 따른다 — **metric 이름은 유지하고 `period`·`basis` 로 연간임을 명시하며, F9 에 추가 감점을 걸지 않는다.** F6 의 P4 가 "기간 단위가 TTM 아님" 으로 이미 한 칸 내리므로 FPI 라는 사실 하나로 두 번 깎지 않는다.

## 8. 남는 한계

- **이번 과제가 메우는 것은 신선도이지 기간 단위가 아니다.** TSM 의 G1 입력은 여전히 연간이고, 분기 시계열은 SEC 에 존재하지 않으므로 TTM 은 SEC 원자료만으로는 만들 수 없다.
- companyfacts 가 FY2025 를 싣지 않은 **사유는 여전히 확정하지 못했다.** F6-FX-16 후속에서 `Financial_Report.xlsx` 부재와의 상관을 관찰했을 뿐 인과는 증명하지 못했고, 이번에도 증명하지 못했다. **다만 이 과제의 판단에는 사유가 필요하지 않다** — 원문 값이 FY2024 두 경로 검산을 통과했기 때문이다.
- 이 값은 SEC 가 나중에 companyfacts 를 채우면 **자동 대체되어야 한다.** 지금 등록하는 값에 출처(accession + 줄 이름)를 남긴 이유가 그것이다.

## 10. 검토 반영 (2026-09-11, 판정 pass)

C-13 의 29A 와 2자 대조에서 영업손익 한 자리가 갈렸고 **이쪽 값이 채택됐다.**

| 출처 | 영업손익 (백만 TWD) |
|---|---:|
| 감사 연결손익계산서 본문 (이번 채택) | 1,936,091.7 |
| MD&A 비교표 (C-13 29A) | 1,936,092 |

차이는 0.3백만으로 1.9조 중 무의미하지만 **어느 문서를 읽었는지를 드러낸다.** 등록값은 `1,936,091,700,000` 이다.

**같은 제출본 안에서 수치가 갈리면 감사 재무제표 본문이 우선한다.** F6-FIX-21 이 H.10 note 에 "대조는 재무제표 본문 기준" 으로 적은 것과 같은 원칙이고, 이 20-F 안에서 설비투자 서술이 가중평균 31.11 을 쓰던 §5 의 사례가 다른 형태로 다시 나온 것이다.

열 순서 처리에 대해서는 — 검토 시점에 **C-13 이 BABA 20-F 에서 실제로 이 함정에 걸렸다.** 113,350 을 FY2026 으로 읽었으나 그 표도 오름차순이라 113,350 은 맨 왼쪽 FY2024 였고 실제 FY2026 은 50,150, **2.26배 차이**였다. §3 의 머리글 파싱이 가정 회피가 아니라 실제 오류 방지였음이 같은 날 확인된 셈이다.

추가로 확정된 사항 — **C-16 은 downgrade 로 확정**됐다(설계진행 커밋 `1d39409`).
