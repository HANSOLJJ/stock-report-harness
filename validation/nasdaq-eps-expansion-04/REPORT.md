## 3. 게이트 3 — 채택 불가 (결정적)

### 3.1 robots.txt 전면 차단

```
GET https://api.nasdaq.com/robots.txt   → HTTP 200

# This robots.txt file disallows all web crawlers from indexing any pages
# in this API application to prevent search engine indexing of API endpoints

User-agent: *
Disallow: /
```

`www.nasdaq.com/robots.txt` 는 `User-agent: *` 에 `Crawl-delay: 30` 을 건다.

### 3.2 이용약관이 자동·수동 캡처를 금지한다

Nasdaq 약관은 다음을 금지한다.

> "accessing or using the Service through any automated or manual process to capture data or content from the Service or circumvent any mechanisms for preventing unauthorized reproduction or distribution of the Service"

그리고 별도로 AI·머신러닝·데이터 분석 목적의 추출을 명시적 서면 허가 없이 금지하며, 여기에 **스크래핑과 데이터 마이닝을 포함**한다고 적는다. 위반은 계약 위반으로 즉시 해지 사유가 된다.

### 3.3 판정과 조치

**Nasdaq `api.nasdaq.com` 은 우리 파이프라인의 자료 원천으로 채택할 수 없다.** 무료·무키로 응답한다는 사실이 이용 허가를 뜻하지 않는다.

- **12 개사 확장 조회를 실행하지 않았다.** 요청받은 작업이지만 위 확인 직후 수행하면 약관이 금지한 행위가 된다.
- `../spacex-eps-source-03/REPORT.md` 에 기록된 SPCX·AAPL·TSM·BABA 4 종목 자료는 **약관을 확인하기 전 탐색 과정에서 수집한 것**이다. 조사 기록으로는 남기되 **생산 경로의 자료로 쓰지 않는다.** 그 보고서의 "1 순위 후보" 판정은 이 보고서로 철회한다.
- 계속 쓰려면 **Nasdaq 과의 라이선스·서면 허가**가 선행되어야 한다. 이는 조달 결정이므로 사용자·설계진행 판단 사항이다.

## 4. 게이트 1·2 — 확보된 범위만

게이트 3 이 닫혀 채택 판단에 영향이 없다. 추가 조회 없이 기존 응답에서 확인된 것만 적는다.

### 4.1 GAAP/비GAAP — 미확인

응답 헤더 라벨이 `Consensus EPS* Forecast`, `High EPS* Forecast`, `Low EPS* Forecast` 로 별표를 달지만 **각주 본문이 JSON 응답(2,021 바이트)에 없다.** 각주는 웹 페이지에 있을 것으로 보이나 3 절 때문에 추가 조회하지 않았다.

간접 근거는 있다. 우리 기준선 `ntm_per 111.0` 의 출처인 StockAnalysis 페이지가 **"EPS and Forward PE are based on non-GAAP adjusted numbers"** 를 명시한다. 업계 컨센서스가 비GAAP 조정치를 기본으로 삼을 가능성이 높다는 정황이다. 확정은 아니다.

### 4.2 추정 갱신 시각 — 대체 수단 없음

`quarterlyForecast.asOf` 와 `yearlyForecast.asOf` 가 **모두 `null`** 이다. 응답 본문 어디에도 추정 시점 필드가 없다. `up`·`down`(최근 4 주 상향·하향 수정 건수)이 있어 "최근 4 주" 라는 창은 암시하지만 기준 시각을 특정하지 못한다.

우리 공통 방법은 "공급사의 갱신/추정 기준 시각(미표시면 미확인)" 을 요구한다. **미표시이므로 미확인으로 기록해야 한다.**

## 7. TSM·BABA 단위 변환 독립 확인 — SEC XBRL

요청하신 필수 검증 항목이다. 공급사 값이 아니라 **SEC 제출 원문**으로 확인했다.

### 7.1 TSM — SEC 는 보통주 기준, 공급사는 제각각

TSMC 는 IFRS 를 쓰므로 `us-gaap` 택소노미는 404 이고 `ifrs-full` 로 조회해야 한다.

```
GET /api/xbrl/companyconcept/CIK0001046179/ifrs-full/DilutedEarningsLossPerShare.json
units: ["TWD/shares", "USD/shares"]
  2024-01-01~2024-12-31  TWD/shares  44.67   form=20-F
  2024-01-01~2024-12-31  USD/shares   1.36   form=20-F
```

두 값의 비 `44.67 / 1.36 = 32.85` 는 2024 년 TWD/USD 환율 수준과 맞는다. 즉 **같은 주식 단위를 두 통화로 표시**한 것이다.

주식 단위 판정 — TSMC FY2024 순이익 약 TWD 1.173 조를 EPS 로 나눈다.

```
1,173,000,000,000 / 44.67 = 약 262.6 억주  → TSMC 보통주(약 259~263 억주)
ADR 기준이라면 약 52.5 억주여야 하는데 맞지 않는다
```

**결론: SEC 의 TSM EPS 는 보통주 1 주 기준이며 TWD·USD 두 통화로 제공된다.**

이를 기준으로 공급사를 대조하면 이렇다.

| 원천 | 통화 | 주식 단위 | 근거 |

| **SEC (20-F)** | TWD 와 USD | **보통주** | 위 검산 |

### 7.3 실무 함의

우리 F6 은 주가 ÷ EPS 를 **같은 통화·같은 주식 기준**으로 요구한다(`calc_f6._basis_alignment`).

- TSM·BABA 의 미국 상장 주가는 **USD, ADR/ADS 단위**다.
- 따라서 필요한 EPS 는 **USD × ADR/ADS 기준**이다.
- **SEC 값을 그대로 쓰면 안 된다.** SEC 는 보통주 기준이므로 ADR 비율(TSM 5, BABA 8)을 곱해야 한다. 다만 SEC 는 실적이지 컨센서스가 아니다.
- 공급사 중 이 조합을 바로 주는 곳은 **Yahoo(TSM) 와 Nasdaq(TSM·BABA)** 뿐이다. Yahoo 의 BABA 는 CNY 라 환산이 필요하다.

**어느 원천을 쓰든 `basis` 를 우리가 명시적으로 확정하고 검산으로 확인해야 한다.** 이번 검증이 그 방법(순이익 ÷ EPS 로 함의 주식수를 역산해 보통주·ADR 중 어느 쪽인지 판정)을 보여준다.

## 9. 미확인 사항

1. **Nasdaq 각주의 GAAP/비GAAP 기준.** 게이트 3 때문에 추가 조회하지 않았다. 라이선스를 얻는다면 함께 확인할 항목이다.
2. **Nasdaq 이 정말 라이선스로 열리는지, 비용이 얼마인지.** 조달 문의를 하지 않았다.
3. **yfinance 이용 조건.** 프로젝트가 `AGENTS.md` 에서 가격 데이터에 yfinance 를 쓰도록 이미 정하고 있어 기존 관행을 따랐다. 다만 Yahoo 의 약관을 이번에 별도 검토하지는 않았다. **컨센서스 수집으로 용도를 넓히기 전에 검토를 권한다.**
4. **Finnhub 유료 `stock/eps-estimate`.** 4 분기와 표본 수를 함께 주는지 확인하지 못했다(403).
5. **TSM·BABA 의 분기 단위 SEC 자료.** 두 회사 모두 XBRL 에 연간(20-F) 값만 있고 분기 값이 없다. 분기 실적 대조에는 6-K 원문을 읽어야 한다.
6. **BABA 의 `fiscalYearEnd` 가 SEC submissions 에서 null 인 이유.** 20-F 회계기간으로 우회 확정했으나 원인은 확인하지 않았다.
7. **ORCL 발표일 하루 차이**(Yahoo 09-11 대 Finnhub 09-10)의 정확한 값.

## 11. 권고

1. **Nasdaq 을 후보에서 내린다.** `../spacex-eps-source-03/REPORT.md` 의 "1 순위 후보" 판정을 철회한다. 라이선스를 확보하기 전에는 조회하지 않는다.
2. **점수·정책·관측을 바꾸지 않는다.** 8 절대로 확보 수준에 변동이 없다.
3. **Yahoo 를 컨센서스 원천으로 넓히기 전에 약관을 검토한다.** 이번에 확인하지 않았다(9.3). Nasdaq 에서 겪은 것과 같은 순서 실수를 반복하지 않으려면 수집 설계 전에 봐야 한다.
4. **`basis` 검산을 관측 등록 절차에 포함한다.** 7 절 방법(순이익 ÷ EPS 로 함의 주식수 역산)을 ADR/ADS 종목의 필수 관문으로 둔다.
5. **유료 경로를 비교 검토한다.** Finnhub `stock/eps-estimate` 와 FMP 유료 분기가 각각 4 분기·표본 수를 주는지 확인하고 비용을 비교한다. 무료 경로로는 통계 있는 4 분기가 나오지 않는다는 것이 이번 조사의 결론이다.
6. **NVDA·ORCL 의 어긋난 분기를 파이프라인에 명시한다.** 나머지 10 개사와 종료월이 다르다(5 절).
