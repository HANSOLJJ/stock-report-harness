# 사용 범위 확정 — personal / internal only

- 결정일. 2026-09-10.
- 결정자. 사용자.
- 결정. 이 프로젝트 산출물의 사용 범위는 **personal / internal only** 다. 외부 일반 대중 배포를 전제하지 않는다.

## 배경

F6 원천 확보가 라이선스에서 막혀 있었다. Nasdaq Data Link `ZACKS/EE`·`EEH` 승격 조건 5개 중 `"외부 배포 허용"` 이 있었고, C-13 공문 초안도 "정적 HTML 리포트를 외부 일반 대중에게 배포" 를 전제로 작성돼 있었다. 이 전제 때문에 재배포 라이선스(Redistribution Rider)가 필요했고, 연간 수천 달러대 맞춤 B2B 계약과 영업 협상이 따라붙었다. 사용자가 그 과정을 피하고자 사용 범위를 확정했다.

**기존 기록의 "외부 일반 대중에게 배포" 서술은 사실과 다르다.** 해당 기록을 정정한다.

## 무엇이 바뀌는가

- ZACKS 승격 조건에서 `"외부 배포 허용"` 을 제거한다. 나머지 넷(정식 계약·자동 수집 허용·derived data 허용·보관 조건)은 유지한다.
- 남는 것은 Internal / Display Only 구독이다. 셀프서비스로 가능한지를 확인 대상으로 돌린다.
- C-13 공문 초안은 협상 전제가 사라져 폐기한다. 초안 7절 2항의 12개사 목록에 **AVGO·AMD 가 잘못 들어가 있던 오류**(실제는 PLTR·SPCX)도 함께 기록한다.

## 무엇이 바뀌지 않는가

- **`api.nasdaq.com` denied 는 유지한다.** 배제 근거가 `robots.txt` 전면 `Disallow /` 와 automated or manual process 금지라 개인·상업 구분과 무관하다. 개인 사용이라고 완화하지 않는다.
- **Yahoo 는 여전히 F6 원천 부적격이다.** 사유는 약관이 아니라 기술이다. 2026-09-10 검증 기준 회계분기 창 특정 **0/12**(`0q`·`+1q` 는 상대 오프셋, `earnings_dates` 는 발표일)이고 전망이 **2분기뿐**이라 4분기 NTM 이 불가능하다. allowlist 를 열어줘도 이 결론은 바뀌지 않는다.
- investing.com 등 403 차단 그룹도 그대로다. 차단 우회 수집은 Nasdaq 을 배제한 것과 같은 논리에 걸린다.

## 전제가 깨지는 조건

`output/<slug>.html` 을 외부에 공개하는 순간이다. 게시·공유·링크 전달 전부 포함한다. 그 경우 재배포 라이선스 요건이 되살아난다. 정책 파일에 이 조건을 함께 적는다.
