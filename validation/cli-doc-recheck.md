2026-09-08 설계진행 Codex 검토. worker HEAD는 `ea1ecf095c66cb92a563c4ee785a2f5ae0e67143`이다. Qwen의 보고서와 현재 문서·코드·검증 출력을 대조했다. worker 파일 수정, 사용자 승인 생성, 빌드는 수행하지 않았다.

## 재현 범위와 결과

`recheck_cli_doc.py`는 실제 worker 모듈을 읽어 메모리에서 검사한다.

- D-02는 실제 `scorecard_cli.main()`을 호출하되 `cmd_approve`만 기록용 함수로 대체했다. parser 동작만 검증했고 실제 승인·승인 파일·최종 HTML은 생성하지 않았다. 스키마에는 정상 이름과 잘못된 값 4종을 각각 넣었다.
- D-05는 실제 파일 읽기의 반환값에서 리뷰 본문의 Q07 행만 제거했다. 디스크 리뷰 파일은 그대로이며 오류와 성공 라벨의 동시 출력을 재현했다. 총괄 판정은 계속 FAIL이었다.
- D-10은 정상 run의 메모리 사본에 `change_type`만 추가했고 실제 스키마가 거부했다.
- `init --help`를 실행해 날짜 옵션이 노출됨을 확인했다.
- 현재 slug의 계약 검증은 `needs_fix` 리뷰 때문에 예상대로 FAIL이다. 이는 새 코드 수정으로 만든 실패가 아니며 리뷰 미완료 상태를 그대로 보여준다.
- worker 계산 테스트 31/31개, 기존 독립 회귀 테스트 10/10개 통과. 이 결과는 위 문서·승인·이력 문제들이 해결됐다는 뜻이 아니다.
- 검토 대상 해시를 읽기 전후 비교해 검사 중 변경이 없음을 확인했다. 상세 값과 파일 해시는 `cli-doc-recheck-evidence.json`에 있다.

```powershell
python -X utf8 -B validation/recheck_cli_doc.py
python -X utf8 -B validation/test_scorecard_review.py
```

worker worktree에서 계산 테스트를 실행했다.

```powershell
python -X utf8 -B -m unittest discover -s tests -t .
```

## worker 반영 순서

1. D-01·D-02·D-04·D-05를 기존 미완료 리뷰에 추가한다. 상태 정책을 바꾸거나 에이전트가 승인을 대신하지 않는다.
2. D-03·D-06~D-09는 필요한 안내를 함께 보완하고, D-10은 신규 재채점 기능의 미완료 계약으로 남긴다. D-12는 선택적 힌트다.
3. 이전 기준선 재검토의 결측 상태·기간 검증·이관 보고서 지적과 중복을 정리한다.
4. 수정 후 관련 테스트와 영향받은 산출물을 다시 만들고, 바뀐 해시를 대상으로 리뷰한다. 통과 전 승인·빌드 완료로 보고하지 않는다.

Qwen의 13건을 그대로 결함 목록에 복사하지 않는다. 이 문서는 독립 재검토 결과이며, worker의 4영역 최종 리뷰와 최종 커밋 검증을 대신하지 않는다.
