## 2. W1 — 기준일 고정. 이름 변경과 검사 추가를 **둘 다** 했다

재검토는 둘 중 하나를 택하라고 했다. **둘 다 했다.** 이름만 바꾸면 "그럼 기준일은 누가 보나"가 남고, 검사만 추가하면 라벨 연속성과 기준일 고정이 한 이름에 뭉쳐 다시 같은 문제가 된다.

- 이전 `window-verified` → **`label-continuity`**. 회계 라벨 `(year, quarter)` 의 중복·연속·역순만 본다. 날짜를 쓰지 않는다는 사실을 이름이 말한다.
- 새 게이트 **`asof-anchored`**. 분석 기준일을 `_raw/meta.json` 의 `collected_at_utc` 에서 읽어 **판정에 실제로 쓴다**(2026-09-09).

`asof-anchored` 가 보는 것은 둘이다.

1. 선택된 2E 두 행의 `calendar/earnings` `date` 가 **기준일보다 뒤**인가. 발표일 필드가 없거나 파싱되지 않으면 통과가 아니라 문제로 낸다.
2. 전망 목록에 **기준일 전 이미 발표된 행**(`epsActual` 존재 + `date` ≤ 기준일)이 최신 실적 분기보다 뒤 분기로 남아 있지 않은가. 남아 있으면 2A 가 "최근 확정 2 개"라는 전제가 깨진다.

### 2.1 재현 — 이전 검증기가 통과시키던 것이 막힌다

재검토 T1 을 그대로 재현했다. META 최신 실적 `2026Q2` 를 실적 목록에서 빼 전망 목록으로 옮겼다.

**라벨 연속성이 통과하는 것 자체는 맞다.** 옮긴 뒤에도 네 라벨은 연속이기 때문이다. 그것이 바로 이름을 좁힌 이유이고, 기준일 위반은 새 게이트가 잡는다.

T1b 는 두 번째 검사다. 기준일 전 발표된 `2026Q3` 행을 전망 목록에 넣자 `2026Q3 는 기준일 전 발표됐는데 실적 목록에 없음` 으로 막혔다.

## 3. W2 — basis 를 창 4 행 전부에서 읽는다

`sample = (a2 + e2)[0]["raw"]` 를 없앴다. 필드마다 창 4 행 전부를 훑어 상태를 정한다.

| 상태 | 뜻 | 통과 |
|---|---|---|
| 값 | 4 행 전부에 있고 값이 하나 | O |
| `unknown` | 어느 행에도 키가 없다 | X |
| `partialN/4` | 일부 행에만 있다 | **X** |
| `conflict:a\|b` | 행 간 값이 다르다 | **X** |

2A 와 2E 사이의 일치 여부는 `basis_cross_endpoint` 로 **따로** 출력한다(`match` / `conflict` / `one-side` / `unknown`). 두 endpoint 를 함께 쓰는 구조에서 한쪽만 채워지거나 서로 다른 기준인 경우를 판정과 분리해 보여 준다.

### 3.1 재현

```
T2  창 4행 중 1행에만 부여
    basis 통과하지 않는다   {'currency': 'partial1/4', 'share_basis': 'partial1/4',
                             'accounting': 'partial1/4', 'asOf': 'partial1/4'}
    score-ready 가 아니다

T2b 4행 전부 채우되 한 행만 다른 값
    conflict 로 낸다        {'currency': 'conflict:KRW|USD', 'share_basis': 'common',
                             'accounting': 'conflict:ifrs-full|us-gaap', 'asOf': '2026-09-01'}

T2c 2A 는 USD, 2E 는 TWD
    2A-2E 일치가 conflict   {'currency': 'conflict', 'share_basis': 'match',

```

T2b 의 출력에 넣은 값(`KRW`·`ifrs-full`)이 그대로 나온다. **검증기가 상수를 찍는 것이 아니라 입력을 읽는다**는 확인을 겸한다.

### 3.2 결과는 여전히 0/12 다 — 다만 이유가 달라졌다

이전에는 "첫 행에 필드가 없어서" 0/12 였다. 지금은 **4 행 전부에 키가 없어서** 0/12 다. Finnhub 의 `stock/earnings` 와 `calendar/earnings` 응답 어디에도 `currency`·`share_basis`·`accounting`·`asOf` 키가 존재하지 않는다. 값이 비어 있는 것이 아니라 키 자체가 없다. 2A–2E 일치도 네 필드 모두 `unknown` 이다. **양쪽에 아무것도 없는 것은 일치가 아니다.**

## 6. W5 — 3 절 근거를 커밋했다

지적대로였다. `_raw/sec/<TICKER>.json` 은 커밋돼 있으나 본문이 `"(본문 생략 — 크기)"` 인 stub 이고, 검증기가 읽던 `../f6h-feasibility-08/_raw/` 는 비커밋이다. 커밋 트리만으로는 3 절이 전부 `unknown` 이었다.

대조에 필요한 것은 **분기 종료일 목록뿐**이므로 그것만 파생해 커밋했다.

**8 (신규). 회계 라벨과 기업 공시의 대조.** `asof-anchored` 는 공급사가 준 발표 예정일을 기준일과 비교할 뿐, 그 라벨이 기업 공식 회계연도 표기와 맞는지는 보지 않는다. R1 7.2-7 과 같은 항목이며 여전히 미확인이다.
