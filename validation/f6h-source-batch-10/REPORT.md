| FMP(무료) | 0/12 | 등재 | 전 종목 HTTP 402. 분기 파라미터가 유료 |

그리고 통과한 11 개사도 **기준 항목이 비어 있다**. Finnhub 은 asOf·회계기준·통화·주식기준·표본 수·min/max 를 **하나도 제공하지 않는다**(4 절). 즉 "값은 오지만 그 값이 무엇인지 공급원이 말하지 않는다."

## 2. 조사 설계

### 2.1 판정 기준

F6-H = 최근 확정 2 개 분기 실적(2A) + 향후 2 개 분기 컨센서스(2E).

- **통과** = 한 공급원에서 2A 와 2E 를 **모두** 얻는 기업
- **공급원 통과** = 12 개사 전부가 통과

**종목별 공급원 혼합은 금지다.** A 사에서 실적을, B 사에서 전망을 가져오는 것도, 종목마다 다른 공급원을 쓰는 것도 하지 않는다.

### 2.2 조사 대상 공급원

| 공급원 | endpoint | allowlist |
|---|---|---|
| Finnhub | `stock/earnings`(2A) + `calendar/earnings`(2E) | v1.6 등재 |
| FMP | `stable/analyst-estimates?period=quarter` | v1.6 등재 |
| SEC | `companyconcept/us-gaap/EarningsPerShareDiluted` | v1.6 등재 |
| Yahoo | yfinance `earnings_estimate` + `earnings_dates` | **미등재** |

**`api.nasdaq.com` 은 호출하지 않았다.** v1.6 `rules.sources.denied` 의 생산 배제 대상이다.

Yahoo 는 조사 대상에는 넣되 **채택 후보로 취급하지 않는다.** 상류 API 가 personal use only 이고 약관 검토가 선행 조건이다(`../f6-policy-decision-05/` 2.2).

### 2.3 Finnhub 이 두 endpoint 를 쓰는 것은 혼합인가

아니다. **같은 공급원의 서로 다른 조회다.** 실적과 전망을 담는 endpoint 가 나뉘어 있을 뿐 발행 주체가 하나다. 금지되는 것은 **서로 다른 공급원**의 값을 한 창에 섞는 것이다.

다만 이 구조에는 따로 문제가 있다. `stock/earnings` 의 실적과 `calendar/earnings` 의 전망이 같은 기준으로 산출되는지 공급원이 명시하지 않는다(4 절).

**F6-H 자체는 전망 2 개만 필요하므로 3 개는 여유가 있다.** F6-N 이 4 개를 못 채워 막혔던 것과 대조된다.

### 3.2 FMP(무료) — 0/12

12 개사 **전부 HTTP 402**.

```
Premium Query Parameter: 'Special Endpoint : This value set for 'period' is not
available under your current subscription
```

`period=quarter` 자체가 유료 파라미터다. 종목 문제가 아니라 파라미터 문제이므로 **무료 등급에서는 어떤 종목도 통과하지 못한다.**

### 3.3 SEC XBRL — 0/12

- 분기 EPS 조회 가능: **10/12**. TSM·BABA 는 20-F 제출사라 분기 개념이 없다.
- **전망 필드가 존재하지 않는다.** 공시는 실적만 담는다.

따라서 2E 확보 0 개사이고 **구조적으로 통과 불가**다. 다만 실적의 권위 있는 근거이고 회계기준(`us-gaap`)·통화·제출일(`filed`)을 명시하므로 **교차검증용으로는 가장 낫다**(4 절).

또한 미국 제출사는 회계 4 분기 EPS 를 태깅하지 않아 연간에서 복원해야 한다(`../f6h-feasibility-08/` 3.1).

### 3.4 Yahoo — 11/12 (채택 후보 아님)

| 티커 | 2A | 2E | 전망 통화 | 매매 통화 | 표본 n | min/max | 비고 |
|---|---|---|---|---|---|---|---|
| META · NVDA · GOOGL · MSFT · AAPL · ORCL · TSLA · TSM | O | O | USD | USD | O | O | |
| AMZN | O | O | USD | USD | O | O | 음수 실적 2 건 |
| PLTR | O | O | USD | USD | O | O | 음수 실적 1 건 |
| **BABA** | O | O | **CNY** | **USD** | O | O | **전망 통화 ≠ 매매 통화** |
| **SPCX** | **X** | O | USD | USD | O | O | 확정 분기 1 개 |

**BABA 가 결정적이다.** 전망 EPS 가 CNY 로 오는데 ADS 는 USD 로 거래된다. 이 값을 그대로 주가와 나누면 통화가 어긋난다. 우리 `_basis_alignment` 가 거부해야 하는 형태다.

이 사실은 **공급원이 통화를 명시했기 때문에 잡혔다.** Finnhub 은 통화 필드가 없어 같은 문제가 있어도 드러나지 않는다.

> 조사 중 오류를 하나 잡았다. 처음에는 `info.currency`(매매 통화)를 읽어 BABA 도 USD 로 표시됐다. 전망 행 자체의 `currency` 를 읽도록 고쳐 CNY 임을 확인했다. **매매 통화와 전망 통화는 다른 필드다.**

## 5. 종합 판정

### 5.1 한 공급원으로 12 개사 전부는 불가능하다

allowlist 등재 공급원 기준으로 최고가 Finnhub 11/12 다. **막히는 종목이 SPCX 하나이며 원인이 자료 부족(신규 상장)이라 공급원을 바꿔도 해결되지 않는다.** Yahoo 도 같은 종목에서 막힌다.

즉 **SPCX 는 어느 공급원을 골라도 F6-H 가 성립하지 않는다.** 확정 분기가 2 개가 될 때까지(2026Q3 발표 예정 2026-11-03 이후에도 여전히 2 개) 기다려야 한다.

### 5.2 11/12 를 어떻게 취급할 것인가

세 가지 선택지가 있고 각각 대가가 있다.

| 안 | 내용 | 대가 |
|---|---|---|
| **가-1** | Finnhub 단일 공급원, SPCX 는 `pending_data` | 11 개사 채점, 1 개사 순위 제외. **전체 통일 모드의 취지는 유지** |
| 가-2 | 12 개사 전부 대기 | 자료가 있는 11 개사도 못 씀. 현행과 동일 |
| 가-3 | SPCX 만 다른 공급원 | **금지.** 종목별 혼합이며 이번 요청이 명시적으로 배제 |

**가-1 을 권고한다.** 우리 규칙은 이미 자료 미비 기업을 순위에서 제외하고 0 점으로 채우지 않는다. SPCX 를 `pending_data` 로 두는 것은 기존 취급과 일관된다.

### 5.3 다만 4 절이 선결 조건이다

커버리지 11/12 는 **필요조건이지 충분조건이 아니다.** Finnhub 을 쓰려면 다음이 해소되어야 한다.

1. **회계기준.** 실적과 전망이 GAAP 인지 조정치인지. SEC 와 최대 3~6 배 차이가 나는 이유를 특정해야 한다.
2. **`stock/earnings` 와 `calendar/earnings` 의 기준 일치.** 같은 공급원이라도 두 endpoint 가 같은 잣대인지 확인이 필요하다. 2A 와 2E 를 한 합에 넣기 때문이다.
3. **통화·주식 기준.** 필드가 없으므로 기업별로 우리가 확정하고 검산해야 한다. Yahoo 가 BABA 에서 CNY 를 명시해 잡아낸 문제가 Finnhub 에서는 조용히 지나간다.
4. **추정 시각.** `asOf` 가 없어 point-in-time 무결성을 기록할 수 없다.

`../f6-implement-06/` 에서 구현한 4 분기 관문 중 **공급사 단일·회계기준 확정·ADR/ADS 검산** 세 가지가 그대로 이 문제를 막는다. 즉 **현행 코드는 이 상태의 Finnhub 자료를 자동으로 거부한다.** 정책이 의도대로 작동한다.

## 6. 권고

1. **점수·정책을 바꾸지 않는다.** 이번 조사는 커버리지 확인이며 채점 자료를 만들지 않았다.
2. **F6-H 를 채택한다면 Finnhub 단일 공급원, SPCX `pending_data`(가-1)로 간다.**
3. **채택 전 5.3 의 네 가지를 해소한다.** 특히 1·2 는 Finnhub 에 직접 문의해야 확인된다.
4. **Yahoo 는 커버리지·기준 항목 모두 Finnhub 보다 낫지만 등재 전에는 쓰지 않는다.** 약관 검토가 선행 조건이다. 검토 결과에 따라 후보가 바뀔 수 있다.
5. **SEC 는 교차검증 원천으로 유지한다.** 채점 입력은 못 되지만 회계기준·통화·제출일을 명시하는 유일한 원천이다.
6. **FMP 무료는 후보에서 제외한다.** 유료 등급 비교는 별도 과제다.

## 7. 미확인 사항

1. **Finnhub 의 회계기준.** 응답에 없다. 문의 필요.
2. **`stock/earnings` 와 `calendar/earnings` 의 기준 일치 여부.** 확인하지 못했다.
3. **Finnhub 의 통화·주식 기준.** 필드가 없다. TSM·BABA 는 이전 조사에서 각각 TWD 보통주·CNY ADS 로 역산 판정했으나(`../nasdaq-eps-expansion-04/` 7 절) 공급원이 명시한 것은 아니다.
4. **Yahoo 약관.** 미검토.
5. **FMP 유료 등급의 커버리지.** 결제 없이 확인 불가.
6. **SPCX 의 두 번째 확정 분기 시점.** 2026Q3 발표 후에도 2A 는 2 개가 되지만 그 시점의 전망 확보 여부는 그때 다시 봐야 한다.
7. **전망 3 개 중 어느 2 개를 쓸 것인가.** Finnhub 은 3 개를 주는데 F6-H 는 2 개만 쓴다. 가장 가까운 2 개를 쓰는 것이 자연스러우나 규칙으로 고정하지 않았다.

## 8. 재현 방법

```bash
cd worker/validation/f6h-source-batch-10

export FINNHUB_KEY=...
export FMP_API_KEY=...
export SEC_UA="your-app research contact:you@example.com"

python collect.py     # _raw/<provider>/<TICKER>.json + _raw/meta.json (조회 시점 기록)
```

| 파일 | 내용 |
|---|---|
| `collect.py` | 공급원별 배치 수집. 동일 시점·동일 필드 |
| `compare.py` | 원자료에서 2A/2E 충족과 기준 항목 판정 |
| `analysis-output.txt` | 이 보고서에 인용한 실행 결과 |
| `_raw/` | 공급원 원자료와 조회 시점 메타 |
