# QWEN-BASELINE-01 재검토 판정

검토일은 2026-09-08이며 설계진행 Codex가 수행했다. 대상은 Qwen의 `scarpper/validation/qwen-baseline-01/REPORT.md`, 원본 MD·HTML, worker의 현재 기준선·계산기·검증기·렌더러다. worker 구현과 기준선은 수정하지 않았다.

**Qwen 지적 10종 중 6종을 범위를 조정해 채택하고, 4종의 결함 판정은 기각한다.** 별도로 결측 상태 의미 혼합 1종을 발견했다. 14개사의 점수·합계·순위 182개 값은 독립 MD 대조에서도 불일치가 없었다. 따라서 과거 점수 자체를 정정할 근거는 없다.

## 추가 발견 Q-R01. 결측 상태의 의미 혼합

Qwen 보고서는 `not_disclosed` 24건 전체를 올바른 처리라고 판정했지만, 원문 상태 의미를 보존하지 못한 사례가 있다.

- `apple.runway_years.v15` 등 8건의 원문 `∞`는 양의 FCF로 런웨이 계산이 적용되지 않는 경우인데 `not_disclosed`로 저장됐다. null 저장은 적절하지만 실제 미공시 상태는 부적절하다.
- `spacex-xai.ttm_per.v15`와 `nonop_share`의 원문 `적자`도 실제 미공시와 다른 계산 불가 사유다.
- Alibaba·SpaceX의 B종 약정 `미확인`은 확인된 미공시가 아니다.
- `판정 불가`, `—`, `없음`도 일괄 미공시로 번역하지 말고 지표별로 의미를 확인해야 한다. 특히 `없음`을 검토 없이 0으로 일괄 변경하는 것도 금지한다.

현재 24건 중 원문이 명시적으로 `미공시`인 것은 4건이다. 나머지 20건 전부가 확정 오류라는 뜻은 아니며 의미 재분류 대상이라는 뜻이다. 확정적인 8개 런웨이 사례부터 적용 제외와 미공시를 구분하고, 불명확한 원문은 미확인으로 남겨야 한다.

근거는 설계 D-04, 7.2의 `unknown`과 `not_applicable` 구분, 6.4의 수집 실패와 기업 미공시 구분이다. 이 문제가 현재 점수를 실제로 변경했다는 것은 이번 검증에서 입증하지 않았다. 계산기가 FCF로 런웨이를 재산출하는 경로와 데이터의 상태 분류를 구분한다.

## Qwen 검증 방법의 정정

Qwen의 트리거 스크립트는 재실행 시 JSON 대 HTML 차이 3건을 출력한다. 실제 내용은 JS 문자열의 `\'` 해제 2건과 HTML `&gt;` 해제 1건이다. 이는 정상 디코딩이며 이관 내용 손실이 아니다. worker의 원본 리터럴 파서와 텍스트 정규화로 비교하면 39개 트리거가 전부 원본과 일치한다.

Qwen의 `HTML≠MD 21건`은 21개 트리거가 아니라 why/impact 등 필드 차이 건수이며 디코딩·문구 차이도 포함한다. 숫자를 의미 충돌 건수로 쓰지 않는다. Meta FCF와 Menlo 누락은 원문에서 별도로 확인했다.

약 1,094개라는 검사 수는 중복 대조와 의미 판단을 포함한 Qwen의 집계다. 이를 독립 테스트 1,094개 통과나 전체 프레임워크 승인으로 표현하지 않는다. 원본 숫자의 최신 시장 사실 여부도 검증하지 않았다.

## 구현 담당자에게 전달할 범위

1. 이관 보고서에 원본 차이·누락·선택 근거·상태 분포를 기록한다. 기준선 점수와 원문을 소급 수정하지 않는다.
2. 미공시·적용 제외·미확인·파싱 실패의 상태 의미를 분리하고 확인된 미공시만 해당 정책 입력으로 사용한다.
3. 신규 verified 재무 입력의 기간·범위·시점 검증을 추가한다. 기준선에 없는 과거 시점을 만들어 넣지 않는다.
4. 활성 트리거와 신규 F2 판정에 필요한 구조화 정보를 정의하고, 관측·출처 위치 추적을 보완한다.

P4·P5·P9는 수정하지 않아도 된다. P10은 구조 문서의 설명 보완 범위다. Claude 작업 재개를 지시하지 않았으며 이 문서는 재검토 결과이지 구현 완료 보고가 아니다.
