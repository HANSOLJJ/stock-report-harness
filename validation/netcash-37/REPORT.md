# NETCASH-37 — `net_cash` 정의 명문화 · 적용 범위 구분 · 차입금 실측 등록

**과제 셋을 다 했습니다.** 규칙에 작업 정의를 박았고, 설계 지침 6.4 를 P2 로 옮기지 말라는 것을 두 자리에 적었으며, **9개사를 실측 등록**했습니다. 등록하지 못한 3개사는 왜 못 하는지를 남겼습니다.

## 결론

| 항목 | 결과 |
|---|---|
| 정의 명문화 | `policies.f6.net_cash` — 역산 출처·근거·모르는 것·대체 조건을 전부 적음 |
| 적용 범위 구분 | `policies.f6.net_cash.scope_separation` + `policies.f9.g3_cash_scope` 상호 참조 |
| 실측 등록 | **9개사** (microsoft·amazon·nvidia·spacex-xai·tesla·meta·oracle·alphabet·**tsmc**) |

## 1. MCAP-36 재검증 — 셋을 고쳤습니다

먼저 고정 태그 목록으로 돌렸더니 12개사 중 4개사가 갈렸습니다. **원인은 전부 제 목록이었습니다** — microsoft 의 금융리스는 `FinanceLeaseLiability` 한 줄이고 spacex 의 차입은 `LongTermDebtAndCapitalLeaseObligationsIncludingCurrentMaturities` 입니다. 각 사가 실제로 쓴 개념으로 다시 돌리자 MCAP-36 수치가 전부 재현됐습니다. 그 다음에 **개념을 전수 훑어 빠진 것을 찾았습니다.**

### 1.1 amazon — `ShortTermBorrowings` 325M 누락

MCAP-36 의 단기차입 후보군이 **우선순위 fallback** 입니다. `LongTermDebtCurrent` 가 먼저 걸리면 그 뒤를 보지 않습니다. 같은 10-Q(2026-07-31 제출)에 별도로 태깅된 항목이라 합산 대상입니다.

```
LongTermDebtNoncurrent 128,894 + LongTermDebtCurrent 3,330 + ShortTermBorrowings 325 = 132,549
MCAP-36: 132,224 → 정정 132,549 (백만 USD)
```

### 1.2 spacex-xai — 금융리스 1,079M **이중계상**

`LongTermDebtAndCapitalLeaseObligationsIncludingCurrentMaturities` 는 이름 그대로 **자본리스를 이미 포함**합니다. 검산이 정확히 맞습니다.

```
39,364 (총액 태그) − 38,285 (LongTermDebt) = 1,079 = FinanceLeaseLiability
MCAP-36 debt_incl_lease 40,787 → 정정 39,708 (백만 USD)
```

net_cash 가 53,565 → **54,644** 로 1,079 올라갑니다.

### 1.3 alibaba — 차입금 103,311 → **259,996** RMB 백만

MCAP-36 은 `ConvertibleDebtNoncurrent` 와 `LongTermLoansFromBank` 둘만 잡았습니다. 보존 20-F 대차대조표에는 셋이 더 있습니다.

## 2. '결측' 과 '0' 을 갈랐습니다 — palantir

MCAP-36 은 palantir 를 `debt_missing: true` 로 뒀습니다. **차입금이 없는 것이지 못 찾은 것이 아닙니다.**

- 2026-06-30 시점 사실 44건 전수에 차입 부채가 **한 건도 없습니다** (8종 태그 전부 결측)
- 비유동부채 258,098천이 리스 211,400 + 이연수익 33,722 + 기타 12,439 = 257,561 로 **전액 설명됩니다**

차입금을 0 으로 두면 `9,409,099 − 0 − 211,400 = 9,197,699` 이고 legacy `9,200,000` 과 맞습니다. **정의 D 의 여섯 번째 일치입니다.**

**다만 등록하지는 않았습니다.** 유동 리스부채가 미태깅(`OperatingLeaseLiabilityCurrent` 없음)이라 리스 총액이 불완전합니다. apple 과 **같은 결함**이므로 같게 다룹니다 — 한쪽만 등록하면 기준이 둘이 됩니다.

## 3. 작업 정의를 규칙에 박았습니다

`policies.f6.net_cash`.

```
현금및현금성자산 + 유가증권 전체(단기·비유동) − 총차입금 − 리스부채(유동+비유동)
```

### 3.1 출처를 legacy 역산으로 적었습니다

```json
"provenance": {
  "kind": "legacy_reverse_engineered",
  "warning": "**원본 사양이 아니다.** 규칙에도 설계 지침에도 net_cash 정의가 없었고 P2 산식이 이름만 참조했다..."
```

### 3.3 "나머지가 왜 안 맞는지 모른다" 를 더 좁혔습니다

"일곱이 왜 안 맞는지 모른다" 가 아니라 **네 갈래로 갈립니다.**

1. **정의 D 로 계산되는데 값이 다른 넷** — amazon·nvidia·spacex-xai·tsmc. **왜 다른지 모릅니다.** legacy 가 다른 기준일을 썼는지, 다른 정의를 썼는지, 그냥 틀렸는지 가릴 자료가 없습니다.
2. **apple** — 리스를 빼면 `146,517 − 84,344 = 62,173` 이 legacy `62,200` 과 맞습니다. **정의가 달라서가 아니라 legacy 도 같은 리스 공백을 겪었다는 정황입니다.**
3. **palantir** — 실은 맞습니다(위 3.2).
4. **alibaba** — 현금 쪽 정의가 안 정해져 판정 자체가 불가합니다.

### 3.4 확정 정의가 나오면 대체한다고 적었습니다

`supersede` 에 명시했고, **스키마가 이를 강제합니다** — `provenance.kind` 가 `legacy_reverse_engineered` 이면 `warning` 과 `supersede` 가 비어 있으면 로드가 거부됩니다. `evidence.matched.count` 가 실제 목록 길이와 다르면 역시 거부됩니다(개수만 고치고 목록을 안 고치는 실수 차단).

## 4. 6.4 를 P2 로 옮기면 안 된다는 것을 **두 자리**에 적었습니다

`policies.f6.net_cash.scope_separation` 과 `policies.f9.g3_cash_scope`.

| | 설계 지침 6.4 → F9 G3 | F6 P2 → EV 조정 |
|---|---|---|
| 지표 | `cash` | `net_cash` |
| 묻는 것 | **얼마나 버티나** | **기업가치에서 뺄 순현금이 얼마인가** |
| 세는 것 | 즉시 쓸 수 있는 현금 + 확정 미인출 여신만. 제한현금·예상조달·등급추정 제외. 단기투자는 환금성 기준을 정한 뒤에만 | 재무적 자산 전체(현금 + 유가증권 단기·장기) − 총차입금 − 리스부채 |
| 이유 | 소진 속도로 나눌 분자라 실제로 꺼내 쓸 수 있어야 한다 | EV 는 자본구조를 걷어낸 사업 가치다. **환금성은 여기서 묻는 질문이 아니다** |

### 4.1 alphabet 으로 재현했습니다

```
순수 현금      55,911   ← 6.4 가 세는 것
전체 증권     242,474   ← P2 가 세는 것
간격          186,563 (백만 USD)

P2 net_cash    121,683  →  6.4 를 옮기면  −64,880     부호가 뒤집힙니다
EV/Sales         8.968  →                  9.386      밴드는 둘 다 −1
```

**밴드가 안 갈린다고 안전한 것이 아닙니다.** alphabet 의 EV/Sales 는 8·20 선에서 멀 뿐이고, 경계 근처 회사에서는 갈립니다. 드러나는 것은 **EV 가 1,865.6억 달러 과대 계상된다**는 사실 자체입니다.

### 4.2 왜 두 자리인가

6.4 를 고치러 온 사람이 P2 를 같이 고치는 것과, P2 를 고치러 온 사람이 6.4 를 끌어오는 것 **양쪽**을 막아야 합니다. F9 쪽에 `see: policies.f6.net_cash.scope_separation` 를 뒀습니다. 테스트가 이 상호 참조를 고정합니다.

`docs/scorecard/design-guideline.md` §6.4 자체는 **건드리지 않았습니다** — 설계진행 문서입니다. 그쪽에도 한 줄 교차 참조가 있으면 더 좋겠습니다.

**`market_cap` 은 그대로 11개사입니다.** P2 는 여전히 미검증 시총 위에 섭니다. 테스트가 이 사실이 사라지지 않도록 고정합니다.

### 6.3 새 경고 하나

P2 가 산출될 때마다 이 경고가 붙습니다.

```
net_cash 작업 정의 ⚠️ legacy 역산으로 세운 정의 위에서 P2 를 계산한다 —
확정 정의가 나오면 재계산 대상 (policies.f6.net_cash)
```

**점수는 건드리지 않습니다.** 정의가 미확정인 것은 기업의 성질이 아닙니다. `calc.parameters.P2.net_cash_definition` 에도 정의·상태·출처가 같이 찍힙니다 — **선언만 하고 읽는 코드가 없으면 다음 사람은 값만 봅니다.**
