## 이번 라운드 핵심 — `cash` 가 세 갈래였다

worker 가 legacy 값을 전수 분류했다. **내가 "버퍼였다" 고 한 것보다 정확하다.**

| 갈래 | 기업 | 내용 |
|---|---|---|
| 유동성 버퍼와 일치 | 7개사 | MSFT·AMZN·TSLA·PLTR·META·ORCL·GOOGL |
| **비유동 증권까지 포함한 총계** | apple·tsmc·alibaba | apple 은 버퍼의 **2.3배** |
| **어느 쪽도 아님** | nvidia·spacex-xai | spacex 는 `현금 100B(IPO)` 반올림 서술로 보임 |

**`legacy cash` 가 단일 정의가 아니었다.** 12개사가 세 가지 다른 뜻의 수를 같은 metric 에 넣고 있었다.

**이것이 순수 현금 통일의 근거를 더한다.** 어느 갈래를 고르든 임의적인데, **설계 지침 6.4 가 이미 하나를 지정한다** — 사용 가능한 현금 및 현금성자산. 단기 투자자산은 환금성 기준을 먼저 정해야 하고 그 기준이 없다.

**주의를 `basis` 에 남긴 처리가 옳다.**

> 순수 현금 대신 버퍼를 쓰면 alibaba 는 5.75년이라 step 0 이다. **이 판정이 `cash` 정의에 직접 걸려 있어 환금성 기준이 정해지면 `-4 → -3` 으로 돌아온다.**

**판정이 무엇에 달려 있는지가 자료에 있다.** 다음에 기준을 정할 때 이 한 줄이 어디를 봐야 하는지 알려 준다.

## NTM 이 막은 것 — `6.4` 를 `P2` 로 옮기면 안 된다

**이번 라운드에서 가장 값진 지적이고, 내가 저지를 뻔한 실수다.**

내가 `CASH-FCF-35` 에서 **설계 지침 6.4 를 근거로 `cash` 를 순수 현금으로 확정**했다. 그 논리를 `P2` 의 `net_cash` 에 그대로 옮기면 **alphabet 기준 `186B` 가 틀린다.**

확인했다.

```
alphabet   순수 현금 55.91   유동성 버퍼 242.47   차이 186.56
```

**6.4 는 런웨이 절이다.** 묻는 것이 *"얼마나 버티나"* 라 **즉시 쓸 수 있는 현금**만 센다. `P2` 의 `net_cash` 는 **EV 조정**이고 묻는 것이 *"기업가치에서 뺄 순현금이 얼마인가"* 라 **재무적 자산 전체**가 대상이다. **같은 단어가 두 곳에서 다른 것을 가리킨다.**

**오늘 하루 종일 `not_disclosed` 가 네 뜻이라 고쳤는데, `cash` 도 같은 병이었고 `net_cash` 는 아직 병중이다.**

## `net_cash` 에 정의가 없다

규칙 파일을 뒤졌다. **`net_cash` 는 두 번 나오고 둘 다 정의가 아니다.**

```json
"formula": "(market_cap - net_cash) / revenue_ttm",
"inputs": ["market_cap", "net_cash", "revenue_ttm"]
```

**입력 이름으로만 존재한다.** 무엇을 빼고 무엇을 더하는지가 규칙에도 설계 지침에도 없다.

NTM 이 legacy 를 역산해 후보를 찾았다.

```
net_cash = 총현금및전체유가증권 − 총차입금 − 리스부채
           microsoft · tesla · meta · oracle · alphabet  다섯에서 소수점까지 일치
```

**역산 결과이지 원본 사양이 아니다.** 그 사실을 그대로 적은 것이 맞다. **다섯 개사가 맞는다는 것은 강한 신호이나 나머지 일곱이 왜 안 맞는지는 아직 모른다.**

## 차입금 개념을 추측하지 않고 전수 탐색한 것

**후보 목록을 만들어 돌리면 틀린다는 것을 실증했다.** 확인했다.

```
                DebtLongtermAndShorttermCombined   LongTermDebtNoncurrent
oracle                        22건                        0건
tsmc · alibaba                 0건                        0건       ← 태그 체계가 다름
나머지                          0건                       다수
```

**`oracle` 은 총액을 한 태그로 직접 태깅하고 나머지는 쪼개 태깅한다.** 고정 목록으로 돌리면 oracle 이 차입금 0 으로 나온다 — **차입금이 없어서가 아니라 목록이 불완전해서다.**

**"0 이 나왔을 때 그것이 부재인지 탐색 실패인지" 를 가른 것**이 오늘 하루 반복한 주제 그대로다.

## 자체 발견한 조용한 오류

> 초판이 **결측을 0 으로 반환**해 Apple 리스가 0 으로 찍혔고 실제로는 10-K 에만 태깅됩니다.

**정확히 "조용히 틀리는" 종류다.** 0 은 유효한 값처럼 보여서 결측이라는 것이 안 드러난다. 스스로 찾아 고치고 보고한 것이 옳다.

## 결정

### 1. `net_cash` 정의를 규칙에 명문화한다

**NTM 의 역산 결과를 작업 정의로 채택하되 역산이라는 것을 명시한다.**

```
net_cash = 총현금및전체유가증권 − 총차입금 − 리스부채
출처: legacy 역산 (microsoft·tesla·meta·oracle·alphabet 5/12 일치)
지위: 원본 사양 없음. 확정 정의가 나오면 대체한다
```

### 2. `6.4` 는 `F9` 전용임을 규칙에 박는다

**`P2` 의 `net_cash` 와 `G3` 의 완충은 다른 것이다.** 지금은 둘 다 "현금" 이라 불려 섞인다. **각 자리에 무엇을 세는지와 왜 다른지를 적는다.**

### 3. `cash` 는 순수 현금 유지

**확정.** 환금성 기준이 정해지면 재판정하고 그 조건이 `basis` 에 있다.
