# F6 재정의 — 배분 잠정 확정과 0단계 가용성 조사

- 결정일. 2026-09-10.
- 결정자. 사용자.
- 상태. **배분은 잠정.** 0단계 가용성 조사 결과에 따라 확정한다.

## 배경

`ZACKS/EE`·`EEH` 가 F6 의 모든 관문을 닫는 것이 확인됐으나 **구독가 $1,200 으로 사용자가 채택을 접었다.** 무료·허용 원천 중 향후 4개 분기 컨센서스를 주는 곳이 없으므로 NTM PER 을 유지할 수 없다.

사용자가 **채점 프레임워크(9-factor 구조·NTM PER 선택·밴드 구간)가 외부 강의 기준이 아니라 본인 설계**임을 확인해 주었다. 따라서 F6 의 측정 방식을 바꾸는 것은 외부 기준 위반이 아니다.

## 함정 쪽 배점 재배분

실측 근거는 기준선 실행 14개사의 실제 점수 분포다.

| factor | 명목 | 실폭 | 표준편차 | 관측 분포 | 현행 → **개정** |
|---|---|---|---|---|---|
| **F6 가격** | −5 | **5** | **1.86** | 6개 구간 모두 사용 | **−5 → −7** |
| F7 순환금융 | −3 | 3 | 0.99 | **0·−1 에 12/14 집중** | **−3 → −2** |
| F8 비대칭 의존 | −5 | 3 | 1.17 | −1~−4 만 사용, 0·−5 미사용 | **−5 유지** |
| F9 적자 깊이 | −5 | 5 | 1.58 | **0점이 5개** (흑자면 미작동) | **−5 → −4** |

합계 **−18 보존**(`trap_min_active` 불변).

**F6 를 키운 근거.** 유일하게 전 구간을 쓰고 표준편차가 가장 크다. 순위를 실제로 가르는 factor 이고, 내부를 4개 파라미터로 분해하므로 −5 로는 좁다.

**F7 을 줄인 근거.** 12/14 가 0 또는 −1 이라 사실상 2단계만 쓴다.

**F8 을 유지한 근거.** 사용자가 −3 축소를 제안했으나 **반대했다.** F8 은 −1~−4 를 실제로 다 쓰고 있어 줄이면 구분이 사라진다. 오히려 지금 −5 를 안 쓰는 것이 문제다. 판단 근거를 보면 apple(−3, Google 지급금이라는 **수익 항목 하나**)과 anthropic(−3, **컴퓨트 100% 외부·공급자 3사가 전부 경쟁자·약정 $300B**)이 같은 점수인데 성격이 전혀 다르다. anthropic 근거란에는 `-3의 전제가 "3사 분산"이었는데` 라며 **자기 전제가 흔들린다는 서술까지 있는데 점수는 그대로**다. **배점 유지 + anthropic 재판정**이 필요하다. F8 점수는 전부 `reviewer: legacy:v1.5`, `reviewed_at: 2026-09-02` 승계값이다.

## F6 내부 파라미터 (−7)

| 파라미터 | 묻는 것 | 배점 | 산식 |
|---|---|---|---|
| **P1 PER** | 이익 대비 비싼가 | **−2** | `market_cap ÷ net_income_ttm` (**회사 단위**) |
| **P2 EV/Sales** | 매출 대비 비싼가 + 자본구조 | **−2** | `(market_cap − net_cash) ÷ revenue_ttm` |
| **P3 성장률** | 그 값을 정당화할 성장이 있는가 | **−3** | `revenue_ttm ÷ revenue_ttm_prior − 1` |
| **P4 품질** | P1 입력을 믿어도 되는가 | **보정(한 칸 강등)** | `\|nonop_share\| ≥ 0.30` |

바닥 −7, 천장 0.

**P1 과 P3 의 배점을 맞바꾼 이유.** 초안은 PER −3 / 성장 −2 였다. 사용자가 뒤집을 것을 제안했고 데이터가 그쪽을 지지한다. PER 은 이 유니버스에서 **가장 못 믿을 입력**이다 — alphabet `nonop_share` 0.51, amazon 0.46 으로 이익의 절반이 영업외이고, 적자 기업에서는 아예 산출되지 않는다. 품질 보정을 따로 달아야 할 정도의 값에 최대 배점을 주는 것은 앞뒤가 안 맞는다. 반면 매출은 SEC 에서 가장 깨끗하게 나오고 **적자 기업에서도 계산된다.**

부수 효과로 **적자 기업 커버리지가 개선된다.** P1 미산출 시 종전 배분에서는 P2 −2 만 남아 −7 중 −2 밖에 못 썼으나, 바뀐 배분에서는 P2 −2 + P3 −3 = **−5** 까지 쓴다.

**P4 를 배점이 아니라 보정으로 둔 이유.** 품질은 독립된 밸류에이션 축이 아니라 **P1 입력의 신뢰도**다. `nonop_share` 51% 면 PER 16.9 라는 숫자 자체를 못 믿는 것이지 그것이 별개의 비싼 이유는 아니다. F9 의 `g1_direction_relief_step: 1`·`g3` 한 칸 강등과 같은 패턴이다.

**중복 검토 결과.** 다음은 F6 에 넣지 않는다.

| 후보 | 제외 사유 |
|---|---|
| 부채 별도 항목 | **F9 g2·g3 와 중복** (`fcf_ttm`·`runway_years`·`credit_rating`). 단 F9 는 손실 기업에서만 작동하므로 **흑자 기업의 차입은 아무도 안 본다** → P2 분모를 EV 로 두어 흡수 |
| P/FCF | **F9 g2 와 중복** |
| 적자 | **F9 g1 과 중복.** F6 에서 이중 감점하지 않는다 |
| 성장 | **중복 아님.** 9개 factor 전수 확인 결과 매출 성장률을 재는 곳이 없다. F2 는 벤치마크·표준 선점이지 매출이 아니다 |

## 세 트랙

| 트랙 | 대상 | P1 | P2 | P3 | P4 | 상한 |
|---|---|---|---|---|---|---|
| **일반 상장** | 10개사 | `ttm_per` | EV/Sales | 매출 성장률 | `nonop_share` | −7 |
| **ADR** | tsmc·alibaba | 회사 단위 | **USD 통일** | 매출 성장률 | `nonop_share` | −7 |
| **비상장** | anthropic·openai | **미산출** | `post_money ÷ ARR` | **ARR 성장률** | **`ARR ÷ 누적조달`** | **−5** |

**ADR 배수는 회사 단위로 계산하면 약분된다.** `5:1`·`8:1` 이 걸리는 것은 주당 지표뿐이고 `시총 ÷ 순이익`·`EV ÷ 매출` 은 둘 다 회사 전체 값이라 영향이 없다. **남는 것은 통화 하나뿐이다.**

통화는 **USD 로 통일한다.** 시총이 애초에 USD 표시라 환율을 피할 수 없고, USD 로 맞추면 변환이 한 번이다. 20-F 에 **USD convenience translation** 이 있으면 회사가 감사받은 환산치를 쓰고, 없으면 환율 출처와 기준일을 명시한다.

**비상장은 P1 이 빠져 상한이 −5 다.** 상장사 −7 대비 2점 유리하므로 순위 표시에 단서가 필요하다. C-12 가 "상장사 PER 구간 재사용 금지" 를 이미 명시했으므로 밴드도 따로 간다. P4 도 의미가 달라 이름을 **`자본효율 보정`** 으로 분리한다 — 상장사는 이익 품질, 비상장은 조달 대비 매출 창출이다.

## 밴드

**나중에 논의한다.** 사용자가 유보했다. 다만 정할 때 결정할 것이 하나 있다 — **분포를 보고 정할지, 보기 전에 정할지**다. 보고 정하면 순위가 원하는 대로 나오게 맞출 수 있다.

## 0단계 — 가용성 조사 (배분 확정 전 선행)

저장 자료로 확인한 결과 **필요 입력의 상당수가 아예 없다.**

| 파라미터 | 필요 입력 | 보유 | 비고 |
|---|---|---|---|
| P1 | `market_cap` | 12/12 | O |
| P1 | **`net_income_ttm`** | **0/14** | **스키마에 필드 자체가 없다** |
| P2 | `market_cap`·`net_cash` | 12/12 | O |
| P2 | **`revenue_ttm`** | **0/14** | |
| P3 | **`revenue_ttm_prior`** | **0/14** | **스키마에 없다** |
| P4 | **비영업손익 원자료** | **0/14** | **스키마에 없다** |
| 비상장 | `post_money`·`arr`·`cumulative_raised` | 2/2 | O |
| 비상장 | **`arr_prior`** | **0/2** | **스키마에 없다** |
| ADR | 환율 또는 convenience translation | **0/2** | |

**파생값 3종이 원자료 없이 완제품으로만 들어와 있다.** `ttm_per`·`ps_ratio`·`nonop_share` 는 분모가 저장돼 있지 않아 **재계산도 검증도 불가**하고, 회사 단위인지 주당 기준인지도 확인되지 않는다. ADR 약분을 쓰려면 순이익 원자료가 필요한데 지금은 없다.

**저장된 SEC 원자료로는 답이 나오지 않는다.** 10개 파일 전부 `taxonomy=us-gaap`, `tag=EarningsPerShareDiluted`, `units=[USD/shares]` 인 단일 태그 `companyconcept` 다. 매출도 순이익도 들어 있지 않고 **TSM·BABA 는 파일 자체가 없다.**

### 확인 항목

1. **매출** 태그 존재와 회사별 실제 사용 개념 (`Revenues` / `RevenueFromContractWithCustomerExcludingAssessedTax` / `SalesRevenueNet` 중 무엇인가)
2. **순이익** `NetIncomeLoss` 존재
3. **영업이익** `OperatingIncomeLoss` 존재 — `nonop_share` 재계산용
4. **전년 동기**를 같은 개념으로 뽑을 수 있는가
5. **TSM·BABA** 가 `ifrs-full` 로 조회되는가, USD convenience translation 유무
6. 비상장 2사 **전년 ARR** 출처 존재 여부 (공시 의무가 없어 부재 가능성이 크다)

**이번 단계는 값을 뽑는 것이 아니라 "있는지"만 본다.** 스펙 작성 전 사이즈 측정이다.

### 배정

| 워크트리 | 범위 |
|---|---|
| **worker** | 1~4 · 12개 상장사 `companyfacts` 태그 인벤토리 + 6 |
| **C-13** | 1~4 **독립 재확인** — worker 코드를 쓰지 않고 SEC 원자료에서 직접 |
| **NTM** | 5 · TSM·BABA IFRS 경로와 convenience translation |

**종목으로 나누지 않는다.** 두 가지가 깨지기 때문이다. 첫째 **기준 통일** — XBRL 매출 태그가 회사마다 달라 각자 고르면 종목 간 비교가 깨진다(정책의 "종목별 공급원 혼합 금지"). 둘째 **교차 검증** — 종목을 나누면 한쪽 오류를 다른 쪽이 못 잡는다. 이번 세션에서 병렬 독립이 실제로 잡아낸 오류가 여럿이다.

분담 축은 **종목이 아니라 단계와 축**이다. worker 가 스펙을 쥐는 것은 `scripts/scorecard/schema.py`·`calc_f6.py` 를 소유하고 있고 신규 필드 4종이 스키마 변경이기 때문이다. NTM 의 통화 축은 매출 수집과 겹치지 않는다.

## 배분이 흔들릴 수 있는 지점

**−7 배분은 데이터가 다 있다는 전제다.** 0단계 결과에 따라 다음이 바뀐다.

- 순이익이 안 나오면 **P1(−2) 자체가 불가**
- 매출 전년치가 안 나오면 **P3(−3) 불가** — 가장 큰 배점
- 영업이익이 안 나오면 **P4 품질 보정 불가**

따라서 **배분은 잠정이며 0단계 후 확정한다.**
