# ① 풀 먼저 — 14개사 비교 r1 (변형 S·B)

기준일 2026-10-12. 입력은 승인된 실행 `output/ai-scorecard-2026-10-v21/`(judgments·results·evidence·observations)이고, 그 실행은 고치지 않았다. 다음 규칙 버전(v2.2) 후보를 고르기 위한 탐색 계산이다.

## 0. 계산 관례

- **기간**: 회사마다 가장 최근 공시 분기(3개월)의 매출 줄을 쓴다. Microsoft 만 제품별 매출 표가 10-K 연간에만 있어 FY2026(2026-06-30 까지 12개월)을 쓴다. 공시 원문은 저장소의 SEC 캐시(`data/_sec/docs/`, 이전 실행이 `sec-get` 으로 받은 것)에서 읽었고 새 SEC 요청은 하지 않았다.
- **단위 고르기**: 회사 총매출의 15% 이상인 단위만 넣고(최대 셋), 넣은 단위끼리 몫을 합 1 로 다시 맞춘다. 변형 S 는 공시의 가장 잘게 나눈 매출 줄(제품·서비스·플랫폼별 표)대로, 변형 B 는 같은 고객이 묶음으로 쓰는 줄을 합친 뒤 15% 를 건다.
- **풀 추세**: 소비자 단위는 사용자 수, 업무 단위는 매출의 전년 대비(고정환율 값이 있으면 함께 적음)로 본다. +5% 초과 커짐(상한 없음), −5%~+5% 고임(상한 3), −5% 미만 줄어듦(상한 2)이다. 가격을 올린 기간의 정체는 줄어듦으로 읽는다. 자료가 없으면 미확인이고 고임으로 다룬다.
- **거래 단위의 양면 풀**: 두 변(돈을 내는 쪽·쓰는 쪽) 가운데 약한 쪽으로 판정하고, 미확인인 변은 고임으로 센다. 다른 방식의 결과는 3.4 에 적는다.
- **회수 루프의 귀속**: 양면 플랫폼의 루프는 그 플랫폼의 각 변을 이루는 단위에 함께 센다(예: App Store 루프는 iPhone 단위와 서비스 단위에 모두 닿는다). 이 관례를 바꾸면 결과가 크게 바뀌는 회사를 3.2 에 적는다.
- **단위 판정**: 지금 F1 판단이 다룬 채널의 단위는 그 판정 재료를 그대로 쓴다. 다른 단위는 확정 근거로 판정하고, 확정 근거가 없으면 "어림"을 붙인다. 숫자는 근거·공시에서만 가져왔다.
- **사다리**: 회수 루프·전환비용 중 높은 쪽(통과 4·부분 3·실패 1), 가격 실측 통과 +1·실패 −1, 대체 공급 실패 −1, 지속성 할인 −1, 0~5 로 자름. AI 수익화 상한은 회사 판단 값을 그대로 쓴다(Apple 아니오, Alibaba 미확인, 나머지 부분 — 모든 단위가 상한 4). 그다음 풀 상한을 건다. 회수 루프와 전환비용이 둘 다 미확인인 단위는 없었다.
- **회사 ①**: 단위 점수(풀 상한 뒤) × 몫의 합을 0.5 단위로 반올림한다(0.25 는 올림). 표의 괄호 값은 반올림 전 가중합이다.
- **총점·순위**: `results.json` 의 `total` 에서 지금 ① 을 빼고 새 ① 을 더한다. 동점은 같은 순위다.

## 3. 발견

### 3.1 점수가 움직인 회사와 이유

- **Alphabet·Amazon·Meta 4 → 3(S·B 모두).** 소비자 단위가 풀 상한 3 에 걸렸다. Meta 는 하루 활성 사용자 +3% [EV-meta-011] 로 고임이다. Alphabet(검색 사용자 수 시계열 없음)과 Amazon(Prime 회원·활성 고객 수가 2020년 뒤 미공시 [EV-amazon-028])은 미확인이라 고임으로 다뤘다. 클라우드 단위는 3 이라 평균도 3 이다. 풀 상한을 빼고 계산하면 Alphabet S 3.5·B 4.0, Amazon S 3.5·B 4.0, Meta 4.0 이어서, 하락의 대부분이 풀 상한에서 나온다.
- **Oracle 4 → 2.5(S·B 모두).** 소프트웨어 지원 단위가 줄어듦(지원료 인상 기간의 −1% 정체 [EV-oracle-041, EV-oracle-038])으로 2, OCI 3, 클라우드 응용 3(어림)이다. 풀 상한을 빼면 3.5 라, 평균화로 0.5, 풀 상한으로 1 이 빠진다. 계기였던 "다른 사업의 성장을 빌려 온 잠긴 풀"이 이 설계에서는 풀리는 것을 확인했다.
- **Microsoft 4 → 3.5(S·B 모두).** 풀 상한은 걸리지 않는다. Azure 단위(서버 제품·클라우드, 몫 0.559)가 계약 수준 전환비용(상업 RPO [EV-microsoft-047])과 가격 근거 없음으로 3 이고, M365 상업 단위가 4 라 평균이 3.44 다.
- **OpenAI 0 → 0.5.** 지금 ① 은 가장 강한 채널(소비자, 0점)만 봤다. 가중 평균에서는 기업 단위(1점: 회수 루프 실패, 전환비용 부분, 대체 공급 실패, 가격 실측 실패 — Anthropic 사업 고객 단위와 같은 판정)가 몫 약 0.5 로 들어온다.
- **움직이지 않은 회사**: Apple 4, NVIDIA 4, TSMC 3, Alibaba 3, Palantir 3, Tesla 2, SpaceX 2, Anthropic 1. Apple·NVIDIA·TSMC·Palantir 는 모든 단위의 풀이 커지고 판정이 같다. Tesla(1.814)·SpaceX(1.850)는 반올림으로 2 에 남았다. SpaceX 는 Starlink 소비자 단위가 0 점(회수 루프 실패, ARPU 하락으로 가격 실측 실패)이지만 기업·정부와 AI 솔루션 단위(둘 다 어림 3)가 받친다.
- **순위**: 1위 셋(12점)은 그대로다. Apple 5위 → Microsoft 와 공동 4위, Palantir 9위 → 8위, Oracle 8위 → 9위(Alibaba 와 공동), Anthropic 13위 공동 → 14위(OpenAI 2.0 이 1.5 를 앞선다).

### 3.2 두 변형이 갈린 회사와 이유

- **반올림 뒤 점수가 갈린 회사는 없다.** 가중합만 조금 다르다(Microsoft 3.441·3.462, Oracle 2.703·2.677, Tesla 1.814·2.000).
- 갈리지 않은 이유는 셋이다. (1) 풀 상한 3 이 소비자 단위를 눌러 묶음 판정의 차이를 지운다. 상한을 빼면 Alphabet·Amazon 은 S 3.5, B 4.0 으로 갈린다. (2) AI 수익화 상한 4 가 묶음의 5점을 4 로 자른다. (3) 회수 루프를 양면 플랫폼의 각 변 단위에 함께 센다는 관례(0절)로 S 에서도 루프가 남았다.
- **관례 (3)을 바꾸면 크게 갈린다.** App Store 루프를 iPhone 단위에 넣지 않으면 iPhone 은 루프 실패·전환비용 미확인으로 1점이 되고 Apple 은 S 2.0, B 4.0 이다(총점 8 대 10). 장터 루프를 Amazon 1P 스토어 단위에 넣지 않으면 Amazon 은 S 2.0, B 3.0 이다. 사용자가 걱정한 "나누면 묶음의 락인이 사라진다"는 S 에서 루프·전환비용 근거를 어느 줄에 귀속하느냐로 바로 나타나고, 그 귀속 규칙이 S 의 핵심 미결이다.
- **가장 강한 근거가 작은 공시 줄에 있으면 S 가 버린다.** Amazon 의 가격 실측 통과(Prime 회비 인상 뒤 10분기, [EV-amazon-053, EV-amazon-052])와 전환비용 통과(FTC 합의 뒤 유지, [EV-amazon-055])는 구독 줄(회사 매출 6.8%)의 사실이라 S 의 15% 문턱에서 빠지고, 남은 1P·3P 단위는 전환비용·가격 실측이 미확인이 된다. B 는 이 근거를 리테일 묶음 판정에 쓴다.

### 3.3 묶음 판정이 애매했던 자리

- **Microsoft**: 사용자 예시인 기업 일괄 계약(EA)으로 Azure 와 M365 를 함께 산다는 것은 확정 근거에 없고, 상업 RPO 의 45% 가 OpenAI [EV-microsoft-046] 라 Azure 고객군이 M365 와 다르다. 그래서 B 에서 Azure 를 나눴다. 합치면(서버·클라우드 + M365 상업 + Dynamics + 기업 서비스, 회사 매출 74.9%, +23.2%) 묶음 판정은 M365 근거로 전환비용·가격 실측 통과, 단위 4, 회사 ① 4(총점 10.5)다.
- **Oracle — 같은 잣대를 대면 계기 문제가 되살아난다.** Microsoft 를 합치는 근거(기업 일괄 계약)를 Oracle 에도 대면 OCI·클라우드 응용·소프트웨어가 한 업무 묶음(회사 매출 88.7%)이 된다. 묶음 매출은 $12,907M → $17,157M, +32.9% 로 커짐이고 묶음 락인은 지원 갱신 [EV-oracle-026] 으로 전환비용 통과라 단위 4, 회사 ① 4 다. 지원(잠긴 풀)과 OCI(성장)를 다시 한 단위로 섞어 지금 규칙과 같은 결과가 된다. B 의 "같은 고객" 판정은 회사 전체 고객군이 아니라 **성장 매출을 내는 고객**으로 봐야 이 문제가 막힌다. OCI 성장은 AI 연산 계약에서 나온다 [EV-oracle-060, EV-oracle-005, EV-oracle-031].
- **공유 계정 묶음의 근거**: Alphabet(Google 계정), Meta(앱 간 계정), Apple(Apple 계정), Tesla(차량·FSD·충전)를 합친 이유는 일반적 사실이지만 확정 근거로 확인한 것이 아니라 어림이다. 이번에는 Alphabet·Amazon 은 풀 상한 때문에, Apple 은 루프 귀속 관례 때문에 점수에 닿지 않았다.
- **Alibaba**: 묶음 단위의 소비자 수가 회사 1차(Taobao 월간 활성 소비자 두 자릿수 증가, 12월 분기 [EV-alibaba-064])와 QuestMobile(+0.6%, 2026-03 [EV-alibaba-059])로 갈린다. 매출로 재면 +4.2% 로 고임이다. 묶음 단위가 3 이라 어느 쪽이든 점수는 같다.
- **SpaceX**: X·Grok 소비자 묶음은 구독 매출이 AI 솔루션·인프라 줄 안에 섞여 몫을 잴 수 없어 B 를 S 와 같게 뒀다.
- **NVIDIA·TSMC**: 공시 줄이 고객 분류(Hyperscale·AI 클라우드)·칩 용도(HPC·스마트폰)라 같은 제품·같은 고객의 줄을 B 가 하나로 합친다. S 의 분할은 판정 차이를 만들지 않았다.

### 3.4 설계상 문제

1. **광고로 버는 소비자 플랫폼의 풀을 무엇으로 재나.** 사용자 수로 재면 포화한 대형 플랫폼은 고임이다(Meta +3%). 돈을 내는 쪽(광고 노출 +14% [EV-meta-041], 유료 클릭 +13%(10-Q))으로 재면 커짐이다. 내는 쪽으로 재면 Meta 4, Alphabet S 3.5·B 4.0 이 된다. 이 선택 하나가 1위 세 회사를 1점씩 움직인다.
2. **자료가 없으면 고임 = 사실상 1점 감점.** Amazon(회원 수 미공시), Alphabet(사용자 수 시계열 없음), Tesla(운행 대수 미공시), Anthropic 소비자가 여기에 걸렸다. 미확인을 점수가 오르는 쪽으로 풀지 않는 원칙에는 맞지만, 공시 관행이 점수를 정한다. Amazon 은 요금 동결 상태에서 구독 매출이 환율 제외 +12% [EV-amazon-026] 라 회원 증가를 시사하지만, 사용자 수가 아니라 쓰지 않았다.
3. **거래 플랫폼의 양면 풀.** 약한 변·미확인 변 고임으로 세서 Amazon 3P 는 판매자 쪽 +16% 인데도 구매자 쪽 미확인으로 고임이다. 내는 쪽(판매자)으로 세면 Amazon S 3.5 다. Alibaba CMR 은 판매자 쪽이 +1%(같은 기준) [EV-alibaba-065] 라 어느 방식이든 고임이다.
4. **클라우드 단위가 모두 3 에 모인다.** AWS·Azure·Google Cloud·OCI·Alibaba Cloud 가 계약 수준 전환비용(백로그·RPO·과금 방식)과 가격 실측 미확인으로 3 이다. 회수 루프 실패와 대체 공급 부분은 다섯 곳 모두 어림이다. 지금 ① 은 가장 강한 채널만 판정해 클라우드 근거를 거의 모으지 않았다. 단위별 판정을 정식으로 하면 판단·근거 수집이 단위 수만큼 늘어난다(S 기준 31개 단위 가운데 지금 F1 판정 재료를 그대로 쓴 단위 14개, 확정 근거로 새로 판정한 단위 6개, 어림이 섞인 단위 11개).
5. **15% 문턱과 최대 셋이 버리는 매출.** Alphabet S 는 YouTube 광고·구독·Network 등 약 26%, Amazon S 는 광고·구독 포함 20.5%, Microsoft S 는 Xbox·LinkedIn·Windows 등 30.3% 를 버린다. 몫을 남은 단위로 다시 맞추므로 버린 줄의 근거가 판정에서 사라진다(3.2 의 Amazon 구독 줄).
6. **S 는 공시 세분화에 달려 있다.** Microsoft 는 FY2027 부터 두 세그먼트(Agents and Infra, Devices and Consumer)로 바꾼다 [EV-microsoft-004]. S 를 세그먼트로 하면 Azure 와 M365 가 한 단위가 되어 위 합친 B(4점)와 같아진다. 이번 S 는 10-K 제품별 매출 줄로 나눴다.
7. **비상장 두 모델 회사의 몫.** 같은 등급(2차 보도)으로 맞췄다. OpenAI 는 1차(기업 40% 초과 [EV-openai-039])로 보든 2차(기업 과반 [EV-openai-154])로 보든 0.5 다. Anthropic 의 사업 고객 80% [EV-anthropic-012] 는 2025-10 보도라 기준일보다 1년 오래됐고, 소비자 몫이 25% 를 넘으면 가중합이 0.75 미만이 되어 0.5 로 내려간다. 두 회사 모두 업무(좌석)와 거래(API)를 나눠 밝히지 않아 한 단위로 묶었다.
8. **0.5 반올림 경계의 값이 많다.** Oracle S 2.703·B 2.677(2.75 에 가까움), Tesla S 1.814, SpaceX 1.850, Anthropic 0.800 이다. 단위 하나의 어림 판정이 회사 점수를 0.5 움직일 수 있다.
9. **미결 상한 숫자에 대한 관찰.** 이번 결과에서 점수를 움직인 것은 고임 상한 3(Alphabet·Amazon·Meta 의 소비자 단위)과 줄어듦 상한 2(Oracle 지원)뿐이다. 커짐(상한 없음)은 모든 업무 단위에 해당해 영향이 없었다. 고임 상한을 4 로 두면 Meta 는 4, Alphabet·Amazon 은 S 3.5·B 4.0(클라우드 단위 3 이 평균을 끌어내림)이 되고, Oracle 은 2.5(지원 단위 2)로 남는다.
