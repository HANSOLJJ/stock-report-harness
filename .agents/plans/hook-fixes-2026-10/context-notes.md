# 결정 기록

- 2026-10-02 사용자 결정: 저장소 메모리(`memory/`, 주입 훅, 형식 검사 훅, 검증기, 규칙 문서)를 아예 없앤다. 근거 — 쓰는 기준이 "비용이 큰 관측" 으로 모호했고, 일지는 주입되지 않아 아무도 읽지 않았으며, 이 틀은 원작자가 종목 리포트용으로 만든 빈 틀(원본에는 기록 0건)이었다. 교훈은 모든 에이전트가 세션마다 읽는 AGENTS.md 와 스킬에 규칙 한 줄로 적는다.
- 2026-10-02 사용자 결정: 승인된 실행 폴더는 훅으로 막지 않는다. 고치면 지문이 달라져 승인이 무효가 되고 빌드가 멈춘다. 훅은 지문이 못 잡는 것(`.env`, 기준선, 승인 파일·승인 명령, 이력 CSV)만 지킨다. 9월 두 실행과 규칙 v1.5~v1.7 의 기존 보호는 그대로 두고 목록에 더하지 않는다(v1.8 포함).
- 2026-10-02 기능을 통째로 없애는 것(메모리)은 주석으로 남기지 않고 삭제한다. "주석으로 남기기" 관례는 살아 있는 기능의 일부를 끌 때만 쓴다(9월 30일 종목 코드 삭제 때와 같은 기준).
- 2026-10-02 셸 쓰기 우회(`echo > report.html` 등)는 훅으로 막지 않는다. 단계 순서와 산출물 정합은 CLI 와 계약 검증기가 첫 방어선이다. 설명서에 한계로 적는다.
- 2026-10-02 초안의 「인용 근거」 표와 References 목록은 기사 제목을 그대로 싣는다(`render_md.py` 456·467행). 투자 권유 검사에서 이 두 절을 뺀다. 빼지 않으면 "Buy Now" 같은 제목의 기사를 인용하는 순간 초안이 막힌다.
- 2026-10-02 탐침 결과(고치기 전)는 스크래치 `probe_hooks.py` 출력으로 남겼다. 고친 뒤 같은 스크립트로 전후를 비교한다.
- 2026-10-02 체크아웃 목록은 `git worktree list --porcelain` 으로 구한다(설계 검토의 (a)안). 대상 경로의 상위에서 `guard.py` 를 찾는 (b)안은 명령 문자열에서 벗길 접두를 미리 알 수 없고 `rm -rf <다른 체크아웃의 상위>` 를 판정하지 못해 뺐다. 세션 루트 안의 경로는 git 을 부르지 않으므로 평소 지연은 그대로다(약 0.13초).
- 2026-10-02 언급 판정(`_mentions`)은 체크아웃 루트 접두를 문자열에서 벗긴 뒤 기존 판정을 다시 돌린다. 쓰기 대상 단어는 문자열 치환이 아니라 절대 경로로 풀어 소속 체크아웃을 찾는다(`cd output && rm <루트>/…` 가 `output/…` 로 잘못 풀리는 것을 피하려고).
- 2026-10-02 체크아웃 목록을 못 구하면 `protect_sensitive_files` 와 `enforce_plan` 은 함수 안에서 잡아 막는다. `main` 까지 올라가면 fail-open 으로 통과되기 때문이다. git 폴더 표시가 없는 폴더(테스트의 임시 루트)는 체크아웃 하나로 본다.
- 2026-10-02 `uv run <옵션 값> scripts/build_report.py` 는 옵션 값과 명령을 구분할 수 없어, `uv run` 뒤에 빌더 파일이 오면 빌드 호출로 본다. 오탐이 나도 리뷰가 pass 가 아닐 때만 막히므로 수용한다.
- 2026-10-02 위험 명령 차단은 `_shell_segments` 로 나눠 git 하위 명령을 본다. 정규식이면 이 작업의 커밋 메시지(`git reset --hard 를 막는다`)도 막힌다. `bash -c "…"` 같은 중첩 실행은 놓친다(둘째 방어선이라 수용).
- 2026-10-02 잠금은 빌드 성공 때 지운다. 훅에서 "승인이 유효한 실행의 잠금은 무시" 하는 방법은 훅에 해시 계산이 들어가고 CLI 의 `claim_lock` 과 판정이 갈라져 뺐다.
