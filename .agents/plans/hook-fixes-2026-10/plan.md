# 가드레일 훅 개선과 저장소 메모리 폐지 (2026-10-02)

## 왜
훅 7개를 전부 읽고 실제 입력으로 판정을 확인하니 구멍과 낭비가 여럿 나왔다.

| # | 문제 |
|---|---|
| 1 | 워크트리 세션에서 원본 폴더의 보호 파일(`.env`·이력 CSV·규칙·기준선·9월 실행)이 보호되지 않는다. 훅이 세션 루트 기준 상대 경로로만 판정한다 |
| 2 | 빌드 검사가 명령 표기에 의존하고(`./scripts/…`·`-Xutf8`·`npm run build:report` 통과), `--directory <원본>` 은 잘못 막는다 |
| 3 | 투자 권유 표현 훅이 수집 원문 `candidates.json` 의 뉴스 제목 "Buy Now" 에 걸려, 원본 루트에서는 모든 셸 명령 뒤에 block 이 난다 |
| 4 | 금지된 git 명령(`reset --hard`·`clean -fd`·`checkout .`)과 `rm -rf ~` 가 통과한다 |
| 5 | 메모리 훅이 한 세션에 약 12만 자를 주입한다. 토픽 7개 중 6개는 파일이 없다 |
| 6 | 저장소 메모리는 쓰는 기준이 없고 읽히지도 않는다(원작자의 빈 틀을 물려받음) |
| 7 | 승인·빌드가 끝난 실행의 잠금이 남고, 잠금 주인(터미널 번호)이 같은 세션에서도 바뀐다 |
| 8 | 차단 메시지가 매번 보호 목록 전체를 적는다 |

## 무엇을
1. 투자 권유 검사: `output/<run>/` 의 draft·judgments·evidence.json 만, evidence 는 우리가 쓴 칸만, draft 는 「인용 근거」·References 절 제외.
2. 저장소 메모리 폐지: 교훈 3줄을 AGENTS.md·score-review 스킬로 옮기고 `memory/`·주입 훅·형식 검사 훅·검증기·규칙 문서·배선을 지운다. 훅은 5개가 된다.
3. 체크아웃 인식: `checkout_roots`·`locate`·`_mentions`·`_join` 으로 같은 저장소의 다른 체크아웃도 같은 규칙으로 판정. 차단 문구 축약.
4. 빌드 검사: 단어 기반 `_build_targets`, 실행될 스크립트가 속한 체크아웃의 리뷰를 본다.
5. 위험 명령: 작업 트리를 지우는 git 명령과 홈 폴더 삭제 차단.
6. 잠금: 빌드 성공 시 `.lock` 삭제.
7. 문서: 훅 설명서·README·guide·TODO.

## 하지 않는 것
- 승인된 실행 폴더를 훅으로 막기(지문 검증에 맡김), 셸 쓰기를 훅으로 완전히 막기, Muse·Antigravity 배선.
