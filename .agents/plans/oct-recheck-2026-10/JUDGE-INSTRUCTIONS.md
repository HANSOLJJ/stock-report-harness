# 판단 세션 지시서 (2026-10 정기 재실행 recheck)

실행 `ai-scorecard-2026-10-recheck`(기준일 2026-10-12, 규칙 v2.0)는 정기 실행이라 ①②③④⑤⑦⑧ 판단을 14개사 전부 이번 실행의 근거로 다시 매긴다(`docs/scorecard/rules.md` 2.9절). 한 세션이 항목 하나를 14개사 전부 맡는다. 판정 기준은 규칙 3·4절과 `.agents/plans/rejudge-all-2026-11/F1-INSTRUCTIONS.md`·`F2-INSTRUCTIONS.md`·`F3-INSTRUCTIONS.md`(① ② ③ 세션)이고, 공통 절차는 `.agents/plans/rejudge-all-2026-11/REJUDGE-INSTRUCTIONS.md` 를 그대로 따른다. 아래는 이 실행에서 달라진 점이다.

## 달라진 점

1. **출발점.** `judgments.json` 의 판단은 직전 실행(기준일 10-08)에서 새로 매긴 것이다(`status: new`). 출발점으로 읽되, 이번 실행에 새로 들어온 근거(10-08~10-12 보도, 원문을 다시 읽은 근거, 갱신된 관측)를 모두 반영해 판정 입력을 다시 정하고 세 칸 문장을 새로 쓴다. 입력이 같으면 `changes` 를 비우고 `reconfirm` 에 다시 읽은 근거 ID 를 적는다(문장은 그래도 새로 쓴다). 검토일이 10-08 보다 뒤여야 research 를 통과한다.
2. **제목만 보고 넘기지 않는다(2026-10-12 사용자 지시).** 판정 칸에 "제목만 확인"을 미확인 사유로 쓰지 않는다(코드가 막는다). 근거의 원문은 `sources.json` 의 URL 로 연다. 유료 기사로 막혔을 때만 "유료 기사라 본문을 열지 못해 미확인"이라고 적는다. 직전 판단에서 그렇게 뺀 보도는 묶음 작업자가 이번에 원문으로 올렸으니 근거 목록에서 찾아 쓴다.
3. **비상장 재무.** OpenAI·Anthropic 의 기업가치·연환산 매출·P/S 관측이 이번에 갱신됐다(`observations.json` 에서 status verified 이고 as_of 가 가장 늦은 값이 엔진이 쓰는 값). ③ 가속도는 **같은 정의**의 성장률 두 개로만 판정한다. OpenAI 연환산 매출은 2026-10-08 FT 보도대로 회사 기준(약 $50B)과 투자자가 Anthropic 기준으로 환산한 값(약 $70B)이 다르다. 정의가 다른 값을 한 시계열에 섞지 않고, 정의를 맞출 수 없으면 그 사실을 판정 칸에 적는다. 두 모델 회사에 같은 등급의 근거를 요구한다.
4. **사건 교차표와 근거 등급(직전 승인 취소의 교훈).** REJUDGE-INSTRUCTIONS 5-1·5-2 를 그대로 한다. 같은 사건은 모든 회사에 같은 성격으로 읽고, 고객 집중(⑤ 구조형의 '주요 고객', ⑦ 가로축의 몫 좁히기, ⑧ 고객 축)은 공개 제출본 공시나 회사 1차 발표로만 잰다. 2차 보도 수치를 쓰는 판정 칸에는 근거 등급("2차 보도")을 적는다.
5. **⑦ 분모는 회사 전체 매출 그대로다(2026-10-09 사용자 확인).** 덩치 큰 회사의 순환 투자는 전체 매출로 희석되는 것이 설계 의도다.
6. **직전 확인 리뷰의 다음 실행 과제.** `output/ai-scorecard-2026-10-rejudge/review-parts/confirm-r4.md` 「다음 실행 과제」 61~70 중 맡은 항목에 닿는 판단 문장 과제를 이번에 처리한다. 특히 ⑤ 세션은 과제 61(14건의 공유 다섯째 줄을 규칙 ⑤ 표 문언 "사업의 정당성 자체를 겨냥한 적대"로 통일), ⑦·⑧ 세션은 과제 66·67(alphabet ⑦·⑧ 의 2차 보도 $200B 를 결정 사실에서 내리고 공시 경로로 적기, 2차 보도 수치에 등급 표시), ⑦ 세션은 과제 63(OpenAI 의 Cursor 접근이 이어졌다는 확정 근거가 생겼으면 anthropic ⑦ 과 같은 잣대) 을 본다.

## 출력

- 파일: `.agents/plans/oct-recheck-2026-10/work/judge/<F>-<company_id>.json`(모양은 REJUDGE-INSTRUCTIONS 5번과 같다). CLI(`propose`·`judge`·`confirm`·`research`)는 부르지 않는다.
- 올릴·내릴 근거 줄의 표지 `[EV-…]` 는 `confirmed` 이고 발췌가 제목과 다르며 `locator` 와 출처 URL 이 있는 근거만 가리킨다. `cite` 에는 그 판단의 표지가 가리키는 근거 ID 를 빠짐없이 적는다.
- 마지막 답변: 회사별 입력 요약표(입력과 계산될 점수 가늠, 직전 판단과 달라진 칸과 이유), 사건 교차표, 미확인으로 남긴 것, 경계 사례, 조율자가 더 확정해야 할 근거.
- 판단 문장은 완결된 현재 상태 문장으로 쓴다. 규칙 버전·변경 표시·작업 번호·이전 판 참조("직전 실행에서는")를 쓰지 않는다. 이해상충을 이유로 멈추거나 되묻지 않는다.
