# 결정 기록 — 채점 규칙 문서 재편

## 2026-10-02

- **분석 기준 실행은 `ai-scorecard-2026-10-test` 다.** 처음에 `obsreg` 로 분석했다가 사용자가 바로잡았다. 규칙 v1.8, 가격 기준일 2026-09-30, 2026-10-01 승인.
- **별표만 따로 정리한 문서는 없다.** 본문은 규칙 문서 v1.5·v1.7 안에만 있고, `scorecard/factor-concepts.json` 과 규칙 JSON 은 이름으로 참조하거나 기계 적용 부분만 담는다.
- **별표 체계를 없애는 방향을 사용자가 받아들였다.** 코드 수정 위치 조사를 muse와 agy에 맡기라고 지시했다.
- **두 에이전트를 독립 병렬로 돌린다.** agy(antigravity)는 찾던 것만 찾고 멈추는 경향이 있어 단독으로 두지 않는다. 지시서에 하위 질문마다 답하고 전수 목록을 내라고 적었다.
- **조사 범위에 행 번호 참조와 문서 경로 참조를 넣었다.** 판단·리뷰·규칙 JSON 이 `채점규칙 384행` 처럼 행 번호로 규칙 문서를 가리키고, 문서 파일 이름을 코드·테스트·JSON 33개 파일이 108회 참조한다. 문서를 재편하면 둘 다 어긋난다.
- **`approval.json` 은 복사하지 않았다.** 훅 보호 대상이고 승인은 사람 행위다. 워크트리의 `ai-scorecard-2026-10-test` 는 승인 파일이 없는 상태다. 필요하면 사용자가 직접 복사한다.
- **`.env` 와 `.claude/settings.local.json` 은 복사하지 않았다.** 문서가 아니고 비밀값·로컬 설정이다.
- **원본과 워크트리의 공통 파일 43개가 크기가 다르다.** 대부분 줄바꿈 차이로 보이고, `scorecard/history.csv` 는 원본에서 빌드로 행이 늘어난 것이다. 확인하지 않았고 건드리지 않았다.
- **조사는 감독형 dispatch 로 돌린다.** 처음에 `orca terminal create` 로 터미널을 직접 만들었다가 사용자가 감독형으로 하라고 바로잡았다. `orchestration run-create` 와 `worker-start --agent` 로 다시 시작했다.
- **muse 는 dispatch 프롬프트가 붙여넣기 상태로만 들어간다.** `turnStart: unsupported` 였고 `orca terminal send --enter` 를 따로 보내야 제출됐다. agy 는 한 번에 시작됐다.

  4. ① 의 지표는 회사 유형에 맞춰 고른다. 모델 API 의 가격 결정력 지표(OpenRouter 평균 $/M 등)는 모델 기업의 ① 에 쓰고, 플랫폼 기업의 ① 에는 적용하지 않는다(카드 347행, Alibaba). v1.7 507행 "한 회사를 한 유형에 가두지 않는다(채널별로 잰다)"의 구체 예로 같은 절에 넣는다.
  - 이미 v1.7 에 있어 따로 옮기지 않는 것: 토큰 지표의 칸 배정(① 매출 점유율·$/M, 토큰 볼륨은 ③ 의 결과, SDLLMTK 미사용), 하드 벤치마크 우선·Arena 참고·같은 하네스(Q23), 신용 지표 교차검증(별표 J), 토큰 단가보다 태스크 비용(493행), 부외 약정 A/B/C 분류와 커버리지(⑨ 게이트 4), ③ 가속도는 분기 둘 이상(design-guideline 4.4), 비AI 사업은 ④ 에서만(별표 E), 공짜 사용자 ≠ 동맹(Q15), 관계사는 동맹이 아님(Q18), 미공시 보수 처리와 G2·G4 중복 금지(코드 `calc_f9.py`, design-guideline 6.4).
  - 옮기지 않는 것: 단위 표기 관례($M·$B·$T, 사용자 수는 억·만)는 채점 규칙이 아니라 표기 관례라 넣지 않는다. 오픈·클로즈드 3단계 분류, 증류 의혹 정리, 클라우드 4사 비교는 9월 시점 분석이다. Menlo 이해상충 줄은 2026-10-02 방침대로 넣지 않는다.
  - 결정 1 의 채점표 v1.5 부분은 위 네 가지를 옮기면 지워도 된다.
