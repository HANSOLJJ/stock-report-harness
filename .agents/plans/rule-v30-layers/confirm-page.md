# 승인 페이지를 확인 페이지로 (2026-10-20 사용자 지시)

## 왜

- 렌더링만 바꾼 초안 재생성 뒤 승인을 다시 받아야 했고, 그 과정에서 띄운 승인 페이지가 해시가 어긋난 옛 승인 때문에 "승인 취소"만 보여 승인이 취소됐다.
- 사용자 지시: "승인 페이지가 아니라 확인 페이지로 바꾸고 거기서 내가 수정할 수도 있어. 확인 누르면 자동으로 빌드되게." "내용 변경 없으면 그냥 하라."

## 바꾸는 것

| # | 내용 |
|---|---|
| C1 | 승인 대조: 규칙·관측·판단·실행·결과·출처·근거·트리거 해시가 같고 초안 해시만 다르면 유효(초안은 해시가 매겨진 입력의 렌더링). `draft` 단계와 훅은 승인된 실행에서도 초안 재생성을 막지 않는다. 리뷰 파일의 draft_hash 가 달라도 results_hash 가 같으면 경고만 |
| C2 | 확인 페이지: 제목·문구를 "확인"으로. 확인에 6자리 코드를 받지 않는다. 확인을 누르면 기록(approval.json)을 남기고 곧바로 build 한다. 이미 확인된 실행은 "다시 빌드" 버튼. 승인 취소 양식은 페이지에서 뺀다. 판단 수정·근거 확정·제안 결정은 그대로 |
| C3 | CLI `build` 하위 명령(확인 페이지가 부른다). 서버는 확인·빌드가 성공하면 내려간다 |
| C4 | AGENTS.md·guide.md 문구, 테스트(파이썬·Node) |
| C5 | v30full: 승인 때 판 초안으로 되돌린 상태에서 사용자가 확인 페이지에서 확인 → build → 커밋·push·맥미니 |

## 유지하는 것

- 에이전트는 확인 버튼을 누르지 않는다(사람이 확인한다). 코드 대신 이 규칙과 `stages.approve` 의 에이전트 세션 거부가 남는다.
- 확인 기록의 해시 대조, 계산(calculate)이 결과를 바꾸면 옛 확인을 지우는 동작.
