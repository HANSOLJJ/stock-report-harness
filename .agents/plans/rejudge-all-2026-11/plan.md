# 정기 실행 전부 재판단 + ① 구조화 (2026-11 실행 준비)

## 목표

정기 채점 실행에서 사람이 판단하는 일곱 항목(①②③④⑤⑦⑧)을 14개 회사 모두 그달 근거로 다시 매긴다.
"이전 점수를 그대로 가져오는" 승계(`status: carried`)는 기업 추가 실행(`init --from-run … --add-companies`)에서만 쓴다.
다시 봤는데 점수가 같으면 "언제, 어떤 근거를 보고 확인했다"는 기록이 남는다.

계기는 2026-10-08 검토 메모(`docs/scorecard/notes/2026-10-08-investment-lens-review.md`)와 `history.csv` 대조다.
9월 2일 기준선 이후 네 번의 실행에서 정성 판단 98칸 가운데 움직인 칸은 8개이고, ①②③⑧은 14사 모두 한 번도 다시 판단하지 않았다.
10월 실행 126칸 중 87칸의 `reviewed_at` 이 2026-09-02 이고, 10월에 근거 문장을 다시 쓰면서 10월 근거 표지가 9월 점수에 붙었다.
지금 구조는 "다시 봤는데 같다"와 "다시 안 봐서 같다"를 구분하지 못한다.

## 범위

1. **규칙 v2.0.** 정기 실행은 모든 정성 판단을 다시 매긴다는 조항. 리뷰의 "승계 판단 예외"는 기업 추가 실행에만 남긴다.
2. **① 구조화 (이름 "락인과 가격결정력").** `kind: score`(자유 서술 + 숫자)를 판정 입력으로 바꾼다. 채널 목록과 네 질문(회수 루프·전환비용·대체 공급·가격 실측)을 에이전트가 근거로 채우고 점수는 프로그램이 사다리 A 로 낸다 — 락인 강도 pass 4 / partial 3 / fail 1 / 없음 0, 가격 실측 pass(8분기 지속) +1·fail −1, 대체 공급 fail −1, 지속성 할인 −1. 전환비용 pass 는 "대체재가 있는데도 남음"(관계 수준)이고 설계·계약 수준은 partial 이다. 부품 채널 일괄 상한 2는 없애고 지속성 할인(10% 이상 고객 + 그 고객의 자체 대체재 출하 중)으로 바꾼다. `ai_monetized_in_channel`(yes/partial/no/unknown)을 점수 밖 표시 필드로 둔다. 미해결 TEN-RC-02·RC3-03·RC4-02 와 부품 상한 문제를 이 재판단에서 한꺼번에 닫는다. 결정은 2026-10-08, 세부는 checklist 0절.
3. **재확인 기록.** 판단에 `reconfirmed` 기록(날짜·검토자·다시 읽은 근거 ID)을 둔다. 점수가 같아도 `reviewed_at` 이 이번 실행 날짜가 된다.
4. **리포트 첫 화면 요약.** 이번 실행에서 판단한 칸 수와 날짜, 지난 실행 대비 바뀐 칸 수, 미해결 지적 사항 수와 처리 예정 시점을 한 상자로 적는다.
5. **② 경로 입력.** 세 경로(성능 도약·패러다임 적응·표준 선점)의 통과·부분·실패·미확인을 14사 전부 처음으로 채운다(지금은 전부 `inputs: {}`). 5점 자격인 "세대 격차"의 정의를 정한다(초안: 세 축 중 두 축에서 독립 측정 1위이고 2위가 따라오는 데 직전 세대 교체 간격 이상 걸림). 벤더 발표만 있는 성능 주장은 부분 통과다(규칙 132행) — NVIDIA 5점은 MLPerf 결과 전까지 4점이 될 수 있다. 승인 페이지 `judge` 에 F2 입력란을 연다.
6. **③ 가속도의 지표 단계 기록.** 입력에 "지표 단계"를 적는다 — (a) 매출 전부 AI, (b) AI 지배 세그먼트·제품선(비AI 비중 표기), (c) 클라우드 전체 등 대리 지표, (d) 사용량 시계열, (e) 없음 → 미확인 → 점수 없음. 같은 단계끼리만 비교한다. 10월에 TSMC 가 전체 매출로 통과, Meta 가 지표 없이 부분을 받은 것을 막는 장치다.
7. **11월 실행.** 위 입력을 만든 뒤 일곱 항목을 14사 전부 다시 판단한다. ⑦ 매트릭스 2사(basis carried)도 처음 만든다.

## 범위 밖

- ⑥·⑨ 산식 변경. 메모 5·6·7절의 자본 효율 진단(주당 FCF, capex/감가상각, 부문 마진), G4 표기 수정, 약정 열 추가는 별도 과제다.
- 요구 성장률 역산표(메모 8절), 과거 시점 재현(11절), 민감도(14절).
- 10월 승인본 점수 변경. 10월 리포트에 요약 상자를 다시 그릴지는 미결(context-notes).

## 진행 순서

1. 규칙 v2.0 문서 초안 → 사용자 확인 → `scorecard/rules/v2.0.json` + `rules.md`.
2. 스키마·엔진: ① 새 kind 와 사다리, `reconfirmed`, 정기 실행에서 `carried` 거부, 테스트.
3. 렌더러: 첫 화면 요약 상자, 판단일 분포.
4. 11월 실행: `init --from-run ai-scorecard-2026-10-rescore --rule v2.0` → collect → ② 경로·⑦ 매트릭스 신규 입력 → 일곱 항목 14사 재판단 → research → calculate → draft → review → 승인 대기.

## 성공 기준

- 11월 실행 `results.json` 에 `carried_score` 가 0칸이다. 모든 정성 판단의 `reviewed_at` 이 11월 실행 날짜다.
- ① 14사의 판단이 같은 네 질문 입력을 갖고, 점수는 `calc_qual` 이 사다리로 낸다. 손으로 적은 ① 점수가 없다.
- 리뷰 체크리스트에 "승계 판단 예외"로 통과한 fail 이 0건이다. 10월에 남긴 미해결 12건이 모두 닫히거나 점수에 반영된다.
- 리포트 첫 화면에 "이번 실행 판단 N칸, 지난 실행 대비 변경 M칸" 이 보인다.
- 테스트 `uv run --frozen python -X utf8 -m unittest discover -s tests -t .` 와 `npm run test:node` 통과.
